### B-F6 — the spread is DIRECTABLE by the policy — **FAIL / INERT**

```
arm A (+axis0 then back) grew at [[0, 0, 0, 0, 0]]: occupied_count=243
arm B (+axis3 then back) grew at [[0, 0, 0, 0, 0]]: occupied_count=243
both arms actually grew (count > 1)   : True
sets DIFFER (required for B-F6)       : False
symmetric difference size             : 0
```

The probe was deliberately built so **both arms actually grow** — each excursions out along a
different axis, returns, and then grows — so that what is compared is the *direction* of growth
and not merely whether growth occurred. From an identical reset state, two different declared
directional decisions produce **byte-identical occupied sets** (symmetric difference 0).

This is the pre-committed INERT criterion exactly: a growth surface *declares*, *validates*,
*compiles*, and produces an observable effect that is **wholly independent of the agent's chosen
direction**. The agent can choose *whether* to grow; it cannot choose *where*. "Learn to spread
**toward** food" is therefore not expressible.

- **Classification:** **INERT**

## Gaps found (recorded here, NOT filed — per this run's scope limit)

Filing was suppressed for this blind re-run to avoid duplicating existing tickets and polluting
the comparison. Each gap is described precisely enough to be matched later.

**G-1 — No cell of a multi-cell container is addressable, in ANY direction. (root cause of THREE failing facets)**
This one defect produces B-F5 (ABSENT), B-F6 (INERT) and B-F7 (BLOCKED). Four sub-findings, each
with its own failure mode, which is why it presents as three separate symptoms:

- **(a) Cell write — refused at compile.** `modify: vfs.<name>[i][j][k][l][m]` →
  `[UAC-RES-VFS] ... uses unknown VFS variable '<name>[i][j][k][l][m]'` at UAC Stage 3. The
  resolver reads the whole indexed expression as a variable *name*.
- **(b) Whole-variable write — the only accepted form.** `modify: vfs.<name>` replaces the entire
  variable (`effects/context.py:269-279`; `executor.py:170-171` broadcasts a scalar via
  `expand_as`). Growth becomes a flood: 1 → 243 in one tick, adjacency violated at distance 10.
- **(c) Cell read — compiles green, then throws.** `value: "vfs.<name>[2][2][2][2][2] + 1"`
  validates (`Validation succeeded in 131.3 ms`) and raises at runtime:
  `IndexError: index 2 is out of bounds for dimension 0 with size 1` — the evaluator resolves the
  container as an agent-batched tensor and indexes the batch dimension. **Note the asymmetry with
  (a): the write is refused cleanly, the read is not refused at all.**
- **(d) Container as a reward source — compiles green, then throws.**
  `drive.yaml` / `extrinsic.variable_bonuses: [{variable: <tensor var>, weight: w}]` validates and
  raises `ValueError: VTC reward program expected total_rewards shape (1,), got (3, 3, 3, 3, 3)`.
  (`variable_bonuses` on a **scalar** VFS variable works correctly — measured: reward
  `1.527639 → 2.027639` as `organism_size` goes `1.0 → 2.0`.)

Consequence: any mechanic that is *local* in a container — growth, spreading, territory,
diffusion, cellular automata, per-cell claims — and any reward or condition that is a *spatial
predicate over* such a container, is un-authorable. Substrate-independent: reproduced identically
on a 2-D grid (B-D1), because (a) fails in Stage 3 reference resolution before any substrate is
consulted.

**G-2 — The VTC action-write subsystem is unreachable from config. (INERT surface; defect)**
`src/townlet/vfs/vtc.py` implements `CompiledVTCActionWrite` with eleven compositions
(`claim_if_free`, `capacity_claim`, `append_event`, …), phase scheduling, per-affordance indexing
(`write.affordance_index`) and the phase `resolve_affordance_access_and_occupancy` — roughly the
exact machinery G-1 needs. It is fed from `RuntimeAction.writes`, which
`src/townlet/universe/compilers/actions.py:204-205` hardcodes to `()`, and
`actions.yaml`'s `CustomActionConfig` (`extra="forbid"`) has no `writes` key. ~3000 lines of
compiled transition machinery that no config pack can reach. **A.7 INERT/dead-surface count: 1.**

**G-3 — No observation feature publishes affordance positions. (ABSENT; feature)**
The closed vocabulary in `universe/dto/observation_feature.py` has no member for "where the
affordances are". On `Grid2D`/`Grid3D` this is masked because `grid_encoding` happens to be an
occupancy grid; on **`gridnd` (all N), and on `continuous`/`continuousnd`**, `grid_encoding` is the
agent's own coordinate (`gridnd.py:382-384`), so *the agent cannot see where anything is*. The only
authoring answer is to hand-duplicate the coordinate as a constant VFS variable — which nothing
keeps in sync, and which silently becomes wrong under `deployment.type: random`.

**G-4 — `spawn_item` can never resolve a position from any declarable trigger. (INERT surface; defect)**

compiles, and always raises at runtime:
`ValueError: agent_positions and self_index required for position 'self'`. The affordance engine
sets `self_index=None` and no `agent_positions` (`affordance_engine.py:509-519`); `_tick_effect`
omits `agent_positions` entirely (`manager.py:490-501`); and `vectorized_env.py:1036-1041` calls
`effect_manager.tick(...)` without it. `position: "target"`, `"random"` and explicit coordinates
fail the same way or are untypeable (see G-8). **A.7 INERT/dead-surface count: 2.**

**G-5 — `vecNi`/`vecNf`/`vec2i`/`vec3i` in `vfs_profiles.yaml` are accepted then crash the compiler. (defect)**
`GlobalVFSVariableConfig.type` / `AgentVFSVariableConfig.type` accept them
(`config/vfs_profiles_config.py:38-52`), and `compilers/vfs.py:298` then raises an **unhandled**
