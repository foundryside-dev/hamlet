## Action-selection contract and actual effects

`epsilon_greedy_action_selection(q_values, epsilons, action_masks=None) -> Tensor[batch]` is the preserved legacy transport function (AS11–88). Q is `[batch,A]`; epsilon is `[batch]`; the documented mask is bool `[batch,A]`. Masked greedy uses `-inf` at disabled actions. An all-false row deliberately returns unmasked greedy transport rather than diagnosing live illegality (AS49–66). With masks, random candidates are sampled only for rows having a valid action, with exactly zero disabled-action mass (AS68–77); without masks, candidates use `torch.randint` over all rows (AS78–80). It then always draws `torch.rand(batch)` for epsilon gates (AS82–86), including epsilon-zero rows and empty-mask transport rows. This function has no eligibility input and no Generator argument. Setting completed-row epsilon to zero, or merely zeroing its action mask, does not eliminate its gate RNG draw.

`epsilon_greedy_action_selection_eligible(q_values, epsilons, action_masks, *, eligible) -> Tensor[N]` is the strict producer-facing function (AS91–120). `action_masks` is an explicit argument, with `None` permitting all actions. It requires a bool `[N]` eligibility tensor on Q's device (AS104–107). A supplied mask must be bool with Q's exact shape/device (AS108–110); any eligible row with no legal action raises before sampling (AS111–112). Membership is never inferred from mask contents. It initializes every output to unmasked Q argmax, calls the legacy function only on eligible Q/epsilon/mask rows and scatters their actions (AS113–120). With no eligible row, it draws no randomness. Inactive action indices are transport; this helper does not make them legal executable actions. Epsilon geometry/value and Q finiteness are not independently validated by this helper; consumers must not claim broader validation than its body provides.

The legacy helper still samples a candidate and epsilon gate for every selected eligible row even when epsilon is zero; strict eligibility changes which rows enter those operations. A strict implementation need not reproduce the old full-N ambient RNG trajectory that included inactive rows. It must preserve the supported active policy and make any stronger stream-isolation claim separately.

## Provider work that selection must not erase

### RND

Construction stores observation/embedding geometry and a positive integer minibatch size, owns one fixed network (all parameters `requires_grad=False`), one trainable predictor, Adam, pending FIFO list, service counters/clocks and one reward RMS (RND131–189). Those objects belong to this provider instance, with no world-ID partition in this file.

`compute_intrinsic_rewards(observations, update_stats=False)` evaluates both networks under no-grad, computes per-row embedding MSE, optionally feeds **every supplied row's MSE** into the single RMS, then divides each MSE by the updated running standard deviation plus epsilon (RND213–242). It does not subtract the mean, apply intrinsic weight, queue observations or optimize parameters. It has no eligibility argument and does not call `_validate_observations`; caller filtering and valid nonempty admission matter. An all-inactive call should not be converted into an empty `update_stats=True` RMS batch: NumPy moments of an empty input are not guarded here (RND56–66,233–240). Runtime scale and canonical reward composition are different owners.

`update(batch)` ignores a batch without `observations` (RND244–251). With configured service, it assigns a next local compatibility tick, calls the bounded service and advances `step_counter` (RND253–261). With no configured service, it validates rows, owns detached clones, increments admissions and calls the one-minibatch legacy `update_predictor` adapter (RND262–266). It never derives eligibility from `batch` and does not normalize rewards.

`configure_service(options)` validates a fully resolved `RNDOptions`, requires every option explicit and capacity at least one minibatch, and prohibits a live policy switch after admissions (RND280–296). `admit_and_service(observations, *, vector_tick)` requires matching finite floating row width/dtype, configured options and a nonnegative monotone integer vector tick (RND268–278,298–317). It owns detached device clones and caller-selected **eligible predecessor** rows (doc/body RND298–349). It does not accept an `IntrinsicTransitionContext` or apply an active mask itself.

The FIFO service drains complete minibatches until the declared paced budget when `paced_fifo`, or drains complete occupancy without that budget restriction otherwise; incomplete tails remain. Same-tick calls share the ordinary paced budget. At capacity, `service_before_admit` performs separately reported mandatory optimizer work, `drop_newest` accounts dropped new rows, and the other resolved overflow branch drops oldest pending rows (RND322–358). Its receipt is **`PredictorServiceReceipt`**, fields `admitted_rows`, `consumed_rows`, `dropped_rows`, `pending_rows`, `optimizer_updates`, `last_loss`, `paced_optimizer_updates`, `overflow_optimizer_updates` (RND21–36). It is not the identically shaped generic exploration receipt: overflow maps to mandatory service at an adapter boundary, not by renaming the runtime class.

`update_predictor()` consumes exactly the oldest full minibatch, computes frozen-target/predictor mean MSE, performs `zero_grad`/backward/**Adam.step**, removes only the consumed prefix and advances consumed/update counters (RND361–389). This is a real parameter update; action selection, RMS admission and merely configuring service do not substitute for it. The direct adapter is callable independently of the service budget. **Even empty new observations can service already queued complete minibatches**, because the service drain loop runs before checking whether input is exhausted (RND322–330). An action-only eligibility change must not silently remove the preserved shared service schedule or pending work.

`decay_epsilon()` changes `self.epsilon` once when called (RND391–393). Selection reads the passed state's epsilons instead; this file does not establish their synchronization. Do not silently replace state epsilons with this scalar when composing strict action selection.

`available_state()` deep-copies weights, Adam, epsilon, geometry and RMS but not FIFO/clocks (RND395–416). `checkpoint_state()` additionally captures pending row order, resolved service options, accounting, optimizer offset and clocks (RND418–446). Full `load_state` prepares complete state before installation; the explicitly historical available-state path preserves destination pending work/clocks and does not invent absent tails or RNG (RND492–661). No action-policy/global RNG state is in this provider snapshot. The full pending-tail continuation and available-state import roles are distinct preserved APIs.

### Adaptive RND

Reward computation and observation-batch update delegate unchanged (AD103–130); neither applies `current_intrinsic_weight` to returned novelty. The comments claiming replay-buffer weight ownership (AD110–121) are legacy comments, not evidence overriding accepted BAC-C08's canonical environment reward owner.

`update_on_episode_end(survival_time)` appends one supplied survival value, truncates to `survival_window`, and may anneal (AD132–148). The decision requires at least ten history values, recent survival variance below threshold and mean survival strictly above `int(min_survival_fraction * max_episode_length)` (AD150–178). `anneal_weight()` multiplies current scale by decay and clamps to the minimum (AD180–187). No world ID, episode ID or duplicate-completion guard exists in these bodies; the caller must deliver each owned outcome once and must not replace differing lane outcomes with a batch mean. Selection does none of this history work.

`decay_epsilon` delegates to RND (AD189–191). The adaptive snapshot includes contained RND state, scale, thresholds/window/decay and survival history, while `load_state` first loads RND then installs scalar/history fields (AD193–226). Unlike RND's explicit deep-copy snapshot, adaptive `checkpoint_state` places its live `survival_history` list directly in the returned mapping (AD208), and its own scalar/history load is not an all-fields preflight transaction. A higher-level owned/prepared backend must supply its promised snapshot/install ownership; this note does not qualify that unavailable wrapper.

### Count novelty

COUNT68–82 binds a copied resolved count policy, quantization width, entry capacity, device and instance-owned ordered counts/LRU, then initializes the inherited epsilon policy. `compute_intrinsic_rewards(observations, [update_stats] or update_stats=...)` accepts at most one bool admission flag; omission is a pure query. It validates finite floating `[N,D]` with positive D and the configured device, and prepares **all** exact floor-ratio integer keys before mutating (COUNT88–117).

For each row in supplied order it returns `1/sqrt(next_count)` using a finite logarithmic calculation. Only `update_stats=True` increments the stored count, refreshes that key's LRU position and evicts/increments eviction count when necessary (COUNT118–132). Duplicate keys increment sequentially on an admitting call; pure queries neither increment nor refresh, including duplicates. There is no active mask or event deduplication here: caller supplies eligible reward rows and exactly-once admission. The raw novelty values are unweighted.

`admit_and_service(context)` requires an actual `IntrinsicTransitionContext` instance and returns an all-zero generic `ExplorationServiceReceipt` (COUNT134–147). It performs **no second count admission**, has no neural optimizer or FIFO and cannot replace the reward admission. Checkpoint captures owned count dict/LRU list, eviction count, policy and inherited epsilon state; complete validation precedes installation (COUNT149–206). No world bank, action RNG domain or per-world count partition is implemented here. Separate instances can own disjoint count/LRU state; mixing worlds into one instance intentionally shares it.

### ICM

Construction requires the resolved ICM policy and exact matching provider parameters, positive geometry/rate and pending capacity at least a minibatch. It builds float32 encoder, inverse model and forward model, an Adam over **all three modules**, CPU-owned pending transition queue and service counters (ICM46–101).

`_context(context)` requires actual `IntrinsicTransitionContext`; reads predecessor, action, successor and `active_on_entry`; checks `[N,D]`, int64 actions/bool eligibility, provider device and finite float32 observations. Actions are range-checked only for active rows, but predecessor/successor finiteness is checked for **all transported rows** (ICM103–122). Do not fabricate a predecessor, use selected actions as a successor, or present inactive junk as accepted finite context.

`compute_transition_novelty(context, *, update_stats)` validates a bool flag, computes only active rows under no-grad, and returns detached float32 `[N]` with zeros elsewhere. Reward is half the mean squared error between forward-predicted successor features and detached actual successor encoding (ICM124–137). This reward call changes no queue, counter, optimizer or normalizer; `update_stats=True` does not itself train or admit ICM. Observation-only `compute_intrinsic_rewards` and generic batch `update` explicitly refuse missing transition context (ICM139–143). Sending ICM through RND's observation-only adapter would remove a working provider rather than preserve it.

`admit_and_service(context)` uses the complete actual transition and entry eligibility, monotone vector tick, and row-ordered active admissions; it snapshots predecessor/action/successor to CPU (ICM172–193). Overflow preserves the selected service-before-admit/drop-oldest/drop-newest accounting, then complete queued minibatches run up to the ordinary same-tick budget for paced mode or drain otherwise (ICM179–203). Its generic exploration receipt reports per-call counter deltas, absolute pending rows and last loss. Same-tick calls are budget sharing, **not deduplication**; resubmitting a transition admits it again. An active-empty context can still drain pending work under this shared vector-tick API (ICM177–197).

`_train_batch` uses actual queued transitions; inverse cross-entropy plus weighted forward MSE; successor features are detached in the forward term but remain available to inverse learning. It validates finite loss and gradients, then performs **Adam.step**, pops the consumed prefix and advances successful/mandatory/ordinary counters (ICM145–170). Thus encoder, inverse and forward parameters can really change. `checkpoint_state` owns CPU clones of models, optimizer, epsilon, queue, counters and clocks; `load_state` validates candidates before swapping them (ICM219–380). None of these snapshots carries a world RNG bank. No local `select_actions` override triggers this service implicitly.

Adaptive completion still consumes once-only owned outcomes, not sampler calls.

Accepted T18a prose fixes reward phase as `successor_postphysics`, predictor observation origin as `eligible_predecessor`, and ICM input kind as full transition.
