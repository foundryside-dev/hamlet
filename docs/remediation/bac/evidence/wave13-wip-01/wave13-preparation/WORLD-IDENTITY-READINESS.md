Required proposed producer contract (semantic sketch, **not existing signatures**):

1. Initialization requires exact nonempty unique stable IDs, one per actual single-agent world, and binds them to owned live world state. It retains both canonical membership and lane-ordered binding. Reordering is an explicit validated binding operation over the same worlds, or is refused; relabeling tensors cannot create world identity.
2. Reservation/preparation returns an immutable lane-ordered `(world_ids, world_episode_seqs)` receipt with a destination/generation/content binding, without changing cursor, live simulator/private state, RNG, or completion state. It requires the previous boundary closed. A failed POP/bank preflight leaves reservation unaccepted and sequences unchanged. Consumers must validate the same receipt, not reconstruct tuples from local counters.
3. Acceptance is inseparable from exactly one successful reset installation. A repeated identical accepted request returns the same identity receipt without another reset; stale/changed requests refuse. Failed reset must not be recorded as an accepted episode. If failure occurs after irreversible in-place reset work, quarantine/refuse ordinary retry until explicit recovery; do not silently reset again or claim rollback. The present reset is not transactional. To promise retryable reset failure with unchanged simulator/RNG requires a separately demonstrated prepare/install reset design and inspected dependent owners.
4. POP bind/begin currently precedes POP.reset in the amendment's pipeline; distinguish its pre-reset reservation/preflight from final accepted-token consumption. POP/private bank must finish activation against the accepted receipt produced by the one reset, return equal receipts on identical retry, and never advance their own independent sequence. This handshake must be settled jointly with PW05/T18d and T23; merely calling a pre-reset tuple “accepted” would violate the acceptance contract.
5. Completion closes the accepted token once with equal-content retry and changed-content refusal. It does not increment next sequence. Only the producer's next successful accepted reset advances the per-world cursor. T26's completed boundary also requires all sinks/ledger/epsilon/selection/closure; world closure alone cannot authorize save/next reset. An accepted but empty episode is not a synthetic LaneOutcome/committed batch; abort/quarantine semantics must be explicit so an unparticipated attempt cannot be serialized as completed.
6. Producer receipt publishes exact chosen signatures/types, schema/version/keys, starting-sequence convention, invariants/reset order/failure custody, hashes, focused tests/review and pending integrations. Existing POP `bind_episode_worlds` / `begin_batch_episode` / `commit_episode_outcomes` are amendment-attributed consumer APIs, not independently inspected here. PW05 `CuriosityBank.begin_episode/complete` and T18d completion/epsilon hooks remain planned/unverified in this investigation.
