## Proposed API contract — none of these lifecycle APIs exists yet

ENV remains the single owner of actual world-instance binding and per-world accepted cursors. The new declaration module owns data validation only, with no second coordinator. At construction, require `world_roster: WorldRosterDeclaration` and explicit `training_seed: int` in addition to existing required arguments; EF and callers must change directly. Associate each declared identity with the corresponding owned live world state at creation. Persist this association for the ENV lifetime. Never change an ID while leaving its world state in a different lane.

Suggested vocabulary to freeze in a reviewed implementation receipt:

- `prepare_episode(*, batch_episode: int) -> WorldEpisodeReservation`: pure, destination/generation-bound immutable proposal; contains one lane-ordered tuple pair `(world_ids, world_episode_seqs)` plus batch/content identity. Initial per-world accepted cursor0 means no episode has yet been accepted; the first reservation proposes1. Later proposals use each world's accepted cursor+1. Batch number is supplied for correlation and never determines world sequence. Every full ENV reset currently includes every bound world, without collapsing a tuple to lane0.
- `validate_episode_reservation(reservation) -> None`: pure exact destination/generation/content/closed-boundary validation for POP/private-bank preflight. Equal fresh proposals carry equal meaning; there is no mutable reserved cursor.
- `reset(*, reservation: WorldEpisodeReservation) -> WorldResetReceipt`: replaces untokened reset. Receipt contains the exact immutable accepted identity and an owned initial observation accessor. It performs existing reset body exactly once, then installs accepted identity/cursors/receipt together. Equal accepted retry returns the original reset receipt without running sampling, physics, RNG, items or observation encoding again. Store the initial observation owned and return clones so a caller cannot mutate the retry payload. A changed or stale reservation refuses before mutation. A retry must not substitute current post-step observations for the original reset result. In-process retries after rollout must still avoid mutation; callers remain prohibited from using an old reset result to restart rollout.
- `prepare_episode_close(*, accepted, boundary_key, completion_content, participated_world_ids) -> PreparedWorldClosure`: pure validation against accepted identity, canonical event membership and full prepared boundary. It rejects changed duplicate content, foreign IDs and sequence mismatch. The concrete event codec comes from accepted T20/EP/T23 receipts; do not invent a second event fingerprint convention here.
- `close_episode(prepared) -> WorldClosureReceipt`: idempotently installs closure with its immutable content receipt after required completion/ledger/epsilon/selection effects have succeeded. It does not increment cursors. Equal retries return prior closure; changed content refuses. T26 alone publishes the final completed-boundary marker after closure agrees. `prepare_episode` requires T26's matching completed-boundary release, not merely a caller's assertion that close was attempted. The precise typed release handoff must be recorded jointly with T26; ENV must not decide curriculum/epsilon completion itself.
- `checkpoint_world_state`, `prepare_world_restore`, `install_world_restore`: current-only completed-boundary snapshot, pure validation, then destination/generation-checked installation. These restore the same authority; they do not call reset, complete outcomes or reseed existing private streams.

All tokens are immutable tuples/scalars or owned values. Prepared capabilities include owner-instance identity and generation to reject cross-ENV/recreated-instance or intervening-state misuse. Checkpoint payloads serialize semantic state, never live Python capability identities. Fresh restore makes new in-process capabilities. Same immutable lane-ordered identity is passed to POP and private bank; neither reconstructs it from an independent counter.

## Acceptance, failure, empty participation and reentry

The coherent order is pure ENV reservation -> full POP bind/begin and bank preflight -> single ENV reset accepting that reservation -> idempotent POP/bank activation with the same accepted token -> rollout -> existing whole-sink preflight/commit -> ledger -> epsilon/selection -> identity closure -> T26 completed-boundary publication. POP's pre-reset binding/begin are provisional until reset succeeds; they must not publish a completed batch or consume a private episode. T23/PW05 must directly replace their begin protocols accordingly, and retain the accepted receipt across acknowledgement interruptions. This resolves the apparent ordering tension in the amendment without accepting the episode before reset.

A rejected pure preflight leaves all cursors, simulator tensors, RNG, bank history and ledger unchanged. Distinguish that promise from an in-place reset exception. Before entering reset body mark an internal resetting phase; if anything throws after entry, retain failure custody and quarantine the ENV. Do not advance accepted cursors, publish an accepted receipt, permit step/next-reset/ordinary retry or serialize the failed state as completed. Partial simulator/VFS/RNG mutation remains explicitly possible. Catch interruption classes consistently with project failure policy; do not claim a try/finally can atomically roll back arbitrary engine work.

Recovery is destruction/reconstruction by the owning runtime from the last validated completed native checkpoint (or an explicitly fresh run before first acceptance). There is no in-place clear-quarantine toggle. A process interruption after successful acceptance but before caller acknowledgement is handled by the installed accepted receipt; cross-process crash recovery remains last committed checkpoint, not exact mid-episode continuation. Interruption during final receipt installation must fail closed, never allow another reset to proceed on ambiguous state.

An accepted episode with zero participated worlds is not a completed batch and cannot obtain ordinary closure/save eligibility. Provide an explicit abandoned/failed-attempt disposition that blocks continuing this runtime and restores/reconstructs from the last completed checkpoint. No synthetic death, LaneOutcome, dwell, epsilon decay or ledger mark. An episode with some participating worlds may close only with their genuine outcomes; unparticipated lanes receive no completion event, although their successful full reset did consume an accepted world sequence. PW05 must retire their active episode without applying completion effects. This distinction needs an explicit bank retirement handoff, not fake completion. All next accepted resets still derive sequences solely from ENV.

## Row permutation and native state

Do not expose arbitrary in-place tensor row relabeling: moving live worlds would require every row-indexed simulator dependency and private owner to move coherently. The minimal supported permutation is **fresh construction/current-boundary restoration in a requested lane order over the exact same declared membership**, with per-ID cursor/private-state mapping before the next fresh episode. ENV creates fresh worlds assigned those IDs; world-owned learned state and cursors restore by ID. This supports comparison under row permutations without pretending that unchanged tensors became different worlds. Mid-episode permutation is outside the current fresh-episode checkpoint guarantee, not a removal of a documented current API.

Proposed exact world lifecycle envelope `world-lifecycle-v1` has keys: `schema`, `world_roster`, `lane_world_ids`, `training_seed`, `execution_identity`, `accepted_episode_seqs` (exact ID-keyed map), `last_closed_episode` (canonical accepted tuple and closure content identity), and `completed_boundary_key`. Snapshots are allowed only after at least one genuinely participated completed boundary; no provisional/active/resetting/quarantined state is encodable as completed. Validate exact key sets/types (bool is not an integer), seed/identity agreement, membership/order uniqueness and count, nonnegative cursor domain and closed-token/cursor equality, event membership, and cross-owner POP/bank/T26 consistency before install. A fresh-state transport, if needed for initial construction, is the roster declaration, not a fake completed checkpoint.

Restore keeps accepted cursors unchanged. The next reservation maps each cursor+1 into requested lane order. It neither reruns closure nor increments on load. Cross-owner validators must reject a plausible-looking but contradictory bank/VFS/POP cursor; self-validation of ENV fields is insufficient. No current native validator accepts obsolete no-roster or VFS-only state by guessing identities.

VFS must consume accepted per-world identity directly, eliminating autonomous reset increment and row-derived identity before row-permutation simulator equivalence can be qualified. Prior receipt establishes that this work is needed, not that it has been implemented. Likewise generator=None/shared-layout sampling leaves simulator independence unqualified. The real learner/reset RNG interference case remains an **unrun hypothesis**. Preserve independent worlds/shared-Q distinction, all five exploration choices/four network-replay families and existing mechanics. Do not reuse curiosity seeds as simulator domains, promise an unproven RNG fix or shrink functionality to lockstep-only identity to avoid the work.

### R1: explicit boundary authority, bootstrap and restore

Freeze the following ENV APIs and immutable producer DTOs. `BoundaryKey` is the nonnegative integer batch episode within the selected execution identity; bool refuses. The identity owner records the last accepted batch and refuses reuse or regression. Bootstrap explicitly names the first batch; completed release permits only last batch+1. No batch integer supplies a world sequence.

`env.bind_boundary_authority(*, owner: object) -> WorldBoundaryAuthority` binds once before prepare/reset or restore. `owner` is the actual single T26 runtime owner object, compared by object identity, never a caller-provided label. Equal owner retry returns the same capability; a different owner refuses without mutation. The returned capability is privately retained by T26, never serialized or exposed to episode callers. Its constructor is not a public API; the capability contains an unforgeable in-process owner nonce, ENV destination and generation. This is cooperative in-process custody, not a security boundary against arbitrary Python introspection.

The capability has exactly these issuance methods:

- `bootstrap(*, first_batch_episode: int) -> WorldBoundaryRelease`: allowed only for never-accepted fresh ENV, all accepted cursors zero, no restore pending, no prior bootstrap consumption. The immutable release names kind bootstrap, semantic run identity, destination nonce, initial generation and permitted first batch. Repeated issuance of identical bootstrap content returns the same release while unconsumed; a changed first batch refuses.
- `completed(*, closure: WorldClosureReceipt, effects: BoundaryEffectsReceipt) -> WorldBoundaryRelease`: checks the exact ENV-issued closure and same batch/token/content plus an effects receipt issued by this bound T26 owner. `BoundaryEffectsReceipt` fields are `batch_episode`, `accepted_identity`, `completion_content`, `curriculum_receipt`, `exploration_receipt`, `population_commit_receipt`, `epsilon_install_receipt`, `selection_sync_receipt`, and `retirement_receipt`. Each referenced receipt is owned immutable content under its accepted producer contract. T26 is responsible for obtaining successful receipts from every sink, including idempotent epsilon/selection installation; the authority validates all correlation identities and issuer custody. Missing or mismatched evidence refuses. The release permits batch+1, pins closure and effects content, and is issuable after closure without serializing or saving anything.
- `restored(*, restore: PreparedWorldRestore, boundary: RestoredBoundaryReceipt) -> WorldBoundaryRelease`: only during a fresh destination's joint restore. `RestoredBoundaryReceipt` is issued by bound T26 after pure validation of saved completed-boundary and all nested owner states. It contains saved boundary key/content, saved closure/effects semantic records, semantic run identity, and destination prepared-restore generation. No live old capability is accepted. This release is staged with prepared restore and becomes usable only when that same prepared restore installs.

`env.install_boundary_release(release: WorldBoundaryRelease) -> WorldBoundaryRelease` validates issuing capability identity, destination/generation, kind, permitted batch and exact pinned content before mutation. The sole new state is the installed release and phase. Equal installed retry returns the original receipt without effects. Wrong issuer/destination, changed content, stale release after a newer accepted generation or consumed bootstrap refuses purely. An equal previously-installed completed release remains a no-op retry while that boundary is still current; it cannot reopen it after the next reset. No release operation invokes a sink or reset.

`env.prepare_episode(*, batch_episode: int, release: WorldBoundaryRelease) -> WorldEpisodeReservation` requires the exact installed release and its permitted next batch. Pure repeated preparation does not consume it. Successful reset atomically consumes its one permission along with accepted cursor installation; only then is bootstrap spent. Thus failed pure preflight can retry bootstrap, while no second successful bootstrap episode is possible. Step is blocked until POP/private-bank accepted activation receipts agree through `env.activate_episode(*, accepted: WorldAcceptedEpisode, population_receipt: object, curiosity_receipt: object) -> WorldActivationReceipt`; this method validates the frozen consumers' exact identity/content and returns equal receipt on retry without advancing cursors.

Lifecycle phases are fresh-unbound, bootstrap-ready, active-awaiting-activation, active, closed-awaiting-release, released-completed, restoring, and quarantined. Reset-in-progress is a transient fail-closed phase. `close_episode` moves active to closed-awaiting-release only; prepare/save both refuse there. `checkpoint_world_state(*, release: WorldBoundaryRelease)` requires current installed completed/restored release in released-completed phase; bootstrap does not qualify. After installing a matching completed release, next prepare and saving are independently allowed. Saving neither produces nor consumes the release. Interruption after closure/before release is recovered by equal closure/effects/issuance/install retry.

`env.prepare_world_restore(*, state: Mapping, world_roster: WorldRosterDeclaration, destination_world_ids: tuple[str, ...], semantic_execution_identity: str) -> PreparedWorldRestore` is pure on a fresh bound destination and validates rules below. `env.install_world_restore(*, prepared: PreparedWorldRestore, release: WorldBoundaryRelease) -> WorldBoundaryRelease` installs only the matching restored release and prepared state after all parent/nested preparation succeeds. Parent T25/T26 owns joint installation/quarantine on unexpected interruption. Installation creates fresh local accepted/closure/release capabilities representing the already-completed semantic state and enters released-completed; it performs no reset, closure effect, completion, epsilon change or private RNG reseed. The historical closure/effects records remain saved data. The returned release permits saved batch+1. Equal install retry returns the same installed receipt; altered/stale preparations refuse. This explicitly separates native semantic validation from in-process capability rebinding.

### R2: semantic membership, destination order and historical receipts

Freeze roster serialized form as `{"schema":"world-roster-v1","world_ids":[<exact strings in authored order>]}`. The declaration owns an immutable tuple; `from_dict` clones/validates the exact object, `to_dict` returns a fresh dict/list. Original authored order is persisted unchanged as declaration provenance. `roster_semantic_identity` is SHA256 of UTF-8 canonical JSON `{"schema":"world-membership-v1","world_ids":sorted(exact_ids)}` with sorted keys, compact separators and ensure_ascii=True. It identifies membership, not physical lane order. Execution semantic identity includes this membership hash and actual immutable configuration/seed meaning; it excludes current or historical lane binding. Never hash exact IDs into replacement world names.

A separate `world-binding-v1` record has `world_ids` in lane order and its canonical-JSON SHA256. The native envelope retains both the originally authored roster and the **saved** binding used by its last accepted/closed episode. Validate saved binding uniqueness/membership/hash and that last episode's event correlations against it. Every older retained event uses its own batch's immutable accepted binding, under the R2a amendment below; the latest saved binding cannot validate an older row. Historical EP events, their canonical fingerprints, batch IDs and agent indexes are preserved verbatim. Do not permute/re-hash old events or amend POP seen-event records to destination order.

The required `destination_world_ids` argument to prepare_world_restore is a permutation of exact declared membership. Its order controls the fresh ENV binding for the next episode only. The supplied `world_roster.to_dict()` must equal the persisted authored declaration, including authored order; a caller requests permutation only through destination_world_ids, never by rewriting the manifest. Compare semantic execution identity for continuation eligibility; compare saved binding to saved history for integrity; validate destination binding separately. Checkpoint envelope fields therefore distinguish `saved_lane_binding` from `destination_lane_binding`; when saving a completed new episode, its actual destination binding becomes that snapshot's saved binding. The previous closed historical token keeps its original binding until a new real episode closes. Current native schema must encode both where those phases differ, never overload a single lane_world_ids field.

POP restores historical ledger/event records verbatim; its next bind consumes the new receipt. PW05 restores states by exact ID. WS reconstructs its destination descriptor from the same policy, seed and new lane order while validating its saved descriptor against saved binding; private RNG/backend identities and seeds remain unchanged by ID. T24/T25/PW05 must implement these explicit validators, not assume an ordered descriptor hash can be compared directly across destination bindings.

A genuine current history starting all cursors0 and resetting the full roster keeps accepted cursors equal. Native producer tests must use that reachable history, distinct per-ID learned/private state and reversed destination order; an invented unequal cursor map cannot stand in for genuine native continuation. The API retains per-ID sequence representation and does not reduce identity to a scalar. Unequal native cursors require an explicitly validated future lifecycle provenance owner; this packet introduces no fabricated provenance or arbitrary importer. Reject unsupported unequal native histories rather than claim them current reachable state. This does not assert simulator order independence before the VFS/physics owner qualifies it.

### R3: explicit PW05 disposition and abandonment

Freeze PW05's future boundary APIs (owned/implemented in its existing bank slice):

`bank.prepare_episode_dispositions(*, accepted: WorldAcceptedEpisode, boundary_key: int, completed_outcomes: tuple, participated_world_ids: tuple[str, ...]) -> PreparedWorldDispositions`

`bank.commit_episode_dispositions(prepared: PreparedWorldDispositions) -> WorldDispositionReceipt`

Preparation is part of the whole-sink preflight, before any sink mutates. It validates exact accepted token/binding, canonical genuine events and their positive participation witness from POP's prepared publication; the supplied participated set must equal actual event world membership. At least one participant is required. For every accepted world it proposes exactly one disposition: completed with that world's real event/fingerprint, or retired_nonparticipating with no event. It rejects a purported completion for a zero-participation lane, a retirement for a participated lane, wrong sequence, duplicate world, changed duplicate content or foreign token. Every accepted world is covered exactly once. This pure operation consumes no RNG/history/cursor/service work.

Commit installs completion effects under PW05's idempotent completion receipt plus retirement records under the same boundary identity. An interruption can leave a subset installed; equal retry deterministically finishes remaining worlds without repeating completed effects. A changed disposition batch refuses from its pinned prepared content. Retirement changes only lifecycle disposition/receipt; no synthetic outcome, survival/history append, service clock/update, scale update, epsilon change or RNG draw. The combined WorldDispositionReceipt records accepted token, boundary, canonical outcome content, exact participant set and per-world disposition receipts. `retirement_receipt` in T26 effects is this combined receipt, including its empty retirement subset when all participate.

Freeze each PW05 world native lifecycle record to the exact fields `accepted_seq`, `settled_seq`, `last_completed_seq`, `last_completed_content`, `current_disposition`, `current_disposition_content`, and `active`. The backend/private state schemas remain owned elsewhere. After accepted begin at sequence s, accepted_seq=s, settled_seq=s-1, active=true, current_disposition=active, current_disposition_content=null. Begin must be exactly prior accepted_seq+1 with prior accepted_seq=settled_seq and active=false; equal same-token begin retry returns its prior receipt. Initial accepted_seq=settled_seq=last_completed_seq=0, last_completed_content=null, disposition=initial, active=false.

After genuine completion at s: accepted_seq=settled_seq=last_completed_seq=s, active=false, current_disposition=completed, and current_disposition_content=last_completed_content=the genuine canonical event identity/fingerprint. After retirement at s: accepted_seq=settled_seq=s, active=false, current_disposition=retired_nonparticipating, current_disposition_content=the retirement token/boundary/content fingerprint; last_completed_seq/content remain exactly the prior genuine completion marker, possibly0/null. Always 0<=last_completed_seq<=settled_seq<=accepted_seq; zero completion marker iff null completion content. Do not equate last_completed_seq to ENV accepted_seq for retired worlds.

At completed native boundary, for every world w: bank.accepted_seq[w]=bank.settled_seq[w]=ENV.accepted_seq[w], bank.active[w]=false. Genuine current participant IDs equal the completed disposition IDs and POP event-world IDs; complement equals retired disposition IDs; the union equals accepted membership and intersection is empty. Saved last-closed token, disposition content and T26 receipt agree on sequence/boundary/participation. Preserve older last_completed_content for retired worlds and validate its recorded sequence. Future checkpoints need not fabricate a full historical journal to establish current retirement; retain the owned canonical dedup records required by PW05/POP contracts. These exact equations enter joint pure native validation before install.

Extend ENV closure to require `prepare_episode_close(*, accepted, boundary_key, completion_content, participated_world_ids, dispositions: WorldDispositionReceipt)`. Closure validates the bank-issued committed disposition receipt against the exact full token, participants and content. Thus retirement commits before ENV closure, and closure before release. Receipt custody is bound to the actual PW05 instance during accepted activation; callers cannot pass a mere tuple with matching names as a committed receipt. Equal acknowledgement retry returns the same disposition/closure without effect.

Freeze `env.abandon_episode(*, accepted: WorldAcceptedEpisode, reason: str) -> WorldAbandonmentReceipt`. For an all-empty accepted episode, reason must be `empty_participation`; ENV verifies no eligible step participation and POP/private-bank prepared empty evidence from the accepted activation owners before recording abandonment. Freeze both consumers' callable `prepare_empty_episode_evidence(*, accepted: WorldAcceptedEpisode) -> EmptyEpisodeEvidence`: it purely refuses if any eligible participation/admission or event exists, otherwise returns an immutable owner/generation-bound accepted-token receipt with empty participation/event sets. Activation receipts carry their issuing owner reference and generation in process; ENV retains those exact references and calls both methods, validating their returned identity/generation before abandonment. No caller boolean substitutes for this evidence. These are future POP/PW05 consumer methods, not existing APIs. More generally `reason=runtime_failure` records a failed active attempt without implying zero participation. Allowed reasons are exactly these two. Same accepted token/reason retry returns the original abandonment receipt; altered/wrong token refuses. Abandonment enters quarantined, blocks step/reset/prepare/save and never issues closure/release, retires a fake completed batch or rewinds cursors. Only reconstruction from last completed native boundary (or explicitly fresh run if none exists) recovers.
