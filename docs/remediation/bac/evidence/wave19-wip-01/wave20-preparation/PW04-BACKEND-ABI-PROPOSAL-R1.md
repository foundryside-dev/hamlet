## Exact proposed public boundary

Existing constructor parameters retain order/defaults. Add keyword-only `rng: WorldRNGState | None = None` and `service_clock_unit: Literal['vector_tick', 'world_eligible_admission'] = 'vector_tick'` to each provider constructor (ICM already has keyword-only parameters). Validate exact unit literal and all scalar/geometry configuration before model construction or RNG activation. The unit is an immutable selected configuration exposed read-only as `service_clock_unit`; it cannot switch through a call or native import. Default vector_tick is the current intentional shared selection, not missing-format inference. Private factory must pass world_eligible_admission explicitly. RNG ownership and cadence are distinct selections; passing rng does not silently select a unit.

Add/retain these concrete methods:

- RND: `admit_and_service_at(observations, *, clock: ServiceClock) -> PredictorServiceReceipt`.
- ICM: `admit_and_service_at(context: IntrinsicTransitionContext, *, clock: ServiceClock) -> ExplorationServiceReceipt`.
- AI: `configure_service(options: RNDOptions) -> None`, `admit_and_service_at(observations, *, clock: ServiceClock) -> PredictorServiceReceipt`, and `predictor_service_counters() -> PredictorServiceCounters`, delegating to its actual RND.
- Every provider: `validate_state(state: dict[str, Any]) -> None`, `prepare_state(state: dict[str, Any]) -> opaque destination-bound prepared candidate`, `install_state(prepared) -> None`, and existing `load_state(state) -> None` implemented as prepare then install. Candidate classes live in the respective counted provider file, not a new module. Candidate contents are not public mutable API.
- Preserve substantive current shared entrypoints RND `admit_and_service(observations, *, vector_tick)`, ICM `admit_and_service(context)`, and RND/AI direct `update`; shared entrypoints explicitly select/require the constructor's vector_tick unit. They do not detect old formats or fall back after rejection. Add AI shared service delegation using the same explicit vector_tick signature as RND. Preserve RND direct buffer/update_predictor training in vector_tick mode. Private unclocked/direct entrypoints reject before mutation; private training runs through the clocked entrypoint and a private minibatch implementation, so the public guard does not block its real optimizer work.

`ServiceClock` requires exact type and rechecked exact unit/nonnegative Python int position; bool/float/NumPy scalar aliases refuse. This defends consumers even against forged frozen instances; it is not a security boundary against arbitrary internal mutation. Imports must preserve the receipted WS→RP direction; no new RP source read or reciprocal eager dependency is authorized.

Whole observations/context geometry, dtype, finite values, layout/device validity, selected resolved policy/capacity, clock type/unit and progression are checked before any append, drop, budget/counter change, optimizer/RMS change or model callback. RND consumes only caller-selected eligible predecessor rows. ICM validates all observation rows and all action/eligibility tensor geometry/types, then selected active action ranges; inactive actions remain unused as in its supported context contract. ICM admits active rows in original lane order. Context vector_tick remains required valid metadata even in private mode but grants no private work. In shared ICM mode the supplied clock.position must equal context.vector_tick. RND retains lawful source-device transfer into its destination, with dense concrete CPU/CUDA floating tensors only; no sparse/meta or nonfinite late-row loophole. Empty RND input still requires shape (0, obs_dim) and correct dtype/device class. Empty/all-inactive ICM still validates the entire context.

Reward entrypoints validate their full input and exact bool update_stats before invoking networks or changing RMS; empty RND reward returns an empty detached result without updating RMS. Native malformed-input refusal is distinct from a late numerical/model failure during real training: the latter may have changed a live provider and is quarantined by OwnedWorldBackend, never silently retried or claimed rolled back.

## Cadence: one finite rule per selected unit

Private origin is position0. Let p be the saved cumulative service position and n the number of actually eligible input rows, including rows explicitly dropped by the selected overflow policy. Require requested position = p+n. This is exact, not merely monotone. Skips, regression, nonempty same-position input and advancing empty input all refuse unchanged. The episode-local eligible_seq in a stamp is NOT this cumulative position; ordinary episode resets do not reset p. The bank owns that relation and accepted identities.

After full preflight, a private n-row call is executed as n consecutive one-row events at positions p+1 through p+n in input order. At each event reset its ordinary budget, then perform the provider's existing single-row admission/service order with that row and capacity policy. RND's existing order drains eligible queued full batches before append and again after append; ICM's existing order checks overflow, appends, then drains. Preserve those provider-specific algorithms. Aggregate all actual per-row receipt deltas; pending_rows is final occupancy and last_loss follows the provider's existing convention (RND None if no update; ICM retained last successful loss). The stored ordinary budget is work used at final position, not the aggregate across the call. `max_updates_per_tick` remains the existing policy field name; for private selection its unit is explicitly one actual eligible admission. Unused budget expires at the next actual admission, never accumulates as credits. Thus grouping or splitting the same ordered admissions yields identical losses, batch order, parameters, counters, tail, final clock and final budget; no grouping-dependent opportunity multiplier or loss.

Private n=0 with requested position=p returns a zero-delta receipt without servicing, resetting budget, selecting a different clock, changing step_counter or changing state. Repeated empty calls are state-idempotent. This is not event retry support: repeating a nonempty event with its old position fails; passing an advanced valid position denotes new admissions, and providers cannot detect duplicate content. Only the later bank authenticates EventIds/phases and returns its equal-last-content receipt without calling the provider again. Changed-content/expired retries belong to that bank, not this provider.

Shared selection preserves current grouped batching and vector cadence: nondecreasing exact positions, reset ordinary budget only on a new vector tick, same tick shares remaining ordinary budget, and a newer empty vector call may service a previously complete tail. An equal shared position is not dedup and can admit more rows. Mandatory overflow work may exceed ordinary pacing, with separate receipt accounting. Do not run shared multirow calls through the private per-row algorithm; that would change current behavior. Occupancy service continues draining full batches according to existing provider order.

All modes maintain admitted = consumed + dropped + pending and consumed = successful_service_updates * training_batch_size. Drop-newest still counts admission and private position advancement; drop-oldest discards oldest queued rows only; service_before_admit performs real mandatory optimizer work rather than dropping. Every loop either admits, consumes or explicitly drops, including batches larger than capacity. Ordinary and mandatory/overflow work remain separately reported. Python positions are unbounded exact ints: no wrapping at int64, and a huge skipped private position refuses without iterating the gap. There is no new options family.

Concrete private grouping control: initialize equal providers with B=2, capacity=4 and paced budget1. Admit seven ordered rows in one call at position7 versus calls of sizes [1,3,0,2,1] at positions [1,4,4,6,7]. Require full final state and concatenated consumed batches/losses equal. Repeat with all overflow policies and a native lawful complete queued tail so overflow/budget controls are substantive. Construct that tail through a completely validated current native payload with conserved admissions and clock (not direct private mutation or a fake optimizer). Large n alone under per-admission pacing need not trigger overflow; tests must assert the selected pressure actually did so.

## Findings, risks and limits

Confirmed source defects/gaps: vector-tick service can create work opportunities on newer empty calls; local typed clocks and constructor component hooks absent; ICM has off-side load but no public complete standalone validator/prepared API; AI snapshot/load aliases survival_history and mutates RND before reading all outer fields; RND validate/load accepts missing-service historical payloads. Current reward/completion input boundaries need complete validation before mutation. These are source-confirmed contract gaps, not invented exploit severities.

Refuted hypotheses: isolated provider instances alone prove admission clocks; immutable stamp alone authenticates identities/dedup; successful load/readback equals complete native validation; all private multirow input must share one budget; every empty call in shared mode must be forbidden; ICM consumes a target initialization stream; actual optimizer learning can be replaced by frozen predictors for isolation proof.

Risks requiring root attention before dependent coding: actual clock source ABI still pending; constructor/import dependency must be checked against that finite receipt; provider ceilings leave 311 RND/370 ICM/274 AI lines of growth so public candidate/refactor code may require root reslice; local per-admission pacing deliberately differs from shared grouped pacing and must pass partition invariance; current-only schema changes necessarily require actual consumer migration; later explicit clone origin/counter rebasing remains an owner contract, not guessed here. Hardware CUDA continuation is qualified only when genuinely exercised.

Optional extensions excluded: new scheduler/clipping/loss scaling algorithm, generalized clock options, cross-device bitwise promise, new bank or lifecycle coordinator, arbitrary stamp serialization/hash, compatibility decoder, and copied provider engines. Required original POP/runner/native acceptance is not an optional extension. No routine human permission question or global replanning is introduced.
