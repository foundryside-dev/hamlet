## Cadence: one finite rule per selected unit

Private origin is position0. Let p be the saved cumulative service position and n the number of actually eligible input rows, including rows explicitly dropped by the selected overflow policy. Require requested position = p+n. This is exact, not merely monotone. Skips, regression, nonempty same-position input and advancing empty input all refuse unchanged. The episode-local eligible_seq in a stamp is NOT this cumulative position; ordinary episode resets do not reset p. The bank owns that relation and accepted identities.

After full preflight, a private n-row call is executed as n consecutive one-row events at positions p+1 through p+n in input order. At each event reset its ordinary budget, then perform the provider's existing single-row admission/service order with that row and capacity policy. RND's existing order drains eligible queued full batches before append and again after append; ICM's existing order checks overflow, appends, then drains. Preserve those provider-specific algorithms. Aggregate all actual per-row receipt deltas; pending_rows is final occupancy and last_loss follows the provider's existing convention (RND None if no update; ICM retained last successful loss). The stored ordinary budget is work used at final position, not the aggregate across the call. `max_updates_per_tick` remains the existing policy field name; for private selection its unit is explicitly one actual eligible admission. Unused budget expires at the next actual admission, never accumulates as credits. Thus grouping or splitting the same ordered admissions yields identical losses, batch order, parameters, counters, tail, final clock and final budget; no grouping-dependent opportunity multiplier or loss.

Private n=0 with requested position=p returns a zero-delta receipt without servicing, resetting budget, selecting a different clock, changing step_counter or changing state. Repeated empty calls are state-idempotent. This is not event retry support: repeating a nonempty event with its old position fails; passing an advanced valid position denotes new admissions, and providers cannot detect duplicate content. Only the later bank authenticates EventIds/phases and returns its equal-last-content receipt without calling the provider again. Changed-content/expired retries belong to that bank, not this provider.

Shared selection preserves current grouped batching and vector cadence: nondecreasing exact positions, reset ordinary budget only on a new vector tick, same tick shares remaining ordinary budget, and a newer empty vector call may service a previously complete tail. An equal shared position is not dedup and can admit more rows. Mandatory overflow work may exceed ordinary pacing, with separate receipt accounting. Do not run shared multirow calls through the private per-row algorithm; that would change current behavior. Occupancy service continues draining full batches according to existing provider order.

All modes maintain admitted = consumed + dropped + pending and consumed = successful_service_updates * training_batch_size. Drop-newest still counts admission and private position advancement; drop-oldest discards oldest queued rows only; service_before_admit performs real mandatory optimizer work rather than dropping. Every loop either admits, consumes or explicitly drops, including batches larger than capacity. Ordinary and mandatory/overflow work remain separately reported. Python positions are unbounded exact ints: no wrapping at int64, and a huge skipped private position refuses without iterating the gap. There is no new options family.

Concrete private grouping control: initialize equal providers with B=2, capacity=4 and paced budget1. Admit seven ordered rows in one call at position7 versus calls of sizes [1,3,0,2,1] at positions [1,4,4,6,7]. Require full final state and concatenated consumed batches/losses equal for every provider and overflow policy. Explicitly assert zero private RND/AI overflow/drop work in this geometry, even from a validated full native tail: each event drains a complete ordinary batch before checking room, leaving space for its single new row. That is the required algorithmic outcome, not overflow coverage. Keep actual extra private admissions/positive-LR updates/rewards/completions as world0 pressure. Separately exercise each retained shared RND/AI overflow branch with ten ordered rows at one vector tick, B=2/capacity4/cap1: the initial ordinary batch exhausts pacing, later admissions fill capacity, and subsequent rows trigger the chosen mandatory-service or drop branch. Assert actual mandatory updates or drops, exact consumed/pending FIFO contents, conservation and changed parameters/Adam. For ICM, use its preserved pre-append overflow order with a completely validated current native full tail and one real private admission to exercise each branch. Label this imported-tail private coverage, not naturally accumulated backlog; conserve admissions/counters/position and actual warm optimizer history in that payload. Never substitute a fake optimizer or alter private pacing to force an unreachable assertion. The private partition/idle requirements and every overflow branch remain required through their reachable witnesses.
