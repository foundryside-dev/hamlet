## Ownership, phase machine and failure semantics

Private construction is eager in canonical exact-ID order, bank-owned mapping. For each ID call WorldRNGState.create(descriptor=..., world_id=..., cuda_devices=...) at quiescence, then OwnedWorldBackend.construct(rng=..., factory=lambda candidate: make_backend(policy, world_id=..., obs_dim=..., action_dim=..., device=..., rng=candidate, descriptor=...)). Do not retain/use the initial RNG in place of the construct candidate. No RNG snapshot inside callbacks, cross-owner activation, or shared target storage. Publish bank only after all owners constructed. Shared constructs exactly one actual provider with explicit world_id/rng/descriptor=None and vector_tick policy. Global selector is created separately by make_policy_selector under its external owner; bank never selects Q actions or decays global epsilon.

Each exact world owns epoch0, accepted episode, settled eligible sequence, cumulative service position, participation/disposition, pending reservation and last reward/service/completion content plus owned receipt. Cumulative position increments only after successful eligible service and never rebases on ordinary begin. Eligible sequence settles only after reward then service succeed. Reward cannot be skipped; service before reward refuses. Next eligible reservation before prior service refuses. Completion requires no outstanding reward/service/reservation for participating worlds. Completion commit blocks further steps until next accepted episode. Empty accepted attempt must be abandoned via actual ENV empty evidence; it is not ordinary completion.

Replay equality includes accepted token identity and full local event/source content: stamp fields, predecessor/action/successor bytes with dtype/shape/device, eligibility, reward update_stats and phase. Shared equality includes whole ordered batch and vector_tick. Private local content excludes unrelated spectator data and global tick as scheduling authority, but each presented context must still match its reserved actual vector_tick provenance. A completed local event may replay last same-content reward/service without a provider call; changed local data, a prior expired ID, gaps, regression, wrong episode/epoch, or wrong phase refuse before any owner call. Inactive retained event IDs never trigger old active receipt replay. Complete batch preflight runs before any row mutation; output scatter uses declared IDs, never row index as identity. Last-phase payload copies are bounded (one event per phase/world), not only unverifiable fingerprints. Do not use stamp identity equality for content checks.

Once an unexpected live provider callback fails, OwnedWorldBackend quarantines that owner; bank quarantines the batch so already performed earlier world effects cannot be retried as though atomic. Expected malformed input is rejected before callbacks. This does not claim rollback of real optimizer updates. Bank serialization excludes shared-policy operations while any private RNG frame is active. snapshot() advances owner revision; never snapshot between prepare and install. A bank transaction revision additionally guards pending completion candidates and cursor state; read-only native diagnostics requiring owner snapshot must also invalidate prepared bank tokens.

Ordinary begin resets only episode-local cursor/reservation/phase caches after accepted advancement; retain models/Adam/gradients, targets, RMS/counts/LRU, queues/tails/drop counters, adaptive history/weights, RNG and cumulative admission/service position. Terminal eligible-on-entry transition is rewarded/serviced exactly once. No population mean scale, active-count denominator, world0 history broadcast, shared quota or global-tick private budget.

DAC remains raw * scale[N] * authored drive base * authored modifiers with existing ending/retirement handling. Bank does not apply base/modifiers or compose extrinsic totals. Eligible runtime scale is actual adaptive get_intrinsic_weight() or resolved initial_intrinsic_weight for the other families; do not infer it from logged summaries. Adaptive raw is unweighted, so DAC applies the scale once.

### F1: exact completion mutation domain

Only adaptive survival_history and current_intrinsic_weight may change at completion. Nonadaptive providers receive no completion call. The shallow-copy algorithm recipe above preserves all other live object identities and values, including nonempty parameter gradients and pending tails. ### F2: one pending completion and explicit revisions

Bank owns integer mutation_revision initially0, one pending_completion slot initiallyNone, one last committed completion receipt/content, and a failed flag. A serialized successful begin, new stamp reservation, reward publication, service settlement, completion-slot publication, completion commit, empty-abandon settlement, or diagnostic owner observation increments mutation_revision exactly once per public operation. Equal cached replay and input refusal increment nothing. A failed candidate operation which already invoked owned.call increments mutation_revision once to reflect owner observation, but leaves learned values, cursor/disposition/receipt caches unchanged unless an unexpected failure quarantines. Explicitly do not promise owner/bank revision equality after such attempted preparation. Snapshot_world increments mutation_revision once because WS snapshot increments owner revision; a metadata-only estimate/read of immutable report does not.

prepare_completion first checks pending slot: same actual accepted token, key, full owned completion content, canonical outcomes and dispositions returns identical prepared object/receipt with no owner calls; any changed preparation refuses before allocation or owner observation. Then validate ALL outcomes via public lane_outcome_state plus token/order/geometry/phase correlations before any candidate callback. Candidate results remain local until every participant succeeds; only then publish the slot and its prepared receipt. Bank revision stored in the token is the post-publication value. If a candidate's expected algorithm validation raises ValueError, catch it inside the shallow-candidate callback and return an owned tagged refusal, so the real owner is not falsely quarantined for that expected candidate refusal; bank then raises ValueError after recording observation revision. Unexpected exceptions retain actual WS quarantine behavior. Prior successful off-side candidates are discarded on refusal, not installed. Last malformed outcome therefore causes zero owner calls and full revision equality; a later candidate numeric refusal preserves learning/RNG/cursors/cache but advances observation revisions explicitly.

While a pending completion exists, all step preparation/reward/service/begin, diagnostics taking owner calls/snapshots, new completion content, and empty-abandon settlement refuse before mutation. Only identical prepare replay, exact commit, and immutable metadata inspection are allowed. commit checks actual token object/destination, pending-slot identity, full content, expected mutation_revision and all participant bindings before first publication. Install all history/weight values using actual unchanged owners, then dispositions/caches and sealed receipt, clear slot and increment bank revision once. Equal last commit replay is mutation-free; consumed unrelated/stale/wrong-destination tokens refuse. Unexpected publication failure quarantines the whole bank; it does not retry earlier applied worlds. No WS restore tokens or snapshots are used during completion, so there is no hidden native-token revision assumption.
