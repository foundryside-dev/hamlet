## Proposed minimal public ABI (new, requires root authorization)

Add three serialized BANK methods, every argument explicit and keyword-only where present:

- `checkpoint_state()` returns one owned complete current bank mapping. Unlike snapshot_world it is a restore format and exports shared provider state exactly once. It preserves the existing _available guard: quarantined source and a pending _prepared completion refuse before any owner observation, report callback, clone, revision change or other mutation. An allowed owner snapshot advances the existing observation revision; saving is not permission to install a stale prepared restore.
- `prepare_restore(state, mode, accepted, parent_restore, validate_parent_restore)` returns an opaque PreparedCuriosityRestore; all five arguments are required and keyword-only. mode is exactly initial, live_episode or completed_boundary, and must equal the saved bank_phase. Live mode requires the actual authenticated current token and explicit parent_restore=None/validate_parent_restore=None. Completed mode requires accepted=None, the actual retained ENV prepared_restore record, and a required pure parent correlation callback as specified below. Initial mode uses accepted=None and either an explicit parent prepared INITIAL record/callback pair or both None for a standalone zero-state bank operation. No live token is manufactured. It validates all metadata and prepares every actual provider/owner off-side before any child install. No destination owner snapshot/call, revision increment, quarantine, cache update or live provider load occurs on expected refusal.
- `install_restore(prepared)` performs the final destination/token/revision/nonconsumption checks under the BANK lock and publishes the fully allocated runtime bundle. It returns None. It never invokes provider loaders, validators, allocation callbacks, receipt issuers or user callbacks after publication begins.

CP exposes the PreparedCuriosityRestore type and portable codec/validation functions used by these methods; it does not read BANK private members, WS private members or provider internals. BANK supplies its complete export mapping and explicit immutable policy/descriptor/device identity to CP. BANK itself assembles candidates through its existing factory and the public WS lifecycle. The prepared token retains a BANK-owned private candidate bundle separate from caller-visible data, a destination identity, a captured destination revision, and single-use state. No public token field is a replacement trust source. Local imports from BANK into CP, if needed, must avoid module cycles; CP must not import BANK at initialization.

Remove the earlier proposed committed_completion restore token entirely. Imported history yields only owned historical checkpoint data through checkpoint_state; neither the preparation nor installation exposes a PreparedBankCompletion, issues prepared_dispositions/dispositions, or populates the live _committed slot from history. Existing source-instance commit_completion retries retain their legitimate original live token/receipt semantics. Historical data never qualifies as one of those tokens. No new historical receipt kind or live close capability is needed.

This adds producer seams rather than pretending snapshot_world is complete or accessing owners from the consumer. Do not expose a general callback that can mutate the live bank during preparation. Same-scope restore is the PW06 operation. Explicit clone and conversion are separate named operations downstream; silently selecting either from mismatched native state is forbidden.
