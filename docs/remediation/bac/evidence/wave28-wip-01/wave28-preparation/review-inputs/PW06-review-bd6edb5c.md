## 1. High — required fresh COMPLETED resume has no callable authentication path

Proposal's minimal ABI and accepted_identity paragraphs require a currently authenticated receiving ENV token for every noninitial bank checkpoint, with None legal only for no saved accepted episode. The CURRENT-WORLD-IDENTITY-CONTRACT's fresh restore requires a fresh authority-bound ENV without live history, prepares all children before joint installation, restores COMPLETED cursors/history, and allows the next fresh episode. Its public accepted token is obtained by actual reset. CURRENT-ENV-ACCEPTED-AUTH-CONTRACT accepts only the current exact token, not serialized history, copied tokens or None. No published public operation supplies a token for the historical completed episode during fresh parent preparation.

Scenario: save a completed learned bank at sequence n, construct a fresh receiving ENV/BANK, prepare all children before installation. The bank cannot supply the required accepted argument. Resetting to obtain a token is neither a pure preparation nor a solution: it advances to n+1 and no longer matches saved n. Installing ENV first also violates complete-parent preparation. This is ordinary learned-state fresh-episode restart, not the separately open active simulator restoration feature (original plan T26 and baseline C10).

Required repair: specify an explicit completed historical restore path that retains exact saved cursor/cache/provider state without requiring or manufacturing a live accepted token, with a concrete parent correlation input/validation responsibility. Distinguish live same-episode restore from historical completed installation. Explain how begin_episode consumes the next genuine n+1 token once, how re-export works before that begin, and how all children prepare before any install. A fresh completed two-world permutation/save-load/next-begin acceptance case must remain required. Do not reduce PW06 to same-live-ENV recovery or rename ordinary fresh restart as optional downstream support.

## 2. High — imported historical completion must not mint live close authority

The proposed ordinary receipt kinds now authenticate the imported bank payload to real ENV close. ENV's completion content is opaque correlation data (PW05-ACTUAL-ENV-FIXTURE-API), not a validator of historical LaneOutcome agent_idx/tensor evidence. Required repair: separate preserved historical completion/dedup evidence from live closing capabilities. Specify precisely when a restored committed retry token exists and what operation can consume it. If a new historical retry result is needed, it must not validate as the ordinary live close kinds. ## 3. High — one accepted binding cannot represent both current permutation and historical outcomes

The exact envelope has accepted_identity only once, and completion's exact fields omit its own original binding. The proposal validates historical agent_idx/participant/disposition order against saved accepted_identity, while rebinding the live bank to receiving destination order. BANK begin/reward/step use its live _accepted order; BANK completion stores full source-indexed canonical outcomes and caches. Current world-native contract explicitly preserves historical accepted_bindings separately from destination_lane_binding for this reason.

Scenario: completed source order (A,B), with outcomes agent_idx (0,1), is restored into (B,A). If the next checkpoint exports receiving accepted_identity=(B,A), unchanged A outcome agent_idx=0 is inconsistent on the second restore. If it exports (A,B), the single field no longer describes the receiving current step/accepted binding; later active exports cannot safely use the same interpretation. Rewriting agent_idx/fingerprint changes historical payload evidence and is not permissible.

Required repair: give historical completion its own immutable saved binding provenance, distinct from current dispatch/accepted binding, or an equally explicit lossless schema that represents both. State how subsequent checkpoints retain it and how begin clears/replaces episode-local records. Validate each historical outcome/cache/canonical pair against its original binding, never a remapped row. Add completed A,B → B,A → checkpoint → A,B restore, comparing full historical bytes and next genuine reset/learning behavior. Combine this with defect 2's refusal of new closure authority; do not fix it by refusing required private permutation.
