## Exact scope and public entry

Add required-keyword `CuriosityBank.prepare_private_initialization(*, state, initialization, parent_restore, validate_parent_restore) -> PreparedCuriosityRestore`. `initialization` is exactly `fresh_private` or `clone_learned_archive_pending`; every argument is required. `state` is a complete current shared BANK checkpoint. The receiver must be a healthy, untouched INITIAL private BANK with no accepted episode, history, completion transaction, prior initialization origin or active reservation. The existing `install_restore(prepared=...)` consumes its destination/revision-bound handle and publishes once. No ordinary `prepare_restore` mismatch calls this method, guesses a policy or changes scope.

The component conversion boundary is a source INITIAL or committed COMPLETED checkpoint. A COMPLETED source may retain a nonempty mixed/unassigned native training tail: that is the required pending archive case. INITIAL uses the existing explicit None/None parent pair or real INITIAL preparation/callback; COMPLETED requires the actual retained ENV prepared_restore and genuine parent authority callback, exactly as current restore. A source live_episode or prepared completion refuses explicitly. Ordinary current live BANK restore remains supported, unchanged in authority semantics. Active captured REPLAY remains active and required; it is not synonymous with switching the simulator's active episode to a different curiosity owner. No new live scope-switch/participation settlement feature is claimed. If the accepted scope includes that feature, a parent participation/closing decision is required before implementation, rather than silently attributing earlier shared work to private owners.

Source and destination must have exact same world membership, seed, observation/action dimensions, device and float32 profile. Receiving order may differ at a completed boundary. Source is explicit shared/vector_tick and destination explicit per_world/world_eligible_admission. Both current policies reconstruct through actual ResolvedExplorationPolicy. Compare active behavior explicitly: same family; all epsilon values; selected provider parameters and source selection where active; reward/predictor phases/input kind; selected scale/base/modifiers; all active adaptive parameters; service_mode, max_updates_per_tick, max_pending_rows and overflow_policy for trainable families. Scope/seed-policy/clock/ownership guarantee and their authoring metadata are the only execution differences allowed. Inactive presets retain their own provenance and are not used as execution identity. Never derive target capacity from private cardinality silently: caller supplies a genuinely resolved target policy retaining selected source capacity. Keep exact source and target policy objects/identities in origin; do not forge a private policy by editing shared authoring tags. RP can remain readonly; compatibility checks live in CP.

## Native composite ledger: no invented per-world past

Let validated source native counters be A admitted, C consumed, D dropped, U successful optimizer updates, M mandatory updates (where emitted), Q ordered pending rows, and B training batch size. Current producer invariants are A=C+D+len(Q), C=U*B; ICM Adam step=U; RND Adam step=U+optimizer_step_offset. Adaptive uses its nested RND ledger. RND's offset can be signed; retain its validated value exactly.

For clone, derive inherited settled baseline `A0=C+D`, `C0=C`, `D0=D`, `U0=U`, `M0=M` where available. The live target native ledger begins with admitted=A0, consumed=C0, dropped=D0, updates=U0, mandatory=M0, pending=[], service_clock_unit=world_eligible_admission, service_position=A0, ordinary_updates_at_position=0. RND step_counter=0. Its original step_counter, budget, clock and all original counters remain unchanged in the archived source. Keep original RND optimizer_step_offset. Keep ICM last_loss and all Adam steps/moments unchanged. RND/adaptive retained learning/RMS, ICM learning, Count counts/LRU/evictions and adaptive history/weight are copied, not recomputed. Diagnostic epsilon is retained for clone and initialized from target policy for fresh; neither operation mutates the separate global selector.

The change A -> A0 excludes exactly the rows moved into the inactive archive. It does not label those rows dropped, consumed, world-owned, or trained. The complete original ledger remains intact in origin. Native counters explicitly represent inherited settled template work plus future local work; they are NOT exposed as counters of work performed by this world.

Let live native counters be An,Cn,Dn,Un,Mn and active private tail Qn. BANK future-world-local counters are a=An-A0, c=Cn-C0, d=Dn-D0, u=Un-U0, m=Mn-M0. Every difference must be an exact nonnegative integer. Require a=c+d+len(Qn), c=u*B, m<=u where present. Initially all differences and tail length are zero. BANK cumulative_service_position is a and starts0. Before a new eligible row BANK calls the native provider with position=A0+a+1, then emits its public WorldServiceReceipt clock at position=a+1. Per-call admission/update/drop deltas remain the actual provider receipt, unchanged. Neither an inherited baseline nor a vector tick grants a service opportunity. Retry, inactive rows and spectator work grant none. Provider conservation, ICM Adam step=Un and RND Adam step=Un+offset remain the actual strict validators' equations.

The BANK snapshot origin explicitly names `native_counter_basis='inherited_settled_plus_future_local'`. Add independently owned diagnostic `future_service_counters` to snapshot_world for trainable families, calculated from validated native values and baselines, with fields admitted_rows/consumed_rows/dropped_rows/optimizer_updates/mandatory_service_updates/pending_rows. RND/adaptive do not emit a cumulative mandatory counter in native state: do not invent one; represent that field as None and retain actual per-call mandatory receipts. None/Count have no predictor ledger: baseline=None, future_service_counters=None, BANK genuine eligible positions still start0 and advance normally. Count's inherited eviction/count data are learned state, not private admission history.

Fresh uses actual factory-created private native state, baseline zero for trainable counters, empty local tails and the producer's genuine initialized models/RMS/Count/history. It inherits no learned values. Both policies preserve a complete owned source archive as provenance, including pending and original gradients, so fresh does not erase the supplied source. Neither initialization touches source live objects or makes a new source export call.

No ICM source change is proposed. A zeroed native update ledger plus inherited Adam would require a new ICM offset schema; it is unnecessary with this explicit baseline. If later review establishes a concrete reason it is necessary, replace obsolete format directly with all current callers/tests updated, per root's explicit zero-compat ruling; do not add a v2 fallback. The native schemas in this proposal remain rnd-state-v2, icm-state-v2, adaptive-intrinsic-state-v2, count-state-v1 and actual EPS three-field payload.
