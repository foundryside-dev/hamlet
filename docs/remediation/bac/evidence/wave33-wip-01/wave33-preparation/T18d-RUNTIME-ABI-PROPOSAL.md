## Chosen current envelope and transactional custody

Proposed exact top-level current transport fields: `schema`, `policy`, `bank`, `selector`, `cadence`. Schema is `exploration-runtime-state-v1`. `policy` is the complete current policy.to_dict() transport and must reconstruct and roundtrip exactly, equal the receiving complete policy; BANK's nested policy must agree. `bank` is the unmodified complete current curiosity-bank-state-v2 transport. `selector` has exactly epsilon,epsilon_decay,epsilon_min. No old format or pre-scope policy path is accepted. Avoid an independent duplicated provider_kind field: selected `policy.strategy` and validated BANK policy already provide the provider tag.

`cadence` exact fields: `schema`, `last_committed`; schema is `parent-global-epsilon-cadence-v1`. `last_committed` is None or the owned record `batch_episode,completion_content,epsilon_before,epsilon_after`. Content is the parent's full canonical outcome tuple, not BANK's participation subset or fingerprint-only evidence. With no parent commit, selector epsilon equals policy.epsilon_start regardless of BANK local phase. Before/after validates the exact last EPS recurrence and selector equals last after; all scalar bounds/types validate. The record survives any BANK begin/completion and is not forced equal to BANK completion. The parent's validate_parent_cadence authenticates domain/correlation rather than fabricated local coupling. This witness prevents duplicate latest parent-boundary decay and correlates the last transition; it is not a cryptographic attestation of all historic callbacks or a serialized committed-batch counter. No exponent-based reconstruction replaces EPS's repeated floating recurrence. No capability serializes.

Selector validation is narrowly specific to this separate global object: exact keys, finite non-bool numeric values, policy.epsilon_end <= epsilon <= policy.epsilon_start, epsilon_decay exactly policy.epsilon_decay and epsilon_min exactly policy.epsilon_end. Correlate its value to the retained last-transition witness above; an arbitrary policy-bounded scalar alone is insufficient. Native serialization generally does not prove a complete historical execution trace, and this envelope makes no such stronger claim. Do not duplicate BANK native validation, prepare native providers a second time, or deserialize native data in RP. BANK's own strict validators already cover native EPS/provider models/Adam/gradients/tails/RNG/origin/cache.

Proposed runtime restore methods:

- checkpoint_state() -> owned current mapping
- prepare_restore(*, state, mode, accepted, parent_restore, validate_parent_restore) -> opaque PreparedExplorationRestore
- install_restore(*, prepared) -> None

Prepare requires every keyword, owns its input, validates the complete outer policy/selector/cadence off-side, then calls the actual retained BANK's prepare_restore with its complete nested state and unchanged authority arguments. It keeps the actual opaque BANK handle; callers cannot reconstruct or edit publication data. Precompute selector object/scalars, cadence data and final runtime publication references before retaining the runtime handle. Allocate/report any additional owned selector/cadence data coherently with existing explicit allocation reporting; do not represent BANK estimates as total-process bounds.

A runtime RLock serializes threads; an enforced operation-entry guard additionally refuses same-thread reentry. On entry under the lock, every public runtime operation except the harmless scalar epsilon getter checks a private operation-active flag and raises before input ownership/allocation, callbacks, BANK calls, revision/handle changes or action RNG draws if already active. Otherwise it sets the flag for the entire operation and clears it in a finally block. Coverage includes every BANK-forwarding method listed above, epsilon_tensor, select_actions, commit_batch_episode, checkpoint_state, prepare_restore, prepare_private_initialization and install_restore. Internal composition uses private unguarded helpers under the already-held operation guard (for example selection tensor construction); it must not bypass the guard by dispatching through another public entry. The epsilon getter alone may read the current scalar under the lock without callbacks, allocation, RNG, child observation or revision change. This is an operation-reentry safeguard, not a new episode/cadence capability gate.

The guard stays active across all explicit owner callbacks and the whole opaque BANK.install_restore call, including BANK's retained accepted-token validator. A callback attempting runtime-only cadence mutation, selection/action RNG draws or a freshness-changing snapshot therefore refuses before work even though BANK.mutation_revision would otherwise remain unchanged. RLock and revision checks alone are insufficient. Runtime handle custody remains destination identity + actual retained handle identity + revision + single-use status; publication data is retained privately. Reject copied/foreign/stale/consumed handles. Any successful child operation or observation that affects BANK freshness also invalidates runtime restore handles; never export/snapshot BANK between its preparation and installation merely to re-check it. Runtime checkpoint export itself is an observation with the existing BANK revision effects and must invalidate pending runtime handles. Exact outcome of failed preflight versus observed preparation follows existing BANK semantics rather than inventing revision rollback.

Install authenticates runtime handle/freshness under the lock and active operation guard, then lets actual BANK.install_restore perform its final custody/live checks. Its internal accepted-token validator executes while that same guard remains active. If the validator propagates a refused reentrant operation, BANK has not published and selector/cadence remain untouched; the finally block clears the guard and a healthy retry is allowed. If the validator catches the refusal and returns normally without other mutation, BANK's existing final checks can pass and coherent installation proceeds. After successful BANK installation, publish preallocated selector/cadence references using no loader, validation, allocation or callback; clear the operation guard by simple assignment on exit. Do not add a fallible post-BANK freshness check, rollback or corrective publication. A no-fail scalar/reference publication tail is essential: two independent mutating load_state calls do not provide all-or-nothing restore. Runtime callers must not bypass custody through retained BANK/provider references. This is component atomicity under exclusive runtime custody, not a claim that ENV/Q/replay/other parent children publish atomically. No global RNG state is silently added to this envelope; exact stochastic action continuation requires the existing parent RNG contract.
