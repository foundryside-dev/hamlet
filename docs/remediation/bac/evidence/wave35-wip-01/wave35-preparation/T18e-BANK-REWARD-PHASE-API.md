## Confirmed current public API

`townlet.exploration.scoped_curiosity.CuriosityReward(raw: torch.Tensor, scales: torch.Tensor, eligible: torch.Tensor, event_ids: tuple[CuriosityEventId, ...], scope: str)` accepts positional or keyword arguments, all required (BANK76–93). It detach().clone()s each input tensor. Its exact tensor properties are `.raw`, `.scales`, `.eligible`; every access returns a fresh clone. Public metadata are `.event_ids`, `.scope`. There is no `.reward`, `.scale`, weighted/contribution accessor, tuple-unpack contract, or constructor dtype/device/shape validation. The class itself is not frozen; supported custody is tensor copying, not arbitrary-attribute tamper resistance. Constructor tensor dtypes/devices/shapes are preserved, never cast or moved.

BANK-produced results have raw/scales [N] on BANK.device in its declared float32 profile, eligible bool [N], ordered original all-row event_ids tuple and scope `shared`/`per_world` (BANK537–597). BANK construction requires default dtype float32 and CPU or explicitly indexed CUDA (268–274); reward zeros use that declared default, not an independently explicit dtype argument. Inputs/accessor mutations cannot change bank-owned cached rewards. First reward returns a deepcopy; current repeated reward returns a deepcopy; private local replay constructs another owned result. `.raw` means unscaled provider output: RND/adaptive is already RMS-normalized, ICM is raw forward error. It is not necessarily pre-normalization MSE.

## Confirmed event equality, retry and phase order

Stamp preparation requires authenticated current accepted token, exactly accepted.world_ids row order, dense bool [N] active_on_entry on BANK.device, exact int vector_tick>=0 and undisposed episode (BANK393–438). Equal pending tick+active retries return its stamp. Otherwise previous pending must be serviced and new tick strictly greater. Event IDs carry epoch/world/accepted episode/eligible sequence; inactive rows retain eligible cursor. According to the clock capsule stamp itself has no vector_tick field, no content hash and no authority; its sequence/eligibility properties clone owned int64/int64/bool [N] tensors. BANK retains tick in pending metadata.

BANK content equality is actual typed tensor/scalar equality, **not** fingerprint-only equality: `_same` checks type, tensor shape/dtype/device/torch.equal, recursively (110–119). `_context` materializes `predecessor, successor, actions, active, vector_tick` (478–484); local cache clones each row and retains original tick (519–526). Shared current pending context must equal this full content. Private reward/service caches retain full local content; expired-local replay must match latest eligible own reward event and provenance, and each phase replay matches its own retained content (440–506). Inactive rows are excluded from private local equality but still undergo whole-batch geometry/finiteness/action validation. Shared equality covers the complete ordered content.

Reward must precede service (BANK617). Private service explicitly requires reward-cache replay equality, or all inactive (619). Shared service uses the same pending-context equality in `_context`. Thus reward and service content are crosschecked in **both scopes**, although implemented through different storage paths. A stamp cannot legally use successor A for reward and successor B for service when they differ on an eligible row. Changing context before first service refuses, not a supported second-phase update. Even a repeated pending reward is content-checked before cached return. Private own latest-event replay can survive another world's later work at the original tick; shared replay requires current reservation. Equal reward replay must retain update_stats mode. Cached replay calls no provider and advances no cursor/RMS/optimizer/RNG/revision.

Completion fingerprints are a separate domain: `prepare_completion(*, accepted, boundary_key, completion_content, outcomes, participated_world_ids)` requires exact full canonical tuple of `(freeze_lane_outcome(event).payload.hex(), fingerprint)` for actual ordered participating LaneOutcome records (BANK693–748), not digest-only evidence. Runtime parent-global `commit_batch_episode(*, batch_episode, outcomes)` separately authenticates and owns full canonical outcome payload pairs (RP1006–1058); it is not BANK world completion, vector tick or ENV acceptance.

## Confirmed provider input/order/ownership

RND/adaptive/Count/none reward consume eligible context.successor; ICM consumes actual predecessor/actions/successor via `_row_context` (BANK560–566). RND reward validates observations, computes MSE, optionally updates RMS **before** division by the updated RMS standard deviation; empty reward does not update it (RND268–306). AI forwards unweighted normalized novelty (AI177–196). ICM reward is `0.5 * mean((forward(encoder(s),one_hot(a))-encoder(s').detach())**2)` on active rows under no_grad; update_stats is validated but changes no RMS (ICM169–182).

Service after reward admits RND/adaptive eligible **predecessor**, not reward successor; ICM admits complete predecessor/action/successor (BANK646–660). Count admission occurs during reward per public capsule, never a second predictor admission in service. RND queues detached destination-device clones (RND465–467), services FIFO with drain-before-append, selected ordinary budgets/overflow and actual Adam; service does not update RMS (RND35–40,429–523). ICM queues detached CPU clones plus integer action, performs pre-append overflow then append/drain (ICM38–47,254–276); training uses actual encoder/inverse/forward, weighted inverse cross entropy plus forward MSE with detached successor target (190–215). AI delegates RND service (153–157); adaptive history/scale changes only in authenticated completion, preserving minimum-ten/strict-threshold variance logic (AI206–250, BANK750–842).

Unexpected failures after provider observation/publication quarantine BANK (203–217,353–361); there is no rollback promise for already updated Count/RMS/Adam. Expected input/content refusals occur before provider effects. A parent must not retry a partially executed real step as though stamp caching made physics/reward composition atomic. Parent retry/return custody is a required external seam.

## Confirmed vector-clock distinction

BANK `begin_episode` resets pending reservation and episode-local eligible sequence/cache, retains native backend and cumulative service positions (364–390). Therefore BANK reservation vector_tick history is **per accepted episode**, with strict advance between distinct reservations inside it; it has no cross-episode monotonic check. `IntrinsicTransitionContext` checks only scalar nonnegativity.

Private trainable service uses `world_eligible_admission` at own cumulative_service_position+1, independent of context.vector_tick; initialized clone service adds inherited native admitted baseline while its public receipt remains future-local (BANK640–648). Native RND/ICM require exact previous position+actual eligible admissions, including drops (RND393–426, ICM225–252). Episode reset cannot reset this private native clock.

Shared RND/adaptive service uses context.vector_tick and retains native _service_position across BANK episodes: regression refuses, equal position shares existing ordinary budget, greater resets budget (RND388–412,429–448; AI156–157). Shared ICM similarly requires explicit clock=context.vector_tick and no regression (ICM225–239). Consequently shared trainable continuation needs a nonregressing clock across the native provider lifetime/resume; using a strictly increasing value for each genuine vector service opportunity avoids accidental equal-budget reuse across episodes. Native API permits equal ticks for grouped calls; BANK permits equal current preparation only as retry. None/count do not have this native clock, but that does not authorize reducing supported shared trainable behavior.

Supplied external owner fact: ENV.global_tick resets each episode, whereas fixture ticks were monotonic. This is not enough to certify current parent ticks safe; a reset lower than retained shared position refuses, and an equal reset may silently reuse pacing budget. No tick may be derived from fabricated accepted IDs or hidden defaults. Actual caller must explicitly own and restore the service clock, or a reviewed additive clock seam must distinguish episode tick from service cadence.

## Supplied ENV facts and the representational gap

These are supplied as source-verified by the separate bounded ENV owner, **not verified by reopening ENV/RWC here**: retirement +1 enters extrinsic/total after RWC; inactive outputs are zero; retirement dones and time_of_day finalize after RWC. RWC currently encodes postphysics observation before those finalizations; ENV later returns another encoded successor. These encodings may differ even without retirement because time changes.

There are two required meanings: (1) preserve the accepted observation-provider reward phase, and (2) preserve actual returned transition `(s,a,s')` for ICM and replay. Current context has one successor and current cross-phase equality enforces one value. Using early successor for both loses true returned ICM/replay input; using late successor for both changes RND/adaptive/Count reward input. Passing two differing contexts under one stamp refuses. Calling reward twice with different stamps or bypassing BANK duplicates or reassigns RMS/Count/admission effects and does not preserve the event contract. Separate replay storage alone can preserve replay while current ICM still consumes the wrong successor. Therefore current APIs cannot faithfully satisfy both requirements across all selected families when early and returned successors differ.
