## Selected finite coordination model

Add one concrete process ambient-RNG domain custodian, shared by participating parents and WS activation. It protects the existing shared ambient stream, not a new world-derived/shared-private seed stream. It is a real admission protocol with registered owner identities, active lease identity, operation mode, revision and poison state. It is not a `quiescent=True` argument, a per-parent lock, an inferred quiet period or a generic transaction framework.

Proposed implementation location: `townlet/exploration/rng_custody.py`, a narrowly scoped owner module; this name is a proposed new producer, not a file inspected here. It owns only ambient serialization/candidate continuation and participant admission. Parent/world owners retain boundary/role authority; BANK retains learning/reset authority. It must use the same underlying exclusion domain as WS `_rng_guard`, replacing separate uncoordinated lock entry, with no independent parallel ambient lock that private activation can bypass.

All registered uses of a process's ambient CPU Torch/Python/legacy NumPy streams belong to this one domain. CUDA devices are explicit initialized sorted inventory; synchronize used devices before capture/install and before releasing a lease that launched random work. CPU-only operations must not query or initialize CUDA. Register generator-local sources only through actual owner-supplied typed snapshot/prepare/publish adapters with exact names and bit-generator kinds. A local replay generator already carried by replay is owned/published once by replay, not redundantly restored in the ambient record.

Enrollment is done by actual runtime bootstrap before any participating construction or operation. A participant registration binds an actual owner identity to declared ambient devices and permitted entrypoints; registering/unregistering/device inventory changes requires exclusive idle custody and increments membership generation. Normal operation returns an identity-bound lease, never a portable authority. Another parent/thread attempting entry blocks until the active operation exits. Same-thread callbacks must present the exact active operation lineage for permitted nested BANK/private work; unrelated parent reentry refuses before any draw. Do not hold a lease across await/yield or return it for arbitrary caller retention. The runner routes a requested reset to its actual healthy boundary, then performs the synchronous preparation/publication while owning the lease.

The lock order is domain admission, parent lifecycle, BANK, WS owner. WS must not first acquire a distinct guard and then wait for a domain owned by a thread waiting for BANK. Every direct BANK entry that may observe/construct a backend enters domain admission before its `_serialized` lock, including constructor, snapshot, checkpoint, restore, initialization and completion; nested entry validates the current lease lineage. Public private activation without a parent also enters the same domain. Thus enrolled shared parent B cannot draw while private A globals are installed, and private A cannot swap globals during shared B's protected work. Same-owner component nesting retains existing A→B→A behavior. No model is consolidated, no per-world mutable state is shared, and no sampling algorithm is changed.

Shared ordinary operations continue using the ambient stream in actual execution order. Exiting an ordinary operation conservatively increments domain revision even if no draw was observed; an exception may have consumed random values and also invalidates pending preparations. Private activation restores ambient continuation and advances only its own streams on success; domain coordination still prevents concurrency and preserves poison semantics. Merely comparing equal RNG bytes cannot authorize publication after an intervening operation.

**Hard boundary:** no Python lock can exclude arbitrary code that calls torch/random/NumPy directly without enrollment. These bodies contain no mechanism that can intercept every process RNG user. Qualification requires the actual runtime bootstrap/serving/worker owner to enumerate and enroll every participating ambient user before execution. If the requirement includes arbitrary external uncooperative code in the same process, the exact current ambient-swap implementation cannot provide it. The producer must then obtain an explicit ruling authorizing an isolated execution boundary or implement explicit-generator execution in every actual RNG consumer while preserving capabilities. Neither a silently narrowed guarantee nor a new process/seed semantics is approved by this note. Enrolling all application users is the selected additive solution, not permission to forbid existing supported callers. Those callers must be migrated and verified.

## Serialization, shared restore and preserved semantics

The required base is current learned-state fresh-episode restart, with exact private named-stream restoration where already owned. Ordinary qualified shared checkpoint/native-model recovery does not install an old process ambient RNG snapshot. Under the operation gate, capture the current ambient continuation before disposable reconstruction/validation, discard those work draws and retain that current continuation through publication. This neither rewinds peer users nor requires their checkpoints. It preserves all already-qualified child state and replay-local RNG transport through their actual owners; no blanket deletion of child RNG state is authorized. Supported live BANK restore retains its existing authority/phase contract and does not acquire a whole-simulator continuation promise.

Shared RESET remains different and mandatory: hold real domain exclusion continuously from current capture through fresh construction, candidate capture, final authentication and publication/refusal; retain actual fresh-construction consumption on success and restore entry continuation on normal refusal. No peer can run in the gap, and no earlier peer continuation is installed. The current/candidate ambient snapshot is in-process operation data, not a newly required checkpoint field. Private reset forks current named streams and retains construction consumption; private exact restore retains the saved named continuation and discards disposable reconstruction consumption. Never reseed established private owners with create or derive seeds from epochs/rosters/clocks. Capture/restore failure still poisons custody and fails closed.

**Optional additive P3 extension, outside R0/B1/base closure:** exact process-wide stochastic cohort checkpoint/resume. If separately undertaken, one outer owner would serialize an ambient-rng-domain-v1 record plus every state/scheduling dependency needed for its chosen guarantee, with explicit cohort authority and qualified all-child publication. A single-parent ambient rewind cannot supply exact multi-parent continuation. That observation is a condition on the optional stronger promise, not a refusal condition on ordinary shared restore. The base adds no cohort schema/manifest, no all-parent rewind and no requirement to capture peer checkpoints; it must not reject an otherwise qualified single-parent/shared restore merely because other parents exist. Do not infer that the proposed cohort record alone would complete K01's broader simulator/replay-order inventory.

Preserve the approved lifetime invariants without revision: native A=C+D+P, C=batch*U, exact ordered pending work, clock and spent ordinary budget; new O=retained U, RND/adaptive S=(U-O)+signed delta and ICM S=U-O. This amendment controls all earlier “every entrypoint”/manual-interception wording: every supported route needs classification and preserved behavior; only actual ambient-consuming regions require the global RNG gate. Same-object mutation requires its real owner serialization independently of RNG consumption. No speculative optimizer hooks, instance method wrappers, deepcopy rebinding, registration or scheduler machinery is selected for R0.

The accepted reset design makes native handles destination-bound/single-use and explicitly delegates revision freshness, quiescence and boundary publication to BANK/parent. Its signed-delta amendment preserves RND/adaptive manual optimizer steps. Neither that design nor K01 establishes a new promise of concurrent mutation-safe standalone torch optimizers. Therefore an independently owned RNG-free manual step can run while another owner's private stream is installed, provided it neither touches the reset candidate/live owner nor invokes random callbacks. Its model changes cannot corrupt an unrelated RNG continuation. Conversely, RNG-free does not make a concurrent step on the very model being copied/reset safe.

### Smallest fact request and decision test

1. **Native/library algorithm capsule:** the existing N1 owner identifies actual Adam configuration and reachable selected execution modes (CPU/CUDA, foreach/fused/capturable/differentiable as actually enabled), closure use, actual optimizer/module hooks and any indirect callback execution. An appropriately bounded library/source owner supplies the pinned installed implementation's random-consumption facts for those paths, including exceptional paths. No Torch body is added here, and N1's “no project sampler/dropout” observation is not a claim about unread Torch internals. Do not survey unselected optimizer families as a prerequisite to this one classification.
2. **Finite actual witness:** authorized executor surrounds a real supported manual step on real preexisting gradients with owned before/after Torch CPU, Python, legacy NumPy and explicit initialized CUDA RNG states. Synchronize applicable devices; also compare next draws against a restored reference. Exercise the actual selected execution modes, empty/nonempty Adam state, repeated real update, and an applicable refusal/exception path. Build gradients/model before this narrow measurement so it answers the step question; separately cover the complete supported manual operation including forward/backward/closure/hooks. Preserve actual Adam type/Parameter pairing and positive/negative signed-displacement scenarios. This is evidence for tested modes, not proof for all Torch implementations or arbitrary callbacks. CUDA unavailable means CUDA remains unqualified, not inferred from CPU.
3. **Actual owner/access capsule:** BANK/private-owner producer confirms managed backend/optimizer references do not escape through supported APIs, identifies all live model mutations and their owner revision/serialization, and demonstrates reset preparation/publication holds that owner exclusion. The actual Q/parent producer separately supplies its ownership facts; do not infer Q exposure, dropout or scheduler behavior from N1. Standalone native usage retains the existing caller-owned same-object quiescence obligation across preparation→install, with no claim that a bare native handle detects intervening manual mutation.

If (1)+(2) establish the selected bare step consumes no ambient RNG, **do not add a global admission hook to it**. Keep ordinary manual calls and optimizer replacement unchanged. If a supported closure, forward, gradient-generation path, module/optimizer hook or selected algorithm consumes ambient randomness, gate that complete consuming region at its actual entrypoint, with required current-generation custody and caller migration where needed. A pure core Adam step does not exempt its stochastic closure. A single no-hook witness must not justify silently refusing previously supported hooks/closures; their actual project-supported forms must be inventoried, preserved and enrolled. Unknown consuming behavior remains unqualified until resolved, not permanently restricted or assumed safe.

For same-object concurrency, the minimal required BANK/parent implementation holds its existing/new real owner lifecycle exclusion from copying current state through reset publication and final revision checks; all owner mutation APIs participate. A released preparation must reject after an owner mutation even when RNG bytes stayed identical. A standalone caller that mutates its optimizer between native prepare and install has violated the native handle's explicitly delegated quiescence contract; do not advertise automatic detection that does not exist. If a supported managed path exports a mutable optimizer reference and also promises concurrent reset, that is a concrete outer-owner gap requiring a real owner mutation protocol before qualification. A global RNG lock alone cannot repair a caller bypassing that protocol. No claim is made that such exposure exists in unread Q/outer modules.

### Minimal R0 delivery and discriminating acceptance

R0 delivers shared ambient exclusion for proven consumers and all private swaps; held reset capture→fresh construction→candidate capture→publication; pure current private fork; failure/poison and domain-staleness checks. BANK/parent retain separate same-owner mutation freshness. This does not require automatic interception of a qualified RNG-free standalone Adam step or exact cohort resume. Native constructor draws and shared selection still need actual admission; candidate reconstruction/validation is conservatively within custody until its full called behavior is qualified.

Required finite witnesses distinguish the obligations: (a) an actual RNG-consuming shared selector/constructor waits during private swapping; (b) a separately owned qualified RNG-free manual Adam step leaves all ambient continuations unchanged and preserves its own real model/delta change, without a global hook; (c) a supported stochastic forward/closure cannot bypass admission merely because the subsequent Adam core is RNG-free; (d) managed same-owner service/manual mutation cannot race reset copy/publication, and an allowed intervening mutation makes a released candidate stale; (e) standalone direct native reset/manual use satisfies documented same-owner quiescence with exact Adam and signed delta intact. Hooks/deepcopy/scheduler interception tests are needed only if an actual producer selects such an implementation for a demonstrated gap, not as default R0 machinery.

**Readiness:** finite R0 architecture remains feasible. Native manual-operation ambient classification needs the small selected-algorithm capsule plus actual witness; managed same-owner and Q/parent access facts remain separately owed. There is no source-backed reason yet to mandate bare-Adam interception, and no evidence here sufficient to declare unread Torch CPU/CUDA paths RNG-free. No capability degradation, code authority or user approval question follows.
