## Actual public dispatch

`harness.run_side(*, driver: Path, src: Path, params: RunParams, out: Path, repo_root: Path, pack_root: Path, actions: Path | None = None) -> SideFailure | None` (225–278) accepts an explicit driver and import/pack roots, **but no interpreter argument**. Both sides use the harness process's `sys.executable`, `-P`, driver file path, working directory `repo_root`, inherited environment with `PYTHONPATH` replaced by `str(src)`, captured stdout/stderr and no timeout. It transports `--pack`, `--pack-root`, `--level`, `--num-agents`, `--steps`, `--seed`, `--device`, `--out`, and optional `--actions PATH`. These are driver arguments, not harness CLI options. A nonzero return yields `SideFailure(kind="crashed", stderr=...)`; exit zero without an existing output yields `no_trace`; existence alone succeeds here, with decoding deferred.

`run_cell(*, repo_root: Path, old_src: Path, old_pack_root: Path, new_src: Path, cell: Cell, run_dir: Path, run_cuda: bool, scripted: bool) -> CellVerdict` (311–530) has per-side code roots and an explicit old pack root, but sets new pack root to `repo_root` (351). It sets `driver = new_src / "townlet" / "oracle" / "driver.py"` (345), passes that same path to old, matched-crash new, and normal new calls (372,423,467). It never chooses `old_src/.../driver.py`. `run_cell_safely` (533–562) has the same signature and forwards it; exceptions become cell-local HARNESS_ERROR, not a compatibility route. `run_side` can already be called directly with two different driver paths; matrix/cell dispatch cannot.

`main(argv: list[str] | None = None) -> int` (617–682) exposes only `--cuda`, repeatable `--cell PACK:LEVEL`, `--oracle-ref` (default ORACLE_TAG), and `--scripted`. ORACLE_TAG is `oracle-2026-08-17` (__init__.py11). No old/new interpreter, driver, source root, pack root, reuse-only or actions-file CLI option exists. It derives repo root from its own file, uses ensured worktree/src for old imports, repository/src for new imports, repository/oracle_fixtures for old packs and repository for new packs (635–669). Logical pack names include `configs/...`, so old resolution is `oracle_fixtures/configs/...`, not a different logical RunParams.pack.

`Cell` (matrix421–464) carries params and divergence declarations plus `scripted_actions: bool = False`; it has no driver/interpreter fields. `default_cells()` (467–591) constructs twenty CPU/CUDA cells, ten CPU: five curriculum levels, three differential packs and two profile packs, all N4/100 steps/seed42. **No constructed default cell sets `scripted_actions=True`**, despite historical prose in matrix487–493 and the field comment saying DIV-008 cells declare it. This is an implementation fact, not authorization to change matrix behavior.

## Creation, cache and cleanup limits

`ensure_worktree(repo_root: Path, tag: str) -> Path` (90–122) targets `.oracle/<tag>`. If `src/townlet` exists it resolves tag commit and HEAD via git and requires exact equality plus clean porcelain status. Otherwise it **automatically invokes `git worktree add --detach PATH TAG`**. It is not a read-only existence check, does not inspect the supplied registry, and does not remove/prune/repair missing registry entries. Refusal diagnostics suggest destructive remove/recreate remedies, but do not execute them. There is no cleanup/removal path on success or error, and no separate pinned-driver cache in these files.

main calls this helper unconditionally at636, **before cell selection**, CUDA skipping or output creation. Even a default/filtered invocation can create a worktree. It later creates `runs/differential/<timestamp>` with `exist_ok=False`, gathers git provenance, executes cells, writes traces/action files/report and leaves them in place (644–677). run_cell itself does not ensure/create an oracle worktree or create run_dir; it assumes caller-provided locations. `_PACK_DRIFT_IGNORE` excludes `.compiled` and `__pycache__` only from pack-byte comparisons (166–182); this is not cleanup or a cache-creation policy. Driver/compiler caching claims remain attributable to the readiness capsule, not these bodies.

Accordingly no existing helper or default harness execution is safe to treat as authorization to create the absent frozen environment.
