## Corrected reset accounting and fresh-learning semantics

Use per-native ledger C=(A,Cs,D,U,M), pending length P, service position p, ordinary budget b. A is admitted rows, Cs consumed rows, D dropped rows, U actual optimizer operations; M is mandatory operations only where the native producer actually exposes it. Do not invent cumulative M for RND/adaptive. The selected fixed batch size is q. Existing native conservation remains:

- A = Cs + D + P; Cs = q * U.
- For ICM, 0 <= M <= U. RND/adaptive overflow updates still contribute to U and the actual receipt deltas.
- Private p = A (with the producer's honest unstarted representation); shared p is last eligible service vector tick, not A.

At reset, preserve C, the exact ordered pending payload, p, and b. Native fresh learning receives an optimizer origin O := U and learning generation E+1; its new learning-operation count is u := U - O, initially0. Every real subsequent optimizer operation increments both U and u; native Adam validation uses u under the selected actual optimizer/module semantics. A factory-fresh Adam has no history even if lifetime U is nonzero. Do not prepopulate Adam moments/steps with lifetime U. O must be exact int, 0 <= O <= U, reset-owned and serialized; future native validation checks it against the new current schema and qualified learning state. Existing exact restore preserves O; it does not manufacture a reset.

This origin need not be a freely writable “offset bag.” Its sole purpose is separation of service lifetime from fresh optimizer lifetime. Source clone before any reset retains its real inherited optimizer state and native learning origin. On later reset it sets O to the actual current native U. All repeated resets replace the one current origin, advance the bounded reset generation/count once, and preserve service lifetime. Shared and each private owner have their own native origin; one grouped shared provider is counted once.

For existing shared-to-private initialization let H be its independently source-derived settled baseline, and F=C-H for available counters. Keep H unchanged during later reset. Then F.A = world.cumulative_service_position and F.A = F.Cs + F.D + P continue to hold without touching the queue. Private native p = world.cumulative_service_position + H.A; public clock stays the world cumulative position. Fresh_private has zero H. Clone inherited work is not re-executed or counted once per receiver in the parent predictor ledger. No source archive is traversed as active service.

For a parent whose predictor units start with receiving local work, expected totals are sum(F.A), sum(F.U), sum(F.D) for private, or the one shared current-run totals for shared. Map parent predictor_consumed_minibatches to actual U, including ordinary and mandatory updates, not service calls or Cs rows. If the parent legitimately began with nonzero receiving-run history, it must own and authenticate that fixed run baseline: parent metric = parent baseline + normalized current-run delta. That baseline is separate from native learning origin O and private inherited H. Never infer it from a difference merely to make a malformed payload pass.

Parent Q training_step_counter reset has a separate explicit equation: lifetime ledger.optimizer_updates = q_optimizer_epoch_origin + training_step_counter. Transfer sets the new Q origin to current lifetime Q updates and the new epoch counter to0; total_steps/vector_ticks, eligible history, predictor totals, completion totals and global EPS/cadence do not rewind. Its next real Q update increments lifetime and epoch counts once. Exact prepare/load/producer validation must share this equation. Q optimizer/scheduler are genuinely fresh while target becomes the transferred online values, as the transfer-facts capsule requires. This change must reach all current consumers, not retain a compatibility equality path.
