## Decision and scope

Add a genuine **pre-activation participation decision** to the accepted reset lifecycle. Call it retirement operationally, but do not represent it as lifespan completion. The ENV owns the activity change; its registered population owner owns the decision and corresponding population state. This is the finite missing producer for A active/B inactive on the first transition. Neither synthetic transition nor changed health/lifespan is a valid substitute.

All method names below prefixed PROPOSED are future interfaces, not claims about existing APIs. The operation belongs after the existing full-roster reservation and genuine reset, before ENV activation; it does not alter reservation membership, cursor increments, reset RNG or world binding. BANK/runtime begin_episode still supplies genuine activation. Existing activation remains necessary. A caller whose convenience begin() currently returns an already-active episode must move the requested initial activity decision inside begin(), before activation; it cannot call this operation after begin() and pretend the window remains open.

Input is an exact tuple of unique nonempty retired world IDs, a subset in accepted binding order, including () and the whole roster. The surviving set is its complement, not an independently supplied conflicting mask. This covers partial, no-retirement and all-retired cases without supporting arbitrary midrollout membership changes. Roster size remains >=1; zero selected rows for action selection is distinct from a zero-world ENV. One decision per accepted episode, including a sealed empty decision; later genuine resets can choose differently, but never reactivate a lane in the same accepted episode.

No requirement in the two provided caller capsules demands normal successful release for an entirely empty episode. Current ENV explicitly implements empty abandonment with two genuine owner proofs and quarantine. Preserve and test that supported behavior. If the accepted programme requires resumable *normal completion* of an all-empty episode, that is a specific still-open owner fact requiring coordinated BANK/POP/curriculum/ENV changes, not permission to silently omit it. This design does not pass empty tuples through exact_world_ids: it rejects emptiness by design. Both prepare_episode_close and validate_world_snapshot currently use it for participants. Do not globally relax roster validation to solve a participant-list issue.

## Proposed interface and custody

1. PROPOSED population.prepare_initial_participation(*, accepted, retired_world_ids) returns its actually issued `WorldOwnerReceipt(kind='initial_participation_intent')`. Exact payload: accepted, world_ids, retired_world_ids, population_revision. Population keeps its own pending record linking exact receipt identity to accepted token, actual reset completion, previous observation, empty accumulators and staged publication. Its revision is an exact nonnegative integer, not authority on its own. It refuses any prepared/executing step, existing outcome, completion/batch commit/restore work or partial reset. Equal preparation returns the same retained receipt; different requests refuse. No increment to clocks or RNG.
2. PROPOSED env.prepare_initial_participation(*, accepted, intent) -> WorldRecord(kind='prepared_initial_participation'). Authenticate exact current accepted token; `active-awaiting-activation` phase; genuine completed reset receipt; no activation/frozen close/retirement already committed; all step_counts zero, global_tick zero, pristine live dones. Validate intent with WorldReceiptIssuer.validate against the exact registered population role. Check exact payload keys, ordered actual binding, IDs, scalar revision. Retain the exact intent and accepted/reservation/reset/ENV-generation/ENV-revision plus owned before/candidate tensors in an ENV-side publication record. A WorldRecord can carry public owned readings, but the authoritative candidate lives in the issuing registry. Construction, copy, payload equality and arbitrary issuer ownership are insufficient. Equal prepare returns the same retained handle. Changed intent refuses, even with equivalent retirement IDs.
3. PROPOSED population.commit_initial_participation(*, prepared) orchestrates the guarded two-owner publication. It validates its retained matching intent and unchanged revision, stages its completed/activity state, observation and masks, and issues a genuine `initial_participation_ready` receipt with exact accepted, intent, prepared, population_revision fields. This receipt asserts an actual staged publication and the owner retains its custody. ENV commit authenticates it and the exact previously issued preparation. No generic callable-owner introspection is claimed: issuer custody and trusted role registration are the cooperative trust boundary.
4. PROPOSED env.commit_initial_participation(*, prepared, population_ready) -> WorldRecord(kind='initial_participation'). Commit checks phase, exact registry identity, accepted/reservation/reset identity, revision, original observation/dones/counts/meters and owned candidate shape. Ready receipt must belong to registered population and reference the precise intent/prepared handles. All validations, clones, result-record allocation and mask candidate computation precede publication. Publish only candidate dones, owned mask/readings, revision+1 and consumed marker. Preserve phase active-awaiting-activation. Prepared handle has one successful execution; another commit refuses. An already-published result is a data reading, not an executable retry permit.
5. Population immediately publishes its staged state with allocation-free reference assignments and clears pending decision custody. No callback, allocation, provider operation or validation follows ENV publication within this commit. Its method returns the ENV result only after both owners agree. Genuine population activation receipt is issued after this publication. Existing env.activate_episode then validates real population and BANK activation receipts and opens stepping.

The population orchestration guard excludes prepare/claim/step, activation, flush, commit, snapshot/install and recursive participation calls during the transaction. ENV must also reject activation/step/close/restore/reentrant participation while its participation operation is in progress. Existing bound ENV methods are not automatically thread-safe; enforce this finite transaction guard instead of claiming that existing phase checks provide a lock. If multi-thread access is supported by its owners, use their established lock order; exact POP lock API is an external owner fact.

Preparation refusal has no physical/model/clock/RNG writes and publishes no execution right. Failure before ENV publication leaves either the retained retryable preparation or invalidates it explicitly, but must not consume a successful decision. Unexpected failure after any physical-status publication quarantines the accepted episode and population operation, denying activation, step, snapshots and release. Do not repair by reverting tensors after callbacks or by silently retrying. The implementation should arrange the success suffix so there is no ordinary fallible work after ENV publish. Reset/restore generation change, physics revision, changed parent revision, another decision, mutated public live tensors or any competing pending operation makes old handles unusable. Exporting or reconstructing a handle never restores authority.

The genuine reservation's original full roster, sequence derivation and reset retry identity remain unchanged. Calling equal reset again returns its original observation receipt and cannot undo retirement or grant another decision. Cached reset observation is historical reset data, not current activity authority. Activation retries must not reconstruct/populate active masks from reset defaults.

## Publication, observation, geometry and caches

Use existing dones as the authoritative environmental inactive status and existing population completed/activity storage where it can represent completed-with-no-event. Do not create LaneOutcome or EpisodeCompletion for a retired zero-survival lane. Parent accumulator stays zero and completed_outcomes excludes it. Its final physical reading is the owned genuine reset observation/meters, but there is no final *event*. A separate permanent event type or transport version is unnecessary for this operation.

The reset observation is full finite float32[N,D] on actual ENV device and must match actual parent previous observation. D=env.observation_dim and A=env.action_dim; no hardcoded D3/A2. Observation serialization in this body uses positions, velocity, meters, items and effects, not dones, so retirement alone leaves observations byte-equal. Use the already-owned reset observation rather than re-evaluating VFS or inventing zero observations. Parent last-observation must remain the same physical reading. If an implementation changes observation dependencies later, it must stage a genuine pure reading under its owner; no deferred encoder call after publication.

Compute/validate the full bool[N,A] candidate mask before publish: unchanged genuine legal rows for remaining active lanes; all false for retired lanes. Add explicit inactive-row masking at the ENV mask publication boundary if the current builder does not already guarantee it; the builder body was deliberately unread, so its exact current done-row rule is not asserted. A surviving live row must have at least one legal action. Population presents only live rows to runtime.select_actions, which rejects all-false presented rows; empty Q[0,A]/observations[0,D]/mask[0,A] is valid and returns int64[0] without selector RNG. Dense ENV actions for inactive slots remain ordinary in-range filler values, never selected actions or participation authority.

Retirement does not execute reward calculation, prepare_step_stamp, reward, admit_and_service, any effect cancellation hook, item work, VFS expression/history/evaluation, action execution, selection, network, optimizer or replay. It preserves positions/meters/velocity/items/effects/layout/history/time/step_counts and all RNG exactly at its before snapshot. It need not clear physical delayed work: there has been no transition, and subsequent genuine stepping already masks effects by active_on_entry. Do not claim every inactive VFS expression remains unchanged during *other lanes' later steps*: current global tick/profile publication can still update full rows. The no-change guarantee here is for the retirement operation itself; private B provider state must remain unchanged across later A-only work as separately asserted by owning provider tests.

No fake reward components/handoff, zero service receipt, retirement bonus or adaptive survival observation is emitted. Existing reward cache is not refreshed or relabeled as this operation's reward. It may remain previous historical data, so callers must not treat it as fresh. ENV status/mask caches and population state agree before returning. Invalidate any dependent prepared observation/step/restore candidate through the owning revision and transaction guard, rather than hiding the changed status under an unchanged revision. Unrelated affordance layout cache is retained.

All seven ledger readings stay equal: vector_ticks, eligible_transitions, optimizer_updates, completed_batch_episodes, predictor_admitted_rows, predictor_consumed_minibatches, predictor_dropped_rows. Parent total_steps, ENV global_tick, per-lane counts, runtime global EPS and cadence stay equal. Later real A transitions still increment their normal units; later actual completed batch still advances global EPS once via actual parent commit. Retirement itself is not that commit.
