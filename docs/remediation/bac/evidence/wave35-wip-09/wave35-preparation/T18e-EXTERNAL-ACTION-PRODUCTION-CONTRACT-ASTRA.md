## Source-established decisions

1. **No existing inference factory can be claimed.** Whole POP2599 has `__init__`, `for_training` and `_initialize`; no `for_inference`. Both construction paths instantiate actual Q and target networks, optimizer/scheduler/loss and replay (331–415). Calling the general constructor is not a no-learning production mode.
2. **An actions kwarg alone cannot preserve oracle behavior.** `_execute_population_step` binds training, evaluates Q, captures Q-derived entropy and queries curriculum before selecting (roughly1640–1730); then changes depletion according to curriculum. After physics it admits real replay, services runtime, paces replay and invokes learning (1751–1860). The oracle does none of those policy/learning operations. A dummy Q, extreme train_frequency, never-ready replay or selector monkeypatch would conceal the mismatch.
3. **Policy completion is not mechanics capture completion.** POP refuses when every episode_completed is true; finalization requires Q-derived entropy and publishes learning LaneOutcome envelopes. The driver always requests exactly `steps` physics calls, even after all lanes are done. Supplying fake zero entropy or fake LaneOutcome records would weaken genuine policy invariants. Keep those POP invariants.
4. **Public prepare/claim is necessary but insufficient.** It binds exact accepted object, ordered worlds, predecessor, int64 full-N actions, entry mask and candidate parent tick. Claim changes stage to executing; only the parent execution path validates handoff, services, advances and completes progress. A consumer calling ENV after POP.prepare_vector_step would strand that custody.
5. **Runtime is reusable without selecting actions.** Actual runtime exposes begin_episode, prepare_step_stamp, reward, admit_and_service, quarantine_episode and distinct completion/restore operations. select_actions is an independent EPS/Q path that explicitly may consume ambient RNG. Explicit selected `none` is real provider behavior; runtime creation is still genuine BANK/selector construction whose side effects must be qualified, not presumed RNG-neutral.

Consequently the smallest honest oracle route is a **genuine finite mechanics parent/session with explicitly absent learning components**, using current ENV/runtime/world authority. This may be implemented beside POP; do not turn it into a general execution framework or duplicate POP's learner. An existing unopened production controller may supply the lifecycle if its owner demonstrates the exact mechanics mode. Otherwise a small world-owner extension is required. It is not acceptable to relabel the limited ParentFixture controller as production.

- `session.start() -> WorldRecord` performs genuine bootstrap/install/reservation/reset/activation once, retains the issued accepted token and owned current observation, and returns the actual reset record. - `session.step_actions(*, actions: Tensor) -> MechanicsStepResult` is the sole public physics entry. Attempting unsupported learning/native/boundary operations must fail before mutation; their normal production APIs remain supported elsewhere.

Required explicit mode declaration: mechanics capture has external action authority, no learned selector execution, no Q/target/optimizer/scheduler/replay/curriculum execution, no learner completion sinks, and no intrinsic provider contribution. ## Exact action admission and execution

Admission requires a strided tensor with exact int64 dtype, exact shape `[N]`, selected ENV device, every value in `[0,A)`. Reject shape/dtype/device/range before prepare/claim/physics and without consuming RNG. Own a detached clone before invoking downstream callbacks so caller aliases cannot change the candidate. No state-mask admissibility filter is applied in this **mechanics** entry: an in-range unavailable action is an authored mechanical attempt, and actual ENV decides its physical consequence. Inactive rows retain their supplied action values too. Normal EPS/greedy/evaluation policies still require legal action masks and eligible-row constraints; none of their validation is weakened.

The parent captures its actual current accepted token, full ordered lane binding, current observation, actual `~env.dones` and next lifetime vector tick. It issues a real PreparedVectorStep and retains its private immutable candidate registry. Existing identity-only type may be reused; ownership comes from issuer registry membership, not its constructor. Preparing equal pending content is pure/idempotent; changed, foreign, copied, stale, consumed or executing handles refuse. Registry claim must authenticate exactly ENV's kwargs and candidate at the prephysics cut. It is forbidden to bind a no-op callback, accept an integer tick as authority, or obtain a handle from another population.

The single guarded sequence is:

1. Validate and own action input; capture genuine predecessor/activity/candidate. No selector, Q forward pass, curriculum decision or replay binding.
2. Prepare genuine parent handle, then `env.step(owned_actions, 1.0, vector_step=prepared)`. Explicit1.0 preserves the driver's existing default depletion semantics. All other configured ENV mechanics, reward modes, effects/items/terminals and reset behavior remain owned by actual ENV; do not alter them to ease the fixture.
3. Require genuine IntrinsicStepHandoff and correlate exact accepted token, stamp world order/tick/eligibility, predecessor/actions/entry mask and final successor against retained candidate and actual return. Retain the actual handoff objects. Canonical total/components are final ENV values, including retirement adjustment/inactive masking. No second reward query, normalization or recomposition.
4. Record that replay is **declared disabled**, not 'replay_admitted'. Invoke exactly one actual runtime.admit_and_service with the genuine context/stamp/token after canonical capture. Even none uses its real common service path; use actual receipts, never synthetic zero receipts. Shared all-inactive and private zero-event behavior belongs to BANK.
5. Precompute ledger replacement; publish vector tick and eligible transitions at the post-service cut. Count actual receipt admitted/optimizer/dropped amounts in their separate predictor units. None should produce no predictor optimizer work; assert actual receipts. Q optimizer and completed_batch_episodes remain zero because neither operation occurred. No pace/sample/learn/EPS decay.
6. Publish owned current observation and terminal result; consume pending handle, mark progress completed. Do not require/construct policy entropy or invoke POP finalization. A subsequent requested all-inactive step remains a real guarded ENV call, canonical reward/handoff/service event and vector-clock increment, with zero eligible transitions; it is not simulated by repeating the last frame.

A material implementation may factor a genuinely shared transition validator into its owning module if it fits the frozen slice. It may not copy whole POP source or bypass its training requirements by routing learning callers through mechanics mode.
