## Confirmed existing contracts and guards

- BANK constructs its receipt issuer for the actual `self`, checks `issuer.owner is self`, and holds actual accepted-token authentication (scoped_curiosity.py:245, 350, 364). Restore installs a new runtime dictionary into that same object (1234, 1271); replacing internal owned providers is distinct from replacing BANK.
- `prepare_private_initialization` (1066) requires a healthy, untouched INITIAL per-world BANK: no activation, origin, pending work, nonzero cursor, or cache. `conversion_source` (curiosity_checkpoint.py:305) accepts only ordinary shared INITIAL/COMPLETED source, authored shared-to-private scope, matching selected behavior, membership, dimensions, seed, device, and current schema. COMPLETED needs actual parent preparation and correlation, not merely equal portable cursor values.
- Its `fresh_private` creates actual private factory state and zero local work; `clone_learned_archive_pending` clones source native learning/gradients, clears its pending queue in the explicitly archived shared source, and retains a source-derived settled baseline. Both retain the shared source checkpoint as origin evidence and advance curiosity epoch once. Neither is a general reset of an established same owner. Global EPS/cadence are outside this operation: do not infer that fresh target native epsilon fields copy source values. Clone transports source native epsilon; fresh uses factory state.
- `prepare_restore` (1160) restores an exact current same-policy state. Live mode requires the actual accepted token and exact accepted values/order; settled mode correlates actual parent preparation twice. It is useful for restoring a genuine prepared reset state once such a state exists, but does not manufacture lawful fresh learning plus retained history.
- `preflight` (curiosity_checkpoint.py:169) requires epoch zero for ordinary origin; nonzero origin currently means private initialization. All cache/receipt/step event decoding uses the state's current epoch (662, 874, 1111). Incrementing epoch and retaining old completed caches unchanged therefore fails today's schema. Rewriting old event epochs would falsify provenance.
- Private `future_counters` (365) subtracts the inherited baseline, requires admitted = consumed + dropped + pending, consumed = optimizer_updates * batch size, and native service_position = native admitted. `validate_records` (874) additionally requires future admitted = BANK cumulative_service_position. Simply putting a fresh native behind old cursors violates this contract.
- Shared service uses actual vector tick; private public clocks use cumulative eligible admission and add existing initialization baseline only for the native clock (scoped_curiosity.py:601). Reward must precede service; inactive worlds have no provider effect; retries return original receipts. Reset cannot create an admission, replay an old reward under new learning, or replenish same-tick ordinary budget.
- Native guards actually inspected are the BANK bridge (curiosity_checkpoint.py:946): epsilon bounds/schedule for none and RND families, count geometry plus disposable load, other selected families' producer `validate_state`; gradient module inventory, fixed-target no-gradient and actual Adam/Parameter pairing (980, 994). Native provider bodies were not inspected, so no claim that they already permit resetting native clocks, counters, optimizer histories, or adaptive history independently.
- Private RNG lifecycle requires quiescence (`world_curiosity_state.py:414`); the guard only coordinates participants. Construction/restore runs in private ownership, validates pure candidate transport, keeps saved continuation separate from work RNG, and installs destination/revision-bound single-use state (780, 830, 869). Failed live callbacks quarantine; this note adds no recovery path. ID-derived seeds exclude epoch, roster order, population, and clocks. Reset must not silently change that KDF.

## Actual serving phases, and the limit of fresh-receiver coverage

`startup` initializes ENV, exploration, POP, and curriculum first, then loads the checkpoint (live_inference.py:257, 299). Thus a newly constructed receiver exists before the first load. This alone does not establish the private-initialization prerequisites: current serving constructs `AdaptiveIntrinsicExploration`, passes it to POP, and never calls BANK private initialization or supplies its actual parent preparation/source checkpoint.

The loader (398) validates identity/runtime values, then loads only online Q weights, persistent VFS values and draw state; it records checkpoint epsilon in `current_epsilon`. It does not call the transfer loader, restore curiosity learning, or reset novelty. Selection later uses that explicit epsilon (638). Therefore current live inference is not evidence that novelty-reset-on-load is already implemented or needed at each load. Its observed serving contract is Q-only loading with explicit selection epsilon and world/VFS restoration.

Auto refresh runs before each episode on the established population (623). Manual refresh calls the same loader without a quiescence gate (537), and can run while an episode is suspended at broadcast/delay awaits. Pause changes a flag, not proof that the episode task has finished. A future serving reset must serialize/queue refresh at an actual parent-authorized boundary while retaining the refresh option. Do not describe every refresh as an untouched receiver or let an `is_running` boolean authorize reset.

A deliberately wired untouched private receiver plus valid shared settled source and actual parent preparation could use existing private initialization for its genuine scope-conversion purpose. That is conditional coverage, not coverage of repeated refresh, same-scope same-owner transfer, arbitrary cross-universe geometry, or production serving today. Rebuilding a BANK on every refresh is not a substitute.

## Minimal additive feature contract (new work, suggested names only)

1. **Parent boundary authority.** Define a narrowly typed, actual-owner preparation for `reinitialize_curiosity_after_transfer`, bound to the same BANK identity/revision, selected provider/policy, target geometry, accepted-cursor map, real INITIAL/COMPLETED boundary and transfer/network candidate. Authenticate before and after preparation and at installation. A portable snapshot, step receipt, paused flag, or equal token value is not authority. No reserved/reward-only/service-incomplete step, completion transaction, live inference task, or failed owner may be reset. Requests arriving mid-episode are deferred to the existing boundary, preserving manual/automatic refresh capability; no new midstep rollback/recovery protocol.
2. **Native producer candidate.** Add a selected-family native reinitialization preparation/capsule that constructs real fresh learning through the actual native factory under the correct RNG custody. The producer qualifies model, optimizer, gradient, normalization, queue, adaptive history, native clock, and ledger coupling. BANK orchestrates and validates ownership; POP must not edit generic `state_dict` keys, reach through private providers, or counterfeit checkpoint origins. Use current current-generation contracts only.
3. **Same BANK, explicit publication.** Prepare all provider/runtime candidates off-side, report allocation before candidate allocation, recheck all actual boundary/owner revisions, then install into the existing BANK with its issuer/ENV identity intact. Token is opaque, destination-bound, single-use, stale on intervening owner mutation. Parent coordinates network/reset publication at that boundary; any fallible validation/allocation precedes publication. No implied transaction rollback after irreversible live callbacks.
4. **Preserved runtime and receipts.** Global EPS value/schedule and parent cadence remain exactly as selected before transfer; native epsilon transport is explicitly reconciled by its owner and never becomes a second global EPS authority. Preserve actual accepted episode sequences, lifetime per-world admissions, real completion dispositions/outcomes and original receipt/event bindings. Advance a private curiosity learning epoch for new events without relabeling past events. Add explicit current-versus-historical epoch validation for the bounded latest completion/cache evidence; do not fabricate completion, replay old cached rewards into new learning, clear accepted history, or force shared/private conversion.
5. **Bounded accounting/origins.** Keep lifetime BANK ledger and a compact latest-reset record with reset count, previous/new learning epoch, real boundary identity, per-world retained totals and native clock/counter origin. Preserve admission conservation across reset; fresh learning/Adam counters may restart only with producer-qualified offsets separating lifetime totals from new native counters. New receipt positions remain lifetime world-eligible positions. Shared clock remains the actual parent vector tick and retains already-spent ordinary budget at that position; no tick regression, cadence reset, budget refill, empty service call, or artificial 1:1 admission/update gate. A reset is not an admission, update, drop, or episode completion. No chain of source checkpoints or unbounded reset archive is needed.
6. **Pending work must survive.** An episode boundary can still have predictor pending rows. Empty-queue-only reset is an additional restriction on the existing transfer capability and is not the chosen contract. Native preparation must preserve every pending row's exact content/order and ownership, with a producer-qualified clock/counter origin so those rows receive ordinary future service exactly once. A fresh learned predictor may coexist with retained pending work; resetting learning does not mean erasing admitted obligations. No silent archive/discard, zeroing of counters to conceal loss, hidden forced flush, fabricated admission, or service beyond the current budget. If a transfer changes geometry so the old pending payload cannot lawfully continue, the native/transfer owner must provide an explicit lossless disposition compatible with the established transfer option; absent that proof, report this exact unresolved dependency/owner decision rather than claim universal coverage or delete the option. This note does not prove arbitrary geometry support from uninspected POP/native bodies.

Selected-family semantics must be explicit in that producer contract:

| Selected family | Learned novelty reinitialization requirement |
| --- | --- |
| none | Honest no learned-novelty effect; preserve EPS/cadence and authority. Do not synthesize predictor receipts. |
| count_based | Fresh count/LRU novelty state under current parameters; retain lifetime identity/accounting. No predictor work invented. |
| rnd | Fresh target/predictor learning, matching fresh optimizer/gradients and normalization according to actual factory; preserve admitted pending obligations and clock/budget origins. |
| adaptive_rnd | RND reset above plus explicit fresh adaptive survival history and initial selected intrinsic weight; retain real historical completion evidence without reapplying it to fresh adaptive learning. |
| icm | Fresh encoder/inverse/forward learning, matching optimizer/gradients and novelty statistics; preserve ordered transition pending work and mandatory/ordinary accounting origins. |

These are proposed semantics, not existing verified APIs. At minimum RND/adaptive reset must land before migrating the known RND transfer seam; unsupported selected-family behavior must be explicit and cannot silently remove already supported selection/transfer/network options. Ordinary additive ownership work is authorized; no routine user confirmation is needed.

No tests run here. Required implementation proofs/tests are finite and use actual factories, BANK, ENV/parent tokens and serving/transfer calls, not only mock dictionary equality:

1. Explicit count/none/ICM cases verify their selected semantics when claimed supported.
2. Reject equal-value forged/foreign/stale/reused preparations and pending completion or unfinished-step attempts before publication.

4. Independent worlds: reset/continuation under lane permutation, spectator addition and A/B interleavings leaves each exact-ID private learning/RNG/ledger continuation equivalent; inactive rows have zero effect. Shared remains shared and retains grouped receipt ordering.
5. Checkpoint before/after reset: exact current transport, reload through actual parent preparation into same BANK, continue and compare actual novelty, model/optimizer/gradient/RNG states, adaptive weight, queues, public/native clock origins and lifetime ledgers. Exercise prior shared-to-private initialization followed by reset without nested archives or baseline double subtraction.
6. Failure preparation: allocation refusal, invalid native capsule/Adam pairing, malformed epoch/origin/counter/queue correlation, mutating parent validator, and intervening revision leave installed network/BANK/EPS/world state unpublished. Live-callback failure remains existing quarantine, not a reset-recovery promise.
7. Serving phases: first startup, repeated automatic pre-episode refresh, and manual refresh during an awaited episode. Verify exact current Q/world/VFS/epsilon loading behavior and defer any newly required reset until actual parent quiescence, with a single publication and unchanged supported command/selection options.
