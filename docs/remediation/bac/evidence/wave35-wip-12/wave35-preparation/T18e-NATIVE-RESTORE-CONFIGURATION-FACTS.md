## RND: non-equivalence, and exact compatible subset

RND604–632 compares transported group COUNT, each exact field-key SET and each ordered integer params list to the candidate optimizer's current state_dict groups. It deliberately does NOT require LR/betas/eps/weight_decay/flag VALUES to equal candidate defaults.
Numeric settings accept int/float/NumPy floating or zero-dimensional floating tensors, excluding bool; finite-tree checks apply. LR/eps/weight_decay must be >=0; betas in [0,1). Remaining fields must be bool, except foreach/fused may be None. Merely inserting scheduler numeric initial_lr fails this native rule even on a same-source clone; arbitrary custom optimizer configurations are not being claimed supported.
RND634–723 deep-copies fixed model, predictor and actual optimizer together; checks model tensor keys/shapes/dtypes; loads incoming weights and groups/moments. Adam history is empty or complete over every group parameter, with unique integer IDs, coherent finite nonnegative integral step, exact dense moment shape/dtype and nonnegative squared moments. amsgrad adds the required maximum-square moment. A disposable copy receives zero gradients and steps, checking actual destination execution/finite results; this is validation work, not advancement of installed history.
Thus a one-group actual Adam replacement with matching native field keys/IDs, supported changed LR/betas/flags and coherent history can validate/load on a fresh factory despite different initial values. Empty fresh Adam is NOT evidence that other group topologies work.
Minimal concrete counterexample: take a genuine CPU selected RND with positive ordinary LR, no admissions, no service updates, no optimizer state; replace its optimizer with genuine torch.optim.Adam using two nonempty groups partitioning predictor Parameters in their existing traversal order, all normal Adam defaults and same LR. Every Parameter appears exactly once; fixed target stays frozen/gradient-free. Its own/clone snapshot has two standard groups, empty history and U=O=S=delta=0. The clone compares against two groups, prepares and loads that exact native record; fresh make_backend compares against one group and rejects at group count. The new optimizer is paired to actual model Parameters, not fabricated checkpoint state. A standard CPU zero-gradient validation step is compatible; no exotic flags or custom optimizer are needed.
The same partition also admits genuine dense manual steps with complete coherent history. Export derives delta=S-(U-O); positive manual displacement and negative displacement after genuine empty Adam replacement are explicitly supported. Counterexample needs neither invented service work nor edited counters. A replacement after service with S=0 yields delta=-(U-O), while all original service counters/queue/clock remain real.
RND state restores diagnostics/RMS/model/history/pending/counters and exact service options/batch/clock; epsilon values are range-checked rather than matched to fresh values. Selected geometry/options and actual Parameter pairing still matter. All-group identity pairing is a caller/CP obligation for ordinary restore: native reset has an explicit actual-Adam/ordered-pairing check, while ordinary prepare_state does not independently prove it.

## ICM: non-equivalence even without changing group topology

ICM335–380 compares incoming param_groups by complete equality against the candidate's CURRENT optimizer.state_dict groups, then checks exact field types, integer parameter IDs and float beta elements. It does not compare those current group settings against immutable policy learning_rate. _config and policy equality separately bind retained constructor metadata; changing group LR does not change that metadata.
Minimal concrete counterexample: start genuine CPU selected ICM at a normal positive LR L and initial U=O=0, empty moments/pending, last_loss0; set actual optimizer.param_groups[0]['lr'] to another finite positive float L2 (or genuinely replace Adam on the same ordered Parameters at L2). Keep selected policy, retained learning_rate and all other settings unchanged. Source/clone checkpoint groups contain L2; clone validation agrees with its current L2 groups, reconstructs actual Adam on copied models using retained L initially, then load_state_dict restores L2. Native load and re-export therefore preserve the original record. Fresh make_backend has groups at L and rejects before load. Works identically for private initial clock0 and shared initial clockNone.
ICM accepts histories only at S=U-O, empty iff epoch updates0, otherwise complete step/exp_avg/exp_avg_sq for every first-group ID. There is NO signed displacement field; a bare extra manual step or empty replacement after epoch updates is rejected by BOTH candidates unless actual coherent history still meets S=U-O. This is an existing family constraint, not a newly imposed manual/replacement ban.
The strict zip of first-group IDs against all model Parameters makes a genuine two-nonempty-group partition fail ICM validation even on clone. Learned amsgrad adds a moment field that this decoder rejects. ICM has no RND-style destination step probe or independent complete numeric group-domain validator; this report asserts concrete valid ordinary Adam LR changes, not arbitrary settings accidentally surviving comparison or hypothetical custom optimizers. Current supported single-group settings/history must still survive exact load/roundtrip and actual Parameter pairing.
ICM policy identity, exact nondevice config types/values, epsilon schedule, conservation, pending transitions, service clock/budget and epoch origin remain mandatory. Source-device string is provenance restored separately from destination model device. Restoring LR configuration never authorizes changing these constraints.

## Producer API fact needed; RNG and gradient boundaries

An explicit producer seam must preserve source-current validation-relevant optimizer configuration BEFORE native pre-load validation: RND/adaptive actual group topology, field inventory, ordered model-Parameter association (with lawful transported settings); ICM current accepted group values/types as well as identity association and retained native metadata. Same immutable policy alone does not contain these facts. One pure source-owner-protected native clone factory or a qualified explicit configuration adapter can supply them; no permissive decoder or removal of supported manual/replacement/LR capability is justified. This is the finite missing fact, not a design for BANK publication.
A private adapter must receive/validate the ACTUAL candidate RNG provided by its owning construction/restore path with exact target world/descriptor/device binding. It must not substitute a source RNG, infer binding from checkpoint bytes, or silently retain a source-owned RNG reference through generic cloning. In these exact native3 bodies, constructors use the supplied RNG activation but DO NOT store an rng attribute: RND uses target/predictor, adaptive delegates, ICM uses model_init/predictor. Their checkpoints carry no RNG binding. Thus native clone equality alone establishes neither correct private owner RNG custody nor the actual factory binding check. A proposed generalized clone seam must preserve candidate custody explicitly; no extra native RNG-field defect is asserted here.
Gradients are not checkpoint fields. Native preparation copies/loads module/optimizer graphs; it does not constitute verified gradient transport. RND's zero-gradient step affects only its disposable probe. Preserve actual target frozen/None gradients and actual unique model/optimizer Parameter pairing, then attach validated transported gradients to FINAL Parameters after final copy/load as required by the public consumer capsule. No assumption about Torch deepcopy preserving .grad is needed for these counterexamples.
Native handles authenticate destination identity and consumption, not intervening source/owner/parent revision. Equal native checkpoint bytes do not establish currentness or caller quiescence. Snapshot/configuration acquisition, cloning and aggregate candidate preparation require actual source-owner protection and lawful domain admission; ordinary live owner.call is not a pure clone seam. Failure must not mutate/advance/quarantine the live source merely to obtain a template. Exact source custody, target candidate RNG and final parent currency remain separate obligations.
