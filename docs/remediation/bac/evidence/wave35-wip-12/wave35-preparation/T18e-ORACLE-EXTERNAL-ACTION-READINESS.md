## Actual caller topology and retained capability

Driver main parses logical pack, side-specific pack root, explicit level/N/steps/seed/device/output and optional actions file, then calls run_trace. run_trace resolves and compiles that side's pack with primary_level and use_cache=False, obtains selected-level metadata, calls seed_all(seed), constructs ENV, validates a supplied integer actions array of exact (steps,N) shape/range, resets once, and performs exactly `steps` vector calls. Seeded-random mode draws torch.randint on CPU each iteration and then moves actions to ENV device. Scripted mode converts each supplied row to int64/device and submits it verbatim. Neither mode executes Q or chooses actions through a policy. Every row remains present after a lane is done; ENV owns inactive-entry masking. There is no done-based early stop or automatic second reset. Output format4 records reset-inclusive observations, canonical returned rewards, dones, actual submitted actions, logical params, selected/shared provenance hashes, imported townlet code_root, side pack_root and action_source/digest.

Old runs first with its own seeded random actions. Scripted cell mode writes old trace.actions to an actions artifact and passes it to new; it does not supply a user script to both sides via main/run_cell. Direct run_side already transports an explicit script. New reads live packs; old normally reads frozen oracle_fixtures.
