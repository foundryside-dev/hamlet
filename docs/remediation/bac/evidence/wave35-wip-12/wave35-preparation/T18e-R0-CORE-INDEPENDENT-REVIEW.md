### P1 — cross-operation validation discards nested work history

**Location:** rng_custody.py202–217, especially212–217; operation exit185–189; SharedWorldBackend.install at world_curiosity_state.py1195–1202.

`validate_current` checks sequence only when the token's issuing operation is the presently active operation. Nested work in the next operation is also ignored for such a token.

**Causal source trace, no raw alias or invented token:** precreate two real shared owners A and B. Hold an authentic domain lease; prepare A's genuine reset; invoke B.call with the same lineage and actual ambient draws; exit the lease. B's nested call increments sequence, but exit increments the top revision only once and deletes the record. A's owner revision is unchanged, so that check does not rescue publication. Alternatively prepare A normally, enter the next held lease, call B with that lineage, then install A in that lease: the old token's operation differs and the new sequence is never checked.
