## Proposed finite helper behavior

`bac_checkpoint_delta.py plan` takes `--root`, `--work`, `--qualification`, `--inventory`, `--wip13-manifest`, `--wip13-plan`, `--receipt`, `--output`, and `--draft`. The terminal receipt supplies the finite interval and all named review/document/dependency paths and hashes. The tool validates the baseline inventory schema and integrity-failure count, then builds a content lookup from its object table plus WIP13 manifest artifacts and the hash-bound WIP13 selection plan. It verifies exact WIP13 predecessor path/hash and the WIP13 plan path/hash, their mutual object agreement, and every reused target's path/size/hash. This is a targeted additive lookup, not a fresh exhaustive 296 MB archive scan. A content hash found at several paths records one verified immutable target. A same-name path with changed bytes gets a distinct content object and destination. All original logical aliases survive in `inputs`.

The plan covers Q top-level `wave35-rN-...` entries in the explicit interval, all files below those entries, every W/wave35/rN-candidate.json and fixture-resource-preflight.json, the terminal receipt/manifest, historical component receipts, and every named review/document/dependency. Inputs are ordinary files under their declared roots, with no symlink traversal or parent escape. Duplicated logical destination with different original bytes fails. New objects use exclusive `docs/remediation/bac/evidence/wave35-wip-14/...` destinations; Python helper snapshots end `.py.txt`. Existing archived Python paths remain unchanged references. Plan output uses exclusive creation. Draft plans retain unknowns for review but carry a prominent `DRAFT PLAN ONLY` status and cannot be assembled or published.

After validating the plan against a freshly computed selection, it rehashes all inputs, receipt, predecessor and reuse targets, checks archive destinations do not exist, then copies only new objects with exclusive file creation and verifies size/hash after write. Its report is an **incomplete publication proposal** containing the object/alias table, predecessor, plan hash and execution identity; it never stages, commits, pushes, writes a checkpoint manifest or asserts qualification. Root owns the actual archive invocation, authoritative manifest and navigation edits. Tests assemble only synthetic temporary trees, never the real archive. Root separately checks source/execution subtree equivalence, approved navigation pre/post hashes, exact staged scope, independent qualification, actual publication tree, remote identity and CI before publication. Any changed input requires a new plan; partial assembly is not a publishable artifact. The helper never overwrites existing `EVIDENCE-PROCESS.md`, `EVIDENCE-INDEX.md`, `AGENTS.md` or chain files by string substitution; root reviews explicit navigation delta and pre/post hashes first.
