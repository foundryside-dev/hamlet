# R0 replay producer custody API — Stage B authored source, unexecuted

This capsule describes the current five-body authored replay slice. Root has not yet captured or executed this source. Consumer migration, qualification and outer publication remain open. It supersedes the earlier Stage0 replay API capsule only for these producer changes.

`ReplayBuffer`, `PrioritizedReplayBuffer` and `SequentialReplayBuffer` register their actual weak-referenceable lifetime instance with `process_rng_domain()` at constructor completion. Their `rng_participant` property exposes the opaque registered participant. They declare `sample`, `prepare` and `install` operation kinds. CPU registers `cuda_devices=()` without CUDA queries; CUDA requires an explicitly indexed `torch.device("cuda:N")` and the core domain verifies initialized device inventory. A constructor invoked while any domain operation is held refuses registration: enclosing owners must construct at idle and then carry exact lineage into consuming calls. No second domain, ambient checkpoint state or replay seed was added.

All direct and qualified sampling routes require `lineage: RNGOperation | None` as a **required keyword**: flat/PER `sample(batch_size, *, lineage)`, flat/PER/recurrent `sample_batch(request, *, lineage)`, and recurrent `sample_sequences(batch_size, seq_len, *, lineage)`. Explicit `None` is the standalone route; a nested caller passes its exact active issuing-thread operation. Each enters the common domain before the actual replay owner RLock and holds both through the real selected sample, receipt/batch construction and local Generator publication. Even the configured owner-local branches use a conservative whole-sample lease, but their draws remain on their local NumPy Generator. Flat uses selected-device `torch.randperm`; direct PER retains one global vectorized NumPy choice even when configured locally; qualified PER chooses its existing one-vector global legacy schedule or configured per-position residual-loop local Generator schedule; recurrent direct/uniform routes retain Python `random`; recurrent priority retains its staged cloned owner-local generator. No sampler algorithm, seed, pacing, readiness, legality, receipt or local RNG transport was changed.

`ReplayCustody._owner_operation(*, mutation: bool)` is the actual shared owner exclusion guard. Direct storage, configuration, priority/tick, archive and clear methods use it with `mutation=True`; readiness, properties, stats, serialization and validation use it as owner reads. Mutation attempts conservatively advance owner revision. These visible leaf methods use no source-local ambient primitive and never acquire the process domain after the owner lock. The separately source-qualified ordinary in-memory historical archive graph uses data validation/copy/digest with no random primitive for builtin containers, ordinary dense tensors and numeric NumPy values; its export and callback-bearing paths are different and not classified as these leaves. `validate_successor_masks` and `SamplingReceipt` in this same replay contract body validate/copy input without a draw. Their owner-local guard is **not** an atomic global poison fence; they do not heal poison or owner quarantine. Supported direct sampling and preparation/publication enter the actual common domain and reject poison through that admission. Caller-held raw tensor/array/deque aliases remain a cooperative quiescence obligation; the guard cannot intercept external writes.

`PreparedReplay` is an opaque issuer-registered handle. `materialize_validated(..., *, lineage)`, `prepare_serialized(..., *, lineage)` and recurrent `prepare_archived_import(..., *, lineage)`/`prepare_for_mode(..., *, lineage)` issue it inside a registered `prepare` operation with the owner's revision and core current token. The handle exposes no material getter. `load_prepared(handle, *, lineage)` holds registered `install` admission and owner exclusion, checks issuer and handle type, stages all archive validation/merge, storage/array/Generator/episode/policy copies, then authenticates owner revision and `validate_current(token, operation)` immediately before the assignment suffix. Success consumes the handle and advances revision. A clean stale/foreign/used refusal leaves live state unchanged. Unexpected partial assignment quarantines the replay owner; no rollback or healthy retry is claimed. Flat/PER/recurrent installed storage is independently cloned, so the candidate's retained tensors/arrays/episodes cannot become live aliases through normal public handle use.

`load_for_mode(state, *, requested_mode, lineage)` and `load_from_serialized(state, *, lineage)` compose real validation/preparation and `load_prepared` while preserving current mode/old-history rules. The core source-qualified token permits both released prepare→later install (revision plus one) and nested prepare→install under the **same still-active outer operation** (same operation and revision), subject to currency/generation checks. Core currency alone does not count an ordinary nested call inside a still-open inner prepare; replay's own revision and owner exclusion remain necessary. All lineage keywords on domain-entering methods are required; no omitted-argument fallback remains. The historical archive validator-only temporary classes bypass *lifetime* registration because they are never sampled or exposed as replay owners; their private validation does not acquire a domain operation while another owner lock/lease is held. The parent must migrate direct calls of every changed method family and supply authentic lineage when nested. This capsule does not assert that unrelated POP/BANK/runtime callers have been migrated.

The new regression source invokes real flat/PER/recurrent owners and samplers with explicit lineage, checks held peer admission, same-owner clear exclusion, current/one-use/issuer-bound preparation and exact local continuation. Its `replay_poison` spawned child is a consumer fail-closed control using the qualified bootstrap identity, actual child PID/PPID and exact replay import map. The external role verifier must first admit that distinct role; it is not a restoration/setter failure witness or a passed test. CUDA, broader caller integration, exact process/simulator resume and full R0/B1 qualification remain open.
