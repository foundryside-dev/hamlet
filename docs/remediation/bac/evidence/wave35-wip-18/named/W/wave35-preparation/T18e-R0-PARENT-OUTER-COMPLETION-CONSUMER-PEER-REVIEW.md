## Mandatory source and integration facts before acceptance

Current POP has no participant, cross-thread owner lock, outer outcome consumer or finite health guard, and its replay calls still omit the producer's required lineage. The bounded parent writer must establish an actual parent/ENV/runtime/replay acquisition order and keep the relevant locks through outer completion, outcome read and any justified transition. It must inventory every POP public operation that can mutate or publish healthy state after uncertainty, including reset/step/selectors, episode binding/commit/flush, checkpoint export and prepare/install, rather than test only the three example refusals. The existing participation, failed-vector diagnostic and strict native-boundary rules cannot be converted into a generic recovery permit.

Replay supplier facts still needed for dependent routes are recurrent batch/store alias ownership, any actual supported parent use of raw replay columns after a child return, and the exact CUDA source/destination/staged inventories for parent Q/target/optimizer and rejected prefix work. The flat/PER capsule settles only its ordinary profile, including an advanced-index assumption for untyped PER sample; it does not prove arbitrary subclass or raw alias behavior. A replay-specific outer-uncertainty transition mechanism is needed only for a source-established raw route and must be supplied by its producer, not invented in POP. These are explicitly deferred implementation/supplier facts in the proposal, not grounds to read a sixth body or to hold up independent A/B work.

The accepted invocation outcome API itself is still owed implementation and qualification. Root can adopt this finite parent contract for later bounded integration, but neither this review nor the alias capsule supplies a CUDA hardware pass, source-approved parent lock implementation or programme acceptance.
