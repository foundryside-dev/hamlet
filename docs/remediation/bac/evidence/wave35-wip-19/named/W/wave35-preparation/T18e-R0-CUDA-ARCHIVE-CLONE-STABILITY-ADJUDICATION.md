## Why the witness defeats the proof

The helper's `_clone`51–62 recursively dispatches Tensor detach/clone, Mapping items and key/value cloning, list/tuple iteration, or `copy.deepcopy`. `_own`273–275 processes source_formats before original_state; `HistoricalReplayArchive.__post_init__`295–297 completes that ownership and obtains further cloned state/formats before semantic/count validation. Thus earlier clone protocols can change raw values that a later clone has not read yet.

Start with the existing genuine four-row `_family_archive(family, 2)` record and valid digest, then set its raw original_state declared count to ordinary3 while archived_row_count remains4. Set source_formats['replay'] to an int subclass whose `__deepcopy__` changes that raw original_state field back to4 and returns exact4. This is accepted at the real helper boundary: source_formats is normalized to exact valid metadata before validation; original_state is subsequently cloned with count4 and four valid rows. A source_digest `_ArchiveComparison(torch.tensor(0), 1)` accepts the computed digest and performs its real device1 sum.

Shared119–136 instead sees exact-string raw keys, exact kind and exact count3, and stops on3 != 4 before the source_formats hook has run. It retains row clone sources2 but excludes digest1; with valid later transport rows3 it also excludes those rows and prepare destination4. The helper can reach all those effects. No planning hook call or raw count mutation is needed to produce the incorrect plan. This is a concrete material under-inventory finding at shared135–136, caused by the missing clone-stability premise at109–124. It warrants at least P2 correction before this source repair is accepted; the omitted protected device1 makes it materially stronger than the earlier over-inventory findings.

My earlier report checked only whether the selected key/kind/count itself could change during cloning. It failed to account for preceding sibling/source_formats hooks changing that selected input. ## Smallest coherent structural repair

Keep the real helper, accepted inputs, constructor ordering and family validators unchanged. Add one shared planner-only recursive classification of **both complete initial clone inputs**, source_formats and original_state, before making any post-clone refusal deduction. Place the gate after retaining their sources at shared109 and before the semantic/count/digest predicates110 onward. If either graph contains an opaque clone effect, mark possible continuation and stop the safe predicate path, preserving both clone inputs and the usual unknown-path operand/later-state/installed-source/destination inventory. Do not run a clone, hook, repr, comparison, reduction or digest to classify it.

This gate should apply to the whole post-clone proof, not only the literal count comparison. A hook may affect later fields or metadata in either graph; checking only source_formats['replay'], only the selected count, or only items before the current dictionary position recreates the same unsound dependency assumption. The helper clones these mappings repeatedly through `_Owned`; the classifier must describe stability under every such traversal. A complete recursively inert graph is stable across those repeated passes.

The finite proof boundary should be explicit:

| Value encountered | Classification and reason |
| --- | --- |
| Exact None/bool/int/float/str/bytes | Stable leaf; deepcopy preserves its ordinary value without user protocol dispatch. |
| Exact built-in dict, exact collections.OrderedDict, exact list or exact tuple | Recurse through all keys and values/items using their built-in traversal. Stable only if every descendant is stable. Do not accept their subclasses by isinstance. |
| Exact torch.Tensor in the existing ordinary CPU/CUDA Tensor profile | Stable with respect to scalar/container metadata: the trusted native detach/clone operations copy Tensor content and do not call a user subclass protocol. Retain its devices as effects; stable does not mean effect-free. |
| Exact numpy.ndarray with ordinary non-object numeric/bool dtype | Stable native deepcopy leaf. Require dtype.hasobject false and the intended ordinary numeric/bool domain; object arrays can invoke contained deepcopy hooks. Do not infer stability for ndarray subclasses. |
| Any other type, including scalar/Tensor/array/container subclasses, arbitrary Mapping, MappingProxyType, custom keys/values and unclassified NumPy scalar types | Opaque; retain supported execution with possible continuation. Do not inspect the custom implementation or add an accepted-input restriction. |

A conservative false classification is safe: it means unknown continuation, never runtime rejection. This list can remain deliberately small; unneeded extra scalar/container types need no new certification. Exact OrderedDict is safe because the actual clone explicitly rebuilds it from entries; arbitrary instance attributes are not traversed by that branch. MappingProxyType is not automatically stable: its backing mapping can provide custom behavior, and even an ordinary backing mapping can contain clone hooks. Preserving its accepted runtime behavior does not require a negative-prefix proof for every proxy.

Use object identity for an active recursion guard; cycles should become opaque rather than recurse indefinitely. Repeated acyclic aliases may be traversed or memoized without changing the result. Avoid hashing, comparing or rendering arbitrary values. Stop inspecting a branch once its type is opaque. No new source file/helper extraction is needed; the existing shared body is the appropriate owner, subject to the root's explicit revised line budget before implementation.

The exact-Tensor/native-NumPy allowance relies on the already adopted trusted ordinary runtime profile, not on an assertion that Python cannot globally replace built-ins or install arbitrary ambient dispatch machinery. Do not broaden this task into certifying a monkeypatched runtime. If an admitted ordinary-Tensor profile includes custom ambient dispatch that can mutate these inputs, root must exclude that case from this stability proof as well; it cannot be silently certified by an exact-type check.

After this gate, retain the existing ordinary semantic checks, exact archived-count type/range guard, and supported-kind/declared-count comparison. The existing successful-return relationship is sound when its clone-stability premise actually holds. Keep opaque semantic operators as a separate unknown boundary. F1 remains before cloning and does not need this gate; known schema refusal must continue to retain keys/earlier records while excluding untouched values.
