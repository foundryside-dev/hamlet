## Necessary correction1: exact OrderedDict does not imply native items dispatch

The proposal states: “Exact OrderedDict is safe because the actual clone explicitly rebuilds it from entries; arbitrary instance attributes are not traversed by that branch.” The relevant question is whether an instance attribute is *called*, not whether arbitrary attributes are recursively copied. Actual helper54–55 evaluates `value.items()`. An exact OrderedDict can carry an instance `items` callable overriding that lookup. Its execution can change later count metadata before the state is cloned, just as the confirmed scalar hook can. A classifier that uses a native traversal to inspect entries can miss that actual clone dispatch entirely.

Smallest defensible correction: **classify OrderedDict, including exact instances, as opaque.** It remains fully accepted by real execution. This costs precision for that container without affecting the exact dict/list/tuple negative-proof envelope.

An optional precision-preserving alternative is also defensible under the trusted ordinary native runtime: require exact OrderedDict and establish, through trusted base/native instance-dictionary access, that the instance has no `items` override; only then recurse through entries using the trusted native OrderedDict traversal. A simpler stronger sufficient check is an empty native instance dictionary. Do not call `value.items()`, `getattr` on a potentially overridden method, or the override itself to decide whether it is safe. If the native inspection cannot establish the condition without dispatch, classify opaque. There is no need to implement this optional alternative to satisfy the finite repair.

## Necessary correction2: exact Tensor needs an instance-protocol premise

The proposal's exact-Tensor row excludes subclass dispatch but does not exclude a per-instance `detach` override. Actual helper52–53 invokes `value.detach().clone()`. An exact native Tensor can have Python instance attributes; an overridden `detach` can run user code or return an object whose `clone` runs user code. Exact type alone therefore does not certify the clone operation that the helper actually performs. A clone method on the original Tensor is not independently called when trusted native detach returns a fresh ordinary Tensor, but allowing arbitrary instance state without a premise still leaves the detach hole.

Concrete sufficient rule for this bounded repair: **allow an exact ordinary native Tensor as a stable leaf only when trusted native/base access establishes an empty instance attribute dictionary; otherwise classify opaque.** Inspect the dictionary without calling user methods, comparing/rendering attribute values, or dispatching Tensor operations. A missing/unsupported/uninspectable native dictionary condition should conservatively mean opaque. With an empty dictionary, exact Tensor type, and the existing trusted ordinary runtime profile, native detach returns a fresh ordinary native Tensor and the subsequent native clone cannot dispatch an instance override supplied on the input. Retain Tensor devices/effects as already required; stable does not mean effect-free.

The empty-dictionary condition deliberately sacrifices unnecessary precision: an irrelevant harmless attribute can cause unknown continuation, but never runtime rejection. It avoids maintaining a fragile list of Tensor method/hook attribute names. It must not become a new accepted-Tensor restriction or require deletion of user attributes. A more permissive attribute-specific condition needs its own actual-dispatch argument; it is not necessary here.

## Root-adoptable clarified condition

Retain the proposed recursive gate over both complete initial clone inputs, after retaining their clone sources and before every post-clone semantic/count/digest refusal deduction. Use exact built-in scalar leaves, exact dict/list/tuple recursive containers, object-free ordinary numeric/bool exact NumPy arrays under the trusted native deepcopy profile, and the exact ordinary native Tensor rule above. Remove OrderedDict from the stable whitelist unless the optional explicit safe-instance condition is implemented. Treat all other values as opaque; stop that branch before accessing custom traversal/clone attributes. Preserve the identity-based active-recursion guard and cycle-as-opaque handling.

This premise is limited to the adopted ordinary native CPU/CUDA runtime. It does not certify globally monkeypatched Tensor/native methods, ambient custom dispatch, or concurrent external mutation. Those excluded ambient-runtime questions do not justify an unbounded audit. Conversely, per-instance `items`/`detach` overrides are concrete operations that this helper directly calls and must not be silently covered by the ordinary-profile assumption.

The proposal correctly treats arbitrary Mapping, MappingProxyType, subclasses and selected-count clone normalization as opaque rather than rejecting them. Its test-oracle correction is also necessary: `_CUDAData` is a Tensor subclass and cannot obtain a production stability certificate from its test name or currently harmless hook behavior. Native stable negative controls and opaque positive controls should remain separate.

Only two finite acceptance additions/clarifications are needed: an exact OrderedDict with an instance `items` override and an exact Tensor with an instance `detach` override. Establish exact type and installed override in fixture setup; pure planning must invoke neither and must preserve unknown continuation. The existing constructor-valid scalar-hook witness remains the mandatory causal positive; these two extra protocol representatives need not become a new large matrix or duplicate all count/kind cases. If the implementation chooses unconditional OrderedDict opacity, its override case verifies non-dispatch and conservative continuation. A harmless attributed exact Tensor should likewise remain accepted or possible continuation. All prior finite witness/count/short-circuit/cycle/alias obligations in the proposal remain scoped as written.
