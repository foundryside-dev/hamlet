# P2 finite transport amendment proposal (not adopted)

Frozen P0 remains unchanged. These are the minimum consumer gaps discovered while implementing the accepted P2 runner plan. Root owns amendment approval and any P0 change.

1. Add required `timeout_seconds` (strictly positive finite number) and `termination_grace_seconds` (finite nonnegative number) to each job. Timeout starts at successful Popen return using monotonic time; runner sends SIGTERM to the process group, waits the sealed grace, then SIGKILL and reaps. A runner SIGINT/SIGTERM uses the same bounded cleanup. No inherited environment timeout and no unsealed default.
2. Add disposition `completed-unverified` to the closed inventory. Its job result has observed integer exit_code, observed end/elapsed, reason nonempty. It preserves a real command completion (including exit 0) whose required structured outcomes/process/obligation/source records are missing or invalid. It is never `interrupted` solely for absent evidence. Runner returns nonzero for it. `interrupted` is reserved for an actual signal, timeout, or orchestration abort while launched work was active. `successful` remains all required evidence present and command exit zero; independent P4/P5 qualification is still required.
3. Pin this output layout in consumer metadata: roots exist; create output_root/attempt_id and scratch_root/attempt_id exclusively, mode 0700. All job.output/job.scratch are strict descendants of the corresponding attempt directory, with no overlaps or aliases. Runner exclusively reserves job.output before launch, uses `command.json`, `stdout.log`, and `result.json`; command owns exact argv/environment/cwd/seeds and spec/runner references. Case instrumentation writes `completion.json` as a closed `job-result` draft referencing command/log and its actual process/outcome/source/obligation records; runner cross-checks binding, actual exit/end/elapsed and required collection/role identity inventory before producing its independent `result.json`. A stopped child need not emit completion.json. Preserve every actual partial file; never invent a child finish record.
4. Controller witness belongs to P2's actual process: read PID/PPID, process start ticks, boot ID, hostname, monotonic and wall-clock time. Git commands are read-only with `GIT_OPTIONAL_LOCKS=0`: `git rev-parse HEAD`, `git diff --cached --quiet <candidate.tree> --`, `git diff --quiet --`; witness tree is candidate.tree only after equality against the real current index is observed. Rehash actual candidate inventory and compare exact sealed references. Record one source-witness at start, each prelaunch, and final observation. Root grant/source-freeze authenticity and active no-writer interval are prerequisites; hashes alone never prove absence of restored edits. No Torch/CUDA calls.
5. Resource interpretation: spec budget equals admission.admitted_budget and admission/request/candidate/source-freeze/dependencies bindings agree. Job CPU reservation must cover every role count plus permitted replacement overlap, and role inter-op pool reservation requires an explicit root ruling (positive inter_op setting alone does not demonstrate active CPU usage). Runtime sum of CPU/RAM/scratch/inodes across active jobs stays within admitted budget; scratch reservations remain charged after completion because artifacts are retained. Per-host physical-parent, RNG-domain and host timing locks require a single root-authorized shared lease namespace; output-root-local locks cannot coordinate attempts with different roots. A required canonical `lease_root` field in admission-request/spec would provide that namespace; reject a lease root within output/scratch/source roots. Root must freeze lease namespace ownership for an attempt to avoid inode substitution.

Synthetic tests exercise mechanics with inert Python subprocesses and controlled records only. Transport integration remains blocked until root adopts exact fields/dispositions/lease namespace and grant semantics; no legacy fallback is proposed.
