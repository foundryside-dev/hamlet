## Serialization and error semantics

One module-level RLock serializes all transient process RNG swaps. Every owned lifecycle operation uses it (therefore no conflicting per-owner/global lock order). Use a thread-local activation stack, not a world-ID global state cache. Same owner+component reentry shares the active state without reinstall/capture; outermost exit owns capture. Same-owner different-component nesting is permitted: capture/restore the suspended outer ambient state, then resume it exactly. Cross-owner nesting refuses before changing any global stream. Independent threads block and enter serially. The later bank holds its runtime owner through each complete operation, not only a small RNG section.

Entry validates first, acquires the guard, captures all globals, then installs private state. Exit captures consumed private state and always attempts to restore every captured global domain, even if one restoration fails. Catch BaseException for cleanup, preserve cancellation/KeyboardInterrupt semantics, and retain primary plus cleanup failures using ExceptionGroup/BaseExceptionGroup as applicable. No early restoration failure may prevent restoration attempts for other domains. A restoration failure marks the process RNG-domain coordinator unusable and raises the whole failure; do not claim globals restored or silently continue. This is truthful failure custody, not a universal recovery guarantee.

Constructor failure discards the candidate backend and candidate RNG; nothing becomes live. Off-side load failure discards all candidate objects, leaving destination backend/RNG untouched and globals restored. A successful load preserves the transported continuation stream positions: construction/load validation uses disposable work streams, then installs the untouched validated saved stream states. Do not consume saved continuation RNG to rebuild a model and then pretend its future stream is unchanged.

For a live compute/reward/completion/service callback failure, preserve advanced private RNG state when capture succeeds and quarantine that owned backend. It may already have changed RMS/history/weights/moments/queue state; never claim transactional rollback. Reject further ordinary calls until an explicit valid prepared restore installs a healthy snapshot. Snapshot may expose a clearly marked diagnostic failed-state copy, but it is not an ordinary resumable healthy checkpoint. An exception after a real optimizer step therefore cannot lead to a duplicate step through automatic retry. Other world owners and globals remain unaffected when restoration succeeds. Snapshot-read failure is also quarantined conservatively if arbitrary provider code ran. Validation rejection before callback/install does not quarantine or advance healthy state.

`validate_backend(candidate, owned_payload)` is a mandatory pure-validation contract supplied by the actual provider owner before candidate load, not an optional no-op. WS validates its RNG/envelope and copy ownership; backend-specific semantic rules stay with backend owners. Successful load/readback equality alone is not complete validation. PW02 can prove real construct/call/copy/late-failing-load containment with existing providers and explicit counted-test validation callbacks; it must label incomplete provider validation until PW04 supplies native complete adapters, especially adaptive. PW02 does not certify arbitrary adaptive malformed-state acceptance as fixed.
