## Actual launch selection rules

`resolve_launch(path, *, level_name)` resolves the input path and requires a directory. A direct `.../levels/<name>` entry selects its basename and discovers from its grandparent pack root. An explicit different level refuses with DECLARATION_SCOPE; unknown explicit/direct selection refuses PRIMARY_LEVEL_UNKNOWN. Pack input accepts an explicit known level or, with None, exactly one discovered level. Multiple levels with None refuse located DECLARATION_SCOPE; zero levels refuse (discovery may report required-family errors first). There is no authored default/first-level choice here. `DeclarationStore.level_names` comes from sorted nonhidden immediate level directories, not an arbitrary first curriculum file. T06 should transport CLI/constructor selection through this exact interface and preserve existing flags, rather than reinterpret provenance or fixed filenames.

These launch rules must not automatically redefine the old standalone loader domain. The old APIs load the requested section directly from the input directory and never count other levels. A directory containing an otherwise valid local standalone section remains valid even if unrelated level directories exist. A new pack-root request with no local section and multiple level candidates is genuinely ambiguous; direct-level input is its existing-signature explicit selection. A root-local target section must not be silently ignored in favor of a child level.
