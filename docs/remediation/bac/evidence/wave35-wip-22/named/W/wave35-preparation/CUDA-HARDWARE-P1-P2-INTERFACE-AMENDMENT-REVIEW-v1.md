# P1/P2 finite interface amendment — independent metadata review

2026-11-14T05:59:02.421430+00:00. **SPEC changes required; consolidated recommendation below is suitable for root approval.** This is metadata-only review of two proposals against already-reviewed P0 v2. No new tool/application body read, import, execution or P0 edit. Original reviews remain intact. Actual hardware remains UNRUN.

## Concrete gaps and resolutions

1. **P1 SPEC: CPU reservation is not defined by role count or inter-op setting.** Require an explicit per-instance peak CPU-slot reservation plus pinned justification. A strict serial contract may justify peak 1 with inter-op 5; the setting alone proves neither 1 nor 5 active CPU threads. Unknown/unbounded concurrency refuses admission. Root-approved contract or measurement must bound the exact role, case, configuration and workload; a measured point sample alone is not an upper bound. P1 validates this binding, P2 enforces the bound, and actual process witnesses remain P3 work.
2. **P1 SPEC: retained scratch arithmetic disagrees.** P1 proposes top-N largest budgets for every resource, while P2 keeps scratch charged after completion. Use top-N CPU/RAM simultaneous reservations, but charge the sum of all retained job scratch bytes/inodes against remaining admitted scratch capacity (plus separately accounted attempt/capture/log overhead). Otherwise two serial jobs can individually admit then exhaust retained storage. P2 must not silently release retained allocations. Cross-attempt reservations must share an authorized capacity pool or an explicit exclusive/root-partitioned capacity allocation; independent per-attempt admission is not protection from concurrent oversubscription.
3. **P1 SPEC: child-authored final job-result is causally impossible.** A child cannot author its actual eventual exit code or final runner log hash. P2 owner confirms the runner's controller is an attempt-level source-witness emitter, never the job's controller slot. Adopt closed `job-evidence` without terminal fields; runner supplies actual wait status/end/elapsed and final log binding. Missing/malformed evidence after normal completion is `completed-unverified`, not fabricated interruption. Nonzero observed exit remains a real failure; preserve missing evidence as an additional reason rather than erase the exit failure.
4. **P1 SPEC: private observations need actual execution binding.** P1 owner confirms capture accepts no external prerecorded discovery JSON: it launches pinned interpreter + pinned capture discovery command, binds actual Popen PID, capture PPID, observed /proc start identity, current host/boot, exact argv/interpreter/cwd/profile/TMPDIR/visibility and timestamp within launch/completion. If process identity cannot be sampled, refuse rather than infer it. Retain stdout/stderr/exit and recompute every admitted fact from that closed payload with exact raw-reference provenance. Seal these guarantees in metadata. Registry bytes must equal current observed `git worktree list --porcelain` stdout; availability paths/order/existence must reconcile current observations, not merely reference hashes. Exact parsing must handle or explicitly refuse unsupported porcelain path representations.
5. **P2 SPEC: launch/path/lease ownership must be unambiguous.** Add explicit request attempt_id (P1 owner prefers this to path-derived identity), shared lease_root and fixed exclusive layout. Require disjoint output/scratch/job destinations including ancestor overlaps and symlink aliases, and reject lease_root overlap in either direction with source/output/scratch roots. All attempts sharing host resources must use the same root-authorized stable namespace; host/device/physical-parent/RNG keys are canonical. Timing-exclusive acquires exclusive host timing ownership, while every ordinary running job participates in compatible shared ownership; acquiring timing locks only for timing cases does not exclude ordinary work. Lock inode replacement and namespace ownership require root's no-writer custody, not hash-only claims.

## Exact bounded P0 field changes recommended

- `job`: required `timeout_seconds` (exact int/float, finite, >0; bool refused), `termination_grace_seconds` (same exact number types, finite, >=0). No default. Sealed timeout begins after successful launch with monotonic time; actual timeout/signal/active abort uses bounded process-group TERM/grace/KILL cleanup and actual wait observations. Preserve partial evidence.
- `admission-request`: required `attempt_id: id`, `lease_root: path`.
- `spec`: required `lease_root: path`; existing attempt_id must exactly match request.
- `role`: required `peak_cpu_slots: positive-int` (per simultaneously live process instance), `cpu_reservation_basis: enum(accepted-case-contract, measured-bound)`, `cpu_reservation_evidence: reference`. The referenced accepted justification must bind role/config/cases and bound active CPU execution. Minimal conservative reservation is sum of `(count + replacement_limit) * peak_cpu_slots` over roles; P2 must never exceed that number of simultaneously live initial/replacement instances. This intentionally overreserves if replacements are strictly sequential, without multiplying by idle OS/runtime pool width. A later overlap-specific relaxation would require its own explicit bounded contract, not an inferred optimization.
- Add record `job-evidence` with exact fields: `schema`, `kind`, `attempt_id`, `job_id`, `spec`, `command`, `collected_ids`, `outcomes`, `process_records`, `obligation_records`, `source_witnesses`, `inventory`. Reuse existing field types; no exit_code/signal/end/elapsed/disposition/log. Runner cross-binds all fields and owns final `job-result`; P4/P5 still authenticate meaning. Case instrumentation exclusively emits this at `completion.json`; command/stdout/result filenames remain fixed metadata constants, not configurable defaults.
- Add `completed-unverified` to closed DISPOSITIONS wherever used: job-result, attempt-seal and receipt.test_outcome. It requires observed integer exit and measured end/elapsed with valid order, nonempty explanation, and runner nonzero status. Successful still requires exit zero and complete passing required evidence. Define precedence: real signal/timeout/active abort is interrupted; ordinary nonzero exit is completed-failed; ordinary zero exit with missing/invalid proof is completed-unverified. A valid completed-failed record may also retain evidence gaps in its reason. Generic structural success never upgrades qualification.
- Update local spec/request checks for attempt layout, timeout domains, role reservation sum, shared-lease disjointness and new result disposition. No other P0 record fields need change. Private grant/discovery/availability remain pinned closed consumer payloads, not arbitrary pass-through.
