## Core authenticity, ancestor composition and peer refusal

Current public core signatures are `register(*, owner, cuda_devices, entrypoints) -> RNGParticipant`, `admission(*, lineage) -> context yielding RNGAdmission`, `operation(*, participant, operation_kind, lineage) -> context yielding RNGOperation`, and `device_invocation(*, participant, operation_kind, lineage, cuda_devices) -> RNGDeviceInvocation` (449,703,902,922). An exact active issuing-thread/process/generation RNGOperation permits intentional nested participant admission. Nested scopes yield that same operation identity, pin actual participant owners and accumulate device union. `lineage=None` under active operation refuses unrelated same-thread entry; wrong/expired/thread/membership lineage refuses. Core does not infer ancestor identity from a callback, acquire parent owner authority, or distinguish a peer by application role. Possession and authentic forwarding of lineage is necessary domain authority, not sufficient BANK/native reentry permission. BANK's `_entered` separately rejects reentry while its method is active. Today public callbacks cannot supply BANK lineage at all. Native same-owner lifecycle/private-frame restrictions remain separate and must not be bypassed when adding a legitimate ancestor path.

Other threads wait at the actual domain RLock. Nested completion runs before nested return; outer completion uses the sorted accumulated union while domain remains held (1081–1091,1111–1138). Invocation receipts certify only their own completion; no BANK method uses this receipt API today. `admission` holds domain exclusion without creating an operation/draw/token authority. An idle admission gate can preserve a domain-first lock order around preparation, but does not by itself make an active-parent registration legal, authenticate a parent callback, retain BANK locks, or confer a native lifecycle exemption.

Core membership register/unregister/enroll requires idle custody. Registration holds weak owner identity; admitted operations pin members until outer exit. Retirements drain idle and change membership generation. Genuine token validation checks participant participation, generation, revision and ordinary-work currency; neither parent integration nor GC timing may weaken these checks. The current nested-kind currency rule intentionally treats successful work inside an inner prepare differently from ordinary sibling work (1075–1089); domain currentness is not a general proof of callback purity. ## Severity/classification clarification: no demonstrated current healthy window

The mutex-release and late `_failed` ordering above is **not, by itself, a confirmed P1/P2 defect in the currently supported standalone BANK contract**. It is a confirmed mismatch with the prospective explicit owner-lock-retention invariant and an absent ancestor-integration capability. No source-supported current public healthy-window schedule was established in this read-only packet. This conclusion follows the current control flow, not historical passing tests.

For actual BANK own-completion failure, the supported causal schedule is: thread A enters BANK domain then BANK mutex; its body returns or raises; A clears the BANK active fields and releases BANK mutex; A still holds domain RLock; `_finish` synchronizes and on failure calls `poison` before domain release (core530–541,1042,1087,1116); A unwinds domain; BANK's outer catch then sets `_failed` if publication changed. A competing thread B may acquire domain before that last assignment, but `_usable` then observes poison and raises before B takes BANK mutex or executes its public body. The same applies to an accepted/report callback attempting ordinary BANK entry during the active operation: missing lineage refuses, and after poison `_usable` refuses first. A successful method result does not escape the context until domain exit succeeds.

Every listed public BANK live mutation, managed observation/export, ordinary restore preparation/private initialization and final installation uses `_admission`. Domain `_usable` precedes those bodies. None has a BANK local-after-poison escape contract; the source-issued local CUDA contracts in current core are fixed flat/PER routes, not BANK.
