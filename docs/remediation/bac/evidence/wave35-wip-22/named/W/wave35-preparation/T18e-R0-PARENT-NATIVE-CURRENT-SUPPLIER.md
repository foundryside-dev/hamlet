## Decision-ready result

**Native managed owners already accept explicit authentic ancestor lineage, but expose no public ready-owner retained-lock scope, stable CUDA-inventory getter, or callback-free late completion-uncertainty transition.** The BANK capsule establishes that BANK currently cannot accept incoming parent lineage at its public boundary. Fixing runtime alone is insufficient; private native fields are not a substitute for producer APIs.

**Current native nested scopes perform their own declared-device completion.** They do not merely defer completion to an ancestor. C902–906 selects full participant membership; nested C1081–1091 calls `_finish(active, devices, ...)` before returning, and outer C1116 separately completes the accumulated union. W private activation additionally synchronizes its declared devices when capturing/restoring RNG. This only certifies declared/inventoried work, not arbitrary callback devices or a later ancestor phase. Current W uses `operation`, not `device_invocation`, so there is no native public own-phase receipt to read today.

Ordinary native return copying, BANK reward copying (BANK capsule), and stamp public access establish no normal returned-value alias to live native models, optimizer or queues under the ordinary Tensor/container profile. After successful covered native/BANK completion, later parent composition over those copies does **not** justify blanket native-owner quarantine. Conversely, if an integration changes native work to defer its completion, it cannot keep this healthy-child conclusion: the exact affected owner must remain retained through the actual completing consumer's decision.

## Lock, private-frame and callback lifetime

W `_scope` opens common domain operation first, then owner RLock, checks `_quiescent()` and `_active`, runs the method, clears `_active`, releases owner lock, then exits/completes the domain operation (907–924). `_quiescent` checks usable domain and **absence of a private activation stack**, not absence of an active common ancestor (410–417). Thus genuine ancestor lineage with no installed private frame is supported; lifecycle mutation from inside a private callback is refused even with genuine lineage. Same-owner lifecycle reentry also fails `_active`. Raw captured provider references are not intercepted.

Expected ordinary composed stack from the capsules is runtime RLock → common domain → BANK RLock → native owner RLock → private activation where applicable. Domain-before-native is direct source fact. Runtime-first/BANK ordering is attributed. This does not supply a new globally safe parent order; the runtime-first inversion identified by those suppliers still needs integration repair.

Private call/snapshot/capture factories/validators run with common domain plus native owner lock and private RNG service/model-init frame where shown (W1007–1008,1018–1024,1042–1044,1078–1091,1110–1120). Shared callbacks run under domain plus shared-owner lock without a private frame (1252–1259,1266–1273,1295–1307,1325–1336). Restore validators receive a candidate and copied transport; candidate and transported data must remain equal across validation. BANK's outer lock remains held at its attributed managed native calls; direct BANK accepted/report/parent/issuer callbacks are outside these explicit native calls. No arbitrary callback is presumed pure or device-bounded merely because it is named a validator.

`activate_under` retains common exclusion and installed RNG state, **not the backend mutation mutex**. It cannot serve as generic parent retention across worlds: cross-owner private activation is forbidden, and lifecycle work refuses any installed private frame. Same owner/component reuses its frame; same-owner different components preserve/resume nested continuations, including A→B→A (W798–852).

`call` retains its owner's mutex only dynamically during its callback and result copying. It is not a context manager that BANK may keep open after return. Wrapping a whole multi-owner parent phase in a private callback would keep that private frame installed and violate existing lifecycle/cross-owner rules. No such callback workaround is endorsed.

Shared `bootstrap` is a special **empty offside reservation** protocol, not a ready-owner retention API. It holds an outer common lock, opens a prepare operation, then owner lock; allows only the exact active bootstrap lineage through building/installed states; requires installation, preserves ambient, completes its operation, and only then marks ready (W1182–1227). Owner mutex releases before operation completion and is reacquired under retained common exclusion for ready/discard transitions. Ordinary/ready owners cannot enter bootstrap. It neither creates membership nor gives parent all-child publication authority.

## Completion and failure ownership

Private activation `_globals` synchronizes declared devices before RNG capture (W451–463). Its exit captures private continuation, restores ambient and verifies restoration; failed capture marks the RNG broken and restoration failure additionally poisons the domain (497–520,818–852). It does not surrender completion to a surrounding parent. Core native scope completion then runs again over member devices; outer union completion is later and independent. Do not infer all-device tail visitation after a synchronization raises: these generic loops are sequential, not the separate local-CUDA all-declared-device contract.

Native live callback/snapshot failure latches owner `_failed` inside its body catches; call/snapshot increment revision even on failure (W999–1058,1252–1278). `_scope` catches escaping errors after context unwind and sets `_failed` if common domain is poisoned (921–924). This is a poison-based fallback, **not** an own-phase completion receipt consumer or a callable late-ancestor health transition. Prepare candidates isolate live learning; install validates before swap and locally latches assignment failures. Successful explicit local restore sets `_failed=False` (1129–1135,1351–1360), but cannot bypass common poison because entry checks `_usable` first. It grants no new recovery policy for parent uncertainty.

The owner-lock-before-core-exit layout is a confirmed mismatch with the prospective retained-mutex invariant, not by itself a demonstrated supported healthy-window defect today. Common domain lock remains held during own completion; failure poisons before domain release; competing cooperative native admission then refuses before taking its owner lock/body (C1042–1044,530–541). Public RND raw methods lack that guard entirely and are outside managed-owner exclusion. This capsule does not invent a current legal parent/BANK path where the BANK supplier says public incoming lineage already refuses.

Later ancestor failure after a successful covered native child does not reach W's already-returned `_scope` catch. There is **no public `quarantine`, `mark_uncertain`, ready-owner custody context or callback-free failure hook** in these bodies. If actual post-child work reaches live native storage, parent integration must provide an authenticated producer transition under that exact retained owner exclusion; no parent writes `_failed`, `_broken`, `_lock`, `_participant`, `_active` or `_prepared`. Domain poison alone is not that producer API, and identical devices do not identify implicated owners.

The native registered tuple is explicit and canonical. W creation/binding rejects undeclared/uninitialized devices; CPU owners avoid CUDA setup queries on that path (432–448). RND `.device` is an ordinary mutable destination attribute, not complete authenticated inventory; `rng_participant` has no inventory property.

Finite source-backed work requiring inventory before execution includes:

- W result/transport/backend copying, serializer/validator/factory callbacks, RNG capture/restoration and prepared candidate data. `_owned` clones any returned Tensor on its actual device; declared owner devices cannot bound arbitrary callback return devices or hook side effects.
- RND target/predictor parameters and buffers, predictor gradients, Adam moments/steps and tensor-valued group options, pending observations and source/returned tensors, disposable restore copies/probe optimizer. RND finite validation and option equality can execute on input devices or copy to CPU (53–94,760–769,831–900). No arbitrary object traversal, global hook registrar, callback-declared device promise, destination-only assumption or pointer scan is supplied by this packet. ## Constructor, candidate and idle boundaries

WorldRNG construction registers before initialization (W565–570,620–649,661–667). `OwnedWorldBackend.construct` runs a forked registered RNG operation and selected factory under model-init, exits it, **then** adopts actual ownership into the backend at idle (988–997,981–985). This adoption creates authentic new membership; a parent cannot place the whole construct/adopt sequence inside an active ancestor. Shared construct registers first, builds/copies/stages ambient inside its scope, and unregisters on nonpoison failure; reserve registers an empty real owner without native work (1166–1170,1230–1250).

Existing owner `prepare_restore`/`prepare_learning_reset` create candidate RNG forks sharing current authentic membership and retaining a strong lifetime owner, rather than registering new participants (W589–617). Their native factory/copy/validation work can compose under supplied lineage once those required owners already exist. A factory that creates a new registered owner is not made legal by passing lineage. RND native fresh construction itself creates model/optimizer state and uses selected target/predictor streams; it is not independently a membership-admission API.

The BANK capsule's replacement-cohort gap deliberately exits BANK/domain operations before registering fresh world/shared/archive owners, then re-enters and revalidates destination/correlation/currency. Keeping an active ancestor across that gap makes it nonidle and invalid. Idle `admission(lineage=None)` can hold common exclusion while no operation is active; it does not authorize registration inside an active ancestor. Retain genuine offside lifetime owners, match the actual destination on reentry, and preserve token/membership staleness rather than deep-copying participant authority or retrying around refusals.
