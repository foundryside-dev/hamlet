## Public retained replay scope exists now

Exact public contexts, implemented with `@contextmanager`:

```python
ReplayCustody.cuda_preflight(
    self, *, anticipated_devices: tuple[torch.device, ...]
) -> Iterator[None]

replay_cuda_preflight(
    *, owners: tuple[ReplayCustody, ...],
    anticipated_devices: tuple[torch.device, ...]
) -> Iterator[None]
```

C527–529 delegates the singleton to C573–595. These yield **None**, not lineage, admission, inventory, receipt or replay authority. Use the multi-owner function for a finite owner group; independent nested preflight acquisition after taking one owner lock is not the adopted ordering protocol.

At C574–595 the implementation validates tuple/owner/device metadata, deduplicates actual owners by identity and sorts by `id`, holds a strong `pinned` tuple, enters `process_rng_domain().admission(lineage=None)`, calls `gate.enroll(participant=owner.rng_participant, cuda_devices=())` for each owner, and resolves CUDA selectors from the finite anticipated tuple plus each `owner.device`. Resolution occurs before replay lock acquisition. It then acquires each owner's `_owner_operation(mutation=False)` in that stable order, obtains its producer-owned `preflight` inventory, and enrolls each owner's resolved anticipated/selector union plus that owner's actual source devices. Only then does it yield. ExitStack releases locks in reverse order before the domain admission exits; the strong tuple and gate pins survive the yield and unwind.

Thus a parent can retain child exclusion through its entire invocation exit and its own outcome read by placing both inside this public scope. POP need not access `_replay_lock`, `_owner_operation`, `_replay_scope` or `_replay_healthy`. No additive retention API is needed for this ordinary use. Public `owner.rng_participant -> RNGParticipant` is C226–228; it does not expose the lock or promise owner policy authority.

Actual replay owner acquisition (C234–242) checks health, refuses an already active replay lifecycle scope, and uses an RLock. The preflight itself leaves `_replay_scope` unset, so sequential intended replay calls may reacquire their already-held lock on the same thread. During a live replay call, unrelated same-owner lifecycle reentry refuses (C238–239, C439–440, C483–484). This is cooperative exclusion, not a raw-reference or arbitrary-callback sandbox.

Required nesting for parent integration remains domain admission -> all declared replay owner locks -> parent/BANK/ENV locks according to their independently supplied order -> parent invocation/body/exit -> unconditional outcome consumption and justified owner transition -> unlock. Place the invocation and its finally inside the retained owner contexts. Preflight entered under an already active operation refuses because it uses lineage=None (G703–725); it cannot establish a new owner plan halfway through a parent. No await/task handoff or transfer of context ownership is supported. Exact POP/ENV order and finite entrypoint coverage are outside these four bodies and remain planner obligations.

## Current public core interfaces and exact outcome semantics

Public `process_rng_domain()` is G1194–1195. `register(*, owner, cuda_devices: tuple[int,...], entrypoints: frozenset[str]) -> RNGParticipant` is G449–480; `admission(*, lineage: RNGOperation | None) -> Iterator[RNGAdmission]` is G703–725. Its gate exposes `resolve_cuda(device: torch.device) -> int`, `enroll(*, participant, cuda_devices) -> None`, and `report_failure(*, error) -> None` (G94–106). Admission grants exclusion, not draw or operation authority.

`device_invocation(*, participant: RNGParticipant, operation_kind: str, lineage: RNGOperation | None, cuda_devices: tuple[int,...]) -> RNGDeviceInvocation` is G922–936. Every argument is required. The opaque result's `__enter__` yields an authentic RNGOperation; `__exit__` returns Literal[False] on normal exit; `completion_failed() -> bool` is G59–79. `operation` and `device_operation` remain distinct public context managers yielding RNGOperation (G901–920), but have no per-invocation outcome getter themselves.

Issuance checks PID, participant membership, kind shape, lineage registry membership and exact sorted/unique nonnegative-int tuple; actual exclusion, poison, entrypoint, active lineage, initialized subset inventory and reentry are checked on enter (G956–979, G1002–1092). A fresh local invocation variable and entered flag are required. Query only after a successful entry has subsequently exited, in an unconditional finally still inside the owner locks. Entry failure is `entry_failed`, has no readable outcome and runs no body; querying issued/entering/active/entry_failed refuses. Exact registered object identity, real PID and issuing thread-object identity authenticate handle methods before lock/CUDA work (G938–946). Copy/deepcopy/serialization of core capability objects refuses (G28–44). Completion reads require neither domain/owner lock acquisition nor `_usable`, so remain readable after poison; that readability is historical evidence, not renewed mutation authority.

Each fresh handle owns one immutable result even when nested scopes yield the same active RNGOperation. At G530–541 only successful return from that scope's actual `_complete` changes its initially True uncertainty bit to False. False means its own required phase completed, including empty inventory; body errors and reported failures can coexist with False. True means this entered phase failed or did not finish certification. G981–1000 seals exited in finally and drops execution bindings. It does not identify a failing device, heal poison, forgive body/publication failure, or certify a future ancestor. Child False/parent True and child True/parent False are both possible. Same-object body E and sync E still yield True despite identity deduplication exposing E alone (G543–576). Never infer completion outcome from exception shape or domain status.

Nested admitted scopes authenticate exact active lineage (G516–522), yield that same object, complete their own selected tuple, and accumulate devices in the active outer record (G1066–1092). The outermost scope completes the final sorted union including admitted descendants (G1115–1116). Generic `_complete` currently stops at its first synchronize exception (G524–528); no permanent tail-visitation API guarantee follows. Separate local completion attempts every declared device (G858–895). Local CUDA gates do **not** add their device tuple to the active operation union. Parent must account for its own actual later effects; local completion success is not implicit parent inventory enrollment.

Replay's actual consumer is C478–524: domain admission with supplied lineage; owner inspection; selection/source resolution; owner reacquisition/recheck; idle enrollment only when lineage is None; fresh device_invocation; entered flag; genuine lease yield; finally reads own result and quarantines this owner before lock release. Entry ValueError under supplied lineage becomes the explicit idle-preflight-required RuntimeError (C511–514). Local CUDA replay's equivalent gate result is consumed while its owner lock remains held (C453–475). These current wrappers supersede the historical alias capsule's known completion-before-owner-unlock defect statement; this is source evidence only, not a new runtime pass.

Local replay methods such as push/readiness/priority update have no lineage argument. Their local CUDA gate can run inside an authentic parent operation: G743 captures the actual active lineage and G664–665 authenticates it when the gate is used. This is the core's existing same-thread local-gate protocol, not permission to invent lineage or open a second local gate (G733–734). All needed devices must already be initialized; no active bootstrap. Declared preflight locks and domain exclusion must already surround the parent to preserve acquisition order. Local failures report into the active operation's error list (G758–766), but a parent phase can still certify False if its own completion succeeds; local failures must not be relabeled parent completion failures. The local gate still does not expand the parent's device union.

## Inventory, enrollment and candidate lifetime

There is no public replay inventory getter in these four bodies. The public integration is `anticipated_devices` plus producer-owned internal inventory/preflight and public core gate enrollment. `replay_cuda_preflight` enrolls replay owners only; it neither registers nor enrolls the parent participant. Parent must register its own lifetime owner at idle, use public admission/resolve/enroll for its own inventoried effects before beginning the active operation, and pass the genuine yielded parent operation to child admitted routes. An outer idle admission can surround replay preflight without changing the required domain-before-owner order; do not bootstrap a new parent selector after owner locks are held. Resolve any intended target switch in the finite idle plan first. Public preflight returning None cannot be treated as an inventory or a lineage token.

G832–856 enrollment authenticates the live gate, refuses active-operation/local-gate membership changes, checks initialized indices, grows membership monotonically and strongly pins the resolved member owner. Real expansion changes generation; no-op enrollment does not. G785–830 resolves unindexed CUDA against current_device each time; idle initialization advances currency before attempting init. Active initialization refuses; failed initialization/query reports poison. CPU empty inventory does not touch CUDA attributes. A constructor's unindexed selector is not permanently resolved to one device.

Flat/PER constructors call `_init_device_custody`, registering a weak lifetime owner with empty CUDA inventory and `{sample, prepare, install}` (F129–130,184–205; P180–181,250–276; C211–224). Core registration requires idle custody, a weak-referenceable owner and no duplicate owner identity (G449–480). Retirement callbacks enqueue only; retirement drains at idle under exclusion (G427–447). Operation pins and preflight gate pins have separate lifetimes. A copied/temporary parent candidate cannot register fresh replay owners during an active parent operation. No replay deepcopy/clone hook exists in these bodies, and capabilities are noncopyable; a generic deepcopy is not an authenticated adoption mechanism. Choose an explicit fresh-owner/transport staging lifecycle at idle if the parent needs candidate objects, or retain existing authentic owner handles. Do not copy participants/locks or use private core `_adopt` from POP. The exact POP candidate-deepcopy path is uninspected and requires its supplier's decision.

Planner supplied the concrete parent sequence “materialize on live replay, deepcopy(receiver), copied.load_prepared(original handle).” This is attributed POP context, not a fifth-body observation. The replay/core contract does not support that authority transfer: a fresh destination has no original issuer registry entry and rejects the original handle; copied core participant/current-token authority explicitly refuses deepcopy; no replay deepcopy hook rebases ownership or candidates. Neither copying issuer internals nor preserving a copied registry entry authenticates a new lifetime owner. A planner-supplied `_bind_training` path that constructs replay while a parent operation is active likewise encounters the actual idle-only registration guard. Prepare the concrete lifetime owners before active entry and settle staged candidate/handle ownership explicitly in the parent packet; no fallback to lineage=None or copied authority is available.

Producer inventory: C255–265,398–430 recursively visits supported Tensor values, Mapping keys/values and exact list/tuple children; F145–182 and P198–248 extend traversal for their DTO/candidate/sampler dataclasses and exact canonical archives' stored original_state. CUDA tensor indices must already be concrete. `admitted=True` additionally inventories every issuer-retained prepared payload. `preflight` falls through each producer's retained columns/archive route; it includes retained candidates via C429. Inventories are finite metadata traversals, not arbitrary object-graph scans or CUDA device-count sweeps. The traversal itself is not a generic callback-purity guarantee and lacks a general cycle detector. Ordinary-data profile and caller quiescence remain necessary.

Push, sample, transport and PER priority routes select different inventories: C290–396; F152–182; P205–248. PER priority updates cover td_errors source even with CPU destination (P214–215,774). Retained-source devices need not equal current selector; install preserves staged candidate devices instead of moving them to a newly selected target (F790; P1275). Parent must not substitute `owner.device` for actual source/retained/staged devices or duplicate private traversal in POP. Admitted child scopes add actual chosen subsets to the eventual outer completion union automatically, but parent-side Q/optimizer/copy sources require their own bounded supplier inventory.

PreparedReplay is an issuer-held identity capability, not a DTO or cloneable material bundle (C31–43,531–559). It binds original owner revision, core token and payload in a weak-key registry. Mutation attempts advance owner revision before body; prepare/read does not (C240–241,445–446,469–470,517–518). Do not infer any recurrent disposable-generator/scratch behavior from this fact.

## Current ordinary flat/PER no-alias facts

Consequently ordinary successful child sample False followed by parent outer True does not establish replay live-storage exposure. The parent must mark its own uncertain state under its own still-held lock as adopted, preserve the child False and replay-local health, and preserve common poison restrictions. A later push/update/install is a separate replay call with its own outcome. Public raw replay tensor columns and PER arrays remain directly reachable; caller-owned raw mutation is outside this transport guarantee. No recurrent alias conclusion, arbitrary Tensor subclass guarantee or raw-alias detection promise is supplied.

## Refused-prefix work and finite additions, if later required

Rejected does not mean no CUDA work. C83–184 ReplayPrefix records reached validation/copy inputs and conservatively marks opaque continuation; C339–357/F548–704/P944–1172 route transport prefix work. Direct plain top-level key refusal can precede tensor work and must not inventory an unrelated rejected extra field. Conversely mutated DTO materialization clones its graph before revalidation; prior field copies can precede later schema/device/content refusal; stale install clones candidate storage before currentness refusal; td_errors converts before an invalid ID refusal. Archive clone graph classification handles ordinary stable graphs and retains unknown continuation (C50–80,131–179). Preserve actual prefix ordering, original error behavior, no-work laziness and already-touched source completion. Do not convert conservative planning into a new accepted-input restriction or claim arbitrary Mapping/Tensor protocol safety.

No new API is necessary merely to retain preflight locks for ordinary copied-batch parent work. No public producer-owned method currently authorizes a parent to mark an exact replay owner uncertain after a later raw replay-storage effect; `_quarantine_replay` is private (C432–434). If the parent supplier establishes an intentional supported raw route, a separate finite producer delta is required before that route is admitted. The smallest semantic addition should be an opaque producer-issued retained-scope capability binding the exact preflight owner set, issuing thread/PID, live scope and already-held locks, with an authenticated operation to apply outer uncertainty only to a source-established subset while the fresh outer invocation's exited True outcome is authentic. It must reject fabricated/expired/wrong-thread/foreign-owner scope use, perform no new locking/CUDA/callbacks, preserve original failures, and never heal. Concrete naming/signature and authenticity linkage require separate reviewed design; this note does not invent a callable or authorize private parent access.

Similarly, if a genuine parent requirement needs replay's full retained device union before any admitted child enters, rather than automatic descendant union, a producer-owned public inventory view scoped to retained preflight custody is a distinct possible finite addition. It must expose only immutable concrete device metadata after authentic owner locking/inventory, not private payloads, ownership authority or arbitrary route callbacks. It is not present today and is not required solely for the ordinary admitted child union. Parent should first use existing public core enrollment and its own source-proven inventory instead of demanding a new general scanner.
