## 3. P2-2: finite source-owned composed-restore attempt

V1's phrase “actual owning failure/quarantine policy” was unsupported. It is replaced by an explicit **new composed-restore attempt protocol**, owned by the real ENV boundary authority and bound to one actual receiving ENV, actual runtime/BANK and exact prepared world record. This is a narrow restoration owner protocol, not a general transaction framework or a new active-parent RNG operation. Existing standalone runtime/BANK prepare/install and ordinary standalone world restore remain available outside this explicit composition.

The attempt is issuer-registered, Thread/PID-bound, noncopyable/nonserializable and retained only for its lexical transaction. It owns the continuous idle admission gate and keeps genuine ENV/runtime/BANK/authority/cohort/handles alive through final disposition. Public operation names and source placement require the fresh producer proposal; the required operations are: acquire this exact attempt, prepare its runtime child, issue/escrow its release, install its runtime child, install its world child, and end with enforced success/failure disposition. Their bodies must call the actual existing producers. They are not caller-settable stage flags or a success boolean supplied by a fixture.

### 3.1 Capability escrow and issuance

The attempt binds only the actual prepared record and actual receiver/runtime ownership accepted by the producer. It captures no fabricated receipt. Its release is issued by genuine `authority.restored` **after real child candidate/cadence/ledger qualification**, at the ordinary idle cut with ENV retention released. No early release is inferred safe from authentic saved bytes alone.

Both the prepared world record and resulting release are associated with this actual attempt in ENV's nonserialized registry. Once escrowed, ordinary direct ENV installation with them refuses unless invoked by the source-controlled attempt's exact world-publication call. Merely leaking either object through an observer does not make it independently usable. The producer must install a one-use internal call identity before that specific call and consume/expire it on every path; no public permit issuer, caller boolean, generic reentry or arbitrary callback bypass is added. Existing non-attempt world preparations retain their ordinary behavior.

If attempt failure occurs before publication, mark its exact prepared/release associations invalid. If failure follows child publication or uncertainty, revoke its associations and fence the receiving ENV as described below. No later invocation can convert failed attempt records into an ordinary restore. A fresh explicit restore attempt, where the existing receiver remains eligible after confirmed no-publication refusal, is a distinct caller decision—not automatic reprepare/token refresh. A consumed native handle never becomes retryable.

### 3.5 Enforce failure without needing a healthy domain reentry

Failure cleanup must be source-controlled and unconditional on whether user code catches the error. Each attempt method and lexical exit performs the appropriate terminal disposition before releasing outer admission. The attempt never returns a successful stage merely because a callback swallowed a refusal. Primary exceptions remain primary; cleanup failures are attached, not substituted.

Actual BANK completion may poison the domain; therefore terminal failure bookkeeping cannot require a new healthy admission, RNG invocation or accepted-token operation. At runtime-install failure it runs while the preheld ENV retention/exclusion is still present, before that scope exits. At ENV release/install cuts, source-owned error handling must finalize while the actual ENV exclusion is still held; alternatively the attempt's already-established outer-domain custody may reacquire the existing ENV lock in the correct order after lower owners fully unwind, without opening another admission. This narrow terminal-denial path authenticates the live attempt/Thread/PID/custody and performs only preallocated non-callback invalidation/phase assignments. It grants no healthy publication, retry or raw mutation right. The exact lock/failure path needs independent ENV/helper source approval; “finally calls a normal guarded cleanup method” is insufficient under poison.

Preallocate required failure records and next invalidation metadata before publication. If cleanup cannot certify the terminal state, the attempt remains failed and cannot release a healthy result; no application continuation may treat it as reusable. Preserve authentic child completion/poison evidence and references until their actual disposition cut. Reference expiry by itself is not failure enforcement.
