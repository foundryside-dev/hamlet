## Why the prior material gaps are resolved

**Pure currentness is now implementable without narrowing world payloads.** The
ownership capsule establishes frozen owned containers and defensive public
accessors, while correctly retaining possible cloned Tensor and opaque capability
leaves. V3 therefore links the exact issuer-created record/private payload identity
to a separate immutable receiving-metadata seal. It does not traverse the payload,
call accessors/`same_value`, revalidate VFS, perform Tensor work or claim deep
primitive immutability. Source-owned scope/registry authentication precedes record
inspection, and the complete fresh-bound predicate is explicit. Both successful
and refused checks remain non-issuing and non-mutating.

This preserves existing nested completion content, multiple preparations,
uninstalled bootstrap records, ordinary runtime-binding absence and healthy
fresh-bound helpers. Private/object-level mutation remains outside the cooperative
record contract; the method does not pretend to detect it. Seal storage/lifetime
requirements prevent the weak registry from becoming an accidental permanent
owner/record root. Exact concrete type applies to this newly issued authority
path, not an arbitrary portable snapshot schema restriction.

**Mandatory comparisons are now enforceable at the source boundary.** Attempt
adapters invoke the pure check before and after each real parent comparator;
the runtime overlay does the same around its actual already-bound cadence
comparator. The original comparisons, ownership/None/view/revision checks and
callback counts remain. Thus an inner comparator cannot swallow the mandatory
outer currentness refusal. The pure method needs no sticky failure mutation.
The design explicitly does not certify arbitrary Python comparator honesty;
consumer qualification must use the genuine owner functions. This is the correct
cooperative boundary, not stack inspection or general callback authority.

**Failure now has concrete owners, outcomes and enforcement.** Preparation creates
the installation observation before the token-sensitive cut. Guard/body/invocation/
dictionary publication/runtime suffix observations determine the immutable result;
pending/in-progress is never treated as no-publication. Actual own-invocation
completion is separate from publication and normal return. The result survives
dictionary replacement, consumed handles and poison without an extra operation,
status/export or user callback. Foreign/copy/thread/PID and reference-lifetime
rules are specified. Actual implementation must demonstrate every declared cut;
none of these APIs is claimed to exist already.

The explicit attempt owns stages, source callback adapters and escrow. It catches
stage errors before returning to callers; early normal exit also aborts. Distinct
one-use internal identities authorize genuine release issuance and world install.
Escaped escrow cannot replace that path. Source-owned abort derives its result
from actual observations, not caller booleans or exception text. Confirmed no-
publication revokes the attempt without falsely declaring the native child
healthy; partial/uncertain effects terminally fence the joint receiver without
blanket native poisoning or rollback. Poison-safe cleanup uses existing custody,
not an unavailable accepted-token cleanup or fresh healthy admission. COMPLETE
is a sealed terminal success: later abort/exit cannot revoke that installed result
or turn it into failed-attempt escrow, and ordinary exact-pair idempotence remains.

## Direct-BANK/manual capability and core currency are preserved

The two explicit factories are necessary and sufficient for the selected profiles:
real direct BANK uses no fake runtime, delegated scope or cadence callback;
runtime+BANK uses its genuine receiver association and bound cadence owner. The
healthy parent-correlated counts are four BANK comparisons/eight surrounding
checks for direct BANK and seven comparisons/fourteen checks for runtime+BANK.
Live accepted/no-parent standalone routes are preserved as their actual different
paths, not routed through this fresh-bound attempt.

Approved M allows a real fresh manual session to bind before INITIAL/COMPLETED
restore. V3 pins its real population/session and authentic quiescence without
rejecting session presence or demanding runtime binding. Its eventual source
fields/predicate must be supplied to the integrating writer before that code is
written; they are not guessed here. Binding is not entered physical work. The
source handoff must preserve the declared fresh-bound receiving invariants and
generation invalidation, then genuine next reservation/reset/activation/physical
work. If implemented M metadata differs materially from those agreed invariants,
report that concrete interface mismatch rather than exclude this required route.
Terminal denial must reach both new binding and the actual session step/retire.

Ordinary noncomposed fresh-bound restore, bootstrap-issued state, multiple valid
preparations, supported payloads and exact-pair idempotent installation remain
explicit preservation controls. New optional attempt terminal fencing is confined
to an actually failed joint receiver; it is not a blanket reduction of independent
runtime/BANK/native capabilities or an automatic recovery policy.

Core currency remains conditional: admission entry can drain unrelated retirement;
its exit is not a drain; final successful issuer normalization and exact immediate
install at r+1 do not excuse generation/currency mismatch. Extra no-draw work,
membership changes or post-seal GC must still cause genuine stale refusal. No
global pin, token refresh, automatic reprepare or hidden status/export is selected.
