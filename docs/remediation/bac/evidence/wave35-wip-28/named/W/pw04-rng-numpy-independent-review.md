## NumPy ownership and comparison

`owned_value` (129 onward) admits only exact ordinary ndarray with boolean/integer/unsigned/floating/complex dtype kinds and no dtype metadata, then invokes the ndarray implementation's copy. Exact type is checked before dtype access for subclasses. Object/structured/string/date/timedelta arrays are excluded; metadata is excluded because it could retain mutable or behavioral objects. Numeric ndarray copying creates owned element storage even for views, reversed/strided arrays, read-only inputs, scalars and empty shapes; input base ownership does not become receipt ownership. No object-element copying, arbitrary deepcopy, coercion or array subclass hook is introduced.

`frozen_value` recursively freezes container structure and delegates each ndarray to owned_value. Arrays inside internal storage remain mutable implementation data, but receipt `.payload` and dynamic public attributes copy recursively on every read. The new boundary therefore protects against input aliases and mutable public output aliases. This is not a claim that callers who deliberately access private `_payload` cannot mutate internal arrays; the same existing convention applies to internal tensors.

`same_value` checks both operand types, allowed kinds, absence of metadata, exact dtype and exact shape before `np.array_equal`; subclass and non-array mismatches short-circuit without invoking array comparison hooks. No broadcasting, dtype coercion, tolerance or weakened population comparison is introduced. NaNs remain unequal and signed zero compares equal, consistent with existing value-comparison semantics rather than bytewise equality. Non-native endian dtype mismatch is explicitly tested.
