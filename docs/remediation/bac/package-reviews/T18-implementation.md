## Interfaces and compatibility facts for consumers

- Existing constructor signature and working defaults remain unchanged. Invalid nonpositive/noninteger minibatch sizes now refuse before allocation; no new behavioral defaults were added.
- `configure_service(options: RNDOptions) -> None` binds a fully resolved options object before admission. All four fields must be explicit; capacity must fit a predictor minibatch. It does not resolve omissions locally. Consumers should obtain policy from `resolve_bac_options(..., training=...)`; this task leaves the policy resolver unchanged.
- `admit_and_service(observations: Tensor[K,D], *, vector_tick: int) -> PredictorServiceReceipt` consumes caller-selected eligible predecessor rows. Eligibility and local clocks belong to the caller. Input shape, dtype, finiteness, policy presence, and monotone nonnegative integer tick validate before admission. Finiteness is checked in minibatch chunks. Retained rows are owned copies.
- Receipt fields: `admitted_rows`, `consumed_rows`, `dropped_rows`, `pending_rows`, `optimizer_updates`, `last_loss`, plus `paced_optimizer_updates` and `overflow_optimizer_updates`. `last_loss` is None when no update occurred. Admissions count all presented valid rows, including explicitly dropped rows: cumulative admitted = consumed + dropped + pending. Per-call pending is ending occupancy, not a delta.
- Occupancy service drains every complete minibatch in FIFO order. Paced service shares its authored ordinary update budget across repeated calls at the same tick. A later empty call can service backlog. Lossless service-before-admit performs mandatory old-prefix minibatches when capacity is full; those updates are reported separately and can exceed the ordinary paced budget. Explicit drop-oldest/newest count every dropped row. Oversized input advances in bounded admission chunks; no loop spins without admission, consumption, or explicit dropping.
- `update_predictor() -> float` remains exactly one minibatch operation, even when service is configured, and returns 0 for insufficient rows. Public caller-populated `obs_buffer` remains usable and is accounted when this operation is called. Direct calls do not fabricate vector ticks or spend the service API's ordinary pacing budget. This explicit API can leave complete pending batches under occupancy mode; the next occupancy service drains them. Configured checkpoint capacity still validates. The bounded guarantee applies to `admit_and_service`, not arbitrary external mutation of the public legacy buffer.
- `update(batch)` preserves the old one-minibatch behavior when unconfigured. When configured it adapts to the bounded service at the next local tick, preserving continuity after explicit service calls. The unconfigured public adapter remains usable while production callers are migrated; this does not claim G03 production closure.
- Normalization remains exclusively `compute_intrinsic_rewards(..., update_stats=True)`; service does not update its count or apply intrinsic weight. Action selection and epsilon APIs remain unchanged.
- `checkpoint_state()` returns owned tensor snapshots of networks, optimizer, scalar normalization/epsilon, and `predictor_service`: version 1, minibatch size, policy (None for the explicit legacy adapter), pending rows in order, admissions/consumption/drops/update counts, vector tick, used paced budget, compatibility step counter, and signed `optimizer_step_offset`. The offset is captured from trusted live Adam steps minus service optimizer updates, including external public manual optimizer steps and available-state imports. Restore validates the saved offset against every Adam parameter step; it never derives a replacement offset from incoming malformed state.
- `validate_state(state)` validates without installing. `load_state(state)` prepares copied networks/optimizer and owned pending rows before installing any field. Checks cover exact schemas, geometry/dtype/finiteness, scalar normalization, complete dense optimizer moment coverage, common integral Adam steps, moment keys/shapes/nonnegative squared moments/parameter IDs, exact optimizer group fields/types, actual destination execution compatibility on disposable copied parameters, service identity, finite capacity, integer counters, conservation, and pacing clocks.
- `available_state()` exports the exact historical available-state dictionary. `load_available_state(state)` and `load_state(exact historical schema)` preserve access to those artifacts. The recognized old branch is strict, does not catch-and-fallback from a malformed new payload, and leaves destination FIFO/clocks unchanged, matching the prior load API. Old source tails/RNG are unavailable and are never invented; historical available-state import is not a tail-continuation claim. Missing required historical fields retain the KeyError diagnostic, unknown fields refuse, and malformed new service payloads refuse atomically.
- Population keeps its existing exact scalar/network/optimizer validation and accepts only the exact historical key set or that exact set plus `predictor_service`. It additionally invokes the provider's no-mutation validation before applying any population fields. No unknown-key bypass, fallback, version weakening, or unrelated POP behavior changed.
- Each provider owns its queue, networks, optimizer, normalizer, and counters. Restore/service introduce no RNG draws or shared mutable singleton. Existing randomized construction and action selection remain supported; RNG continuation is not claimed. The backend is composable as one instance per world; shared alternatives, live predictor evolution, and separate Q learner are preserved. Per-world lifecycle, ownership, budgets, state-scope selection, and strict isolation qualification remain later work.
