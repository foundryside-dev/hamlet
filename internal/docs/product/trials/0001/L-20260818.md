Anti-conflation note, pre-committed: modelling the cooldown as a *stock* that is spent to 0 and
passively refills (a bar with regen) reproduces the availability *pattern* but is exactly what the
Spec excludes ("gated by time since last use rather than by a stock you spend and refill"). A
stock-regen emulation therefore does NOT pass facet 3. If a stock emulation is the only expressible
form, facet 3 classifies per the §6 tree (a surface that cannot express "time since last use"
gating at all → ABSENT for that facet).

Appended 2026-08-18 (dated note, discovered during authoring — no pre-committed entry edited): the
timer is *stored* in the meter vocabulary (a `bars.yaml` entry) because that is the only per-agent
state with a declarative per-tick writer. Facet 3's anti-conflation test was applied to the *gate*,
as pre-committed: nothing spends the timer, time alone advances it, use resets it, and the gate is
an explicit `if <timer> >= <threshold>` condition — elapsed-time semantics, not affordability.
